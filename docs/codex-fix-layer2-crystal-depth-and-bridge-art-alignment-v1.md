# 第２層：解除クリスタルの前後関係と橋の絵の位置修正

## 承認済みの修正範囲

ユーザーの2026-09-28の実画面報告（Desktopの `スクリーンショット 2026-09-28 10.14.05.png` と `スクリーンショット 2026-09-28 10.16.00.png`）に対応する、**描画だけの２点修正**。第２層のマップ、赤線由来の歩行範囲、仕掛け条件、物体衝突、キャラの足元一点判定は変更しない。

1. 解除クリスタルの背後へキャラが回ったときは、クリスタルの本体がキャラの手前に描かれてキャラを隠す。逆に、クリスタルの前へ回ったキャラは手前に見える。左上・左下の２基とも確認する。
2. 湖上に出現する石畳の橋の**表示位置**を、既存の歩行可能帯と両岸の接続位置へ合わせる。現状は橋の絵が上側に寄り、スクリーンショットでは足元が石畳より下、水上または橋の晶石の位置に見える。歩行可能範囲を絵に合わせて移動・拡張して帳尻を合わせない。

## 現状コードの手掛かり

- `src/render/stages/LightwingCrystalCavernRenderer.ts` では `drawLightwingCrystalCavernBackground` が `drawCrystal` を２回呼ぶ。これは `src/render/Renderer.ts` の `drawActors` より前なので、キャラが常にクリスタルの手前に見える。第２層の `drawLightwingCrystalCavernSanctuaryForegroundEdge` と `drawLightwingCrystalCavernForeground` は空。既存の `drawActors` はアクターと追加描画を y 値でソートできるが、追加描画は現在１件だけなので、２基と泉の重なりを扱う場合は設計を確認すること。
- 同ファイルの `drawBridgeSegment` は承認済みの全体コンセプト画像から、赤線マスクに由来する `BRIDGE_BOUNDS` で橋部分をクリップしている。ただしコンセプト画像は元背景と画素単位で同じ地形ではない。**クリップ座標が合っていても石畳の絵そのものが上へ寄る**可能性がある。素材の実際の上縁・下縁と歩行帯を原寸で照合し、橋の絵または透過橋素材の配置を修正すること。

## 実装・確認の要件

- 奥行きはアクターの足元 `pos.y` とクリスタル石台の接地点を比較する。背後のキャラにはクリスタルの立体部分が重なり、前側のキャラはクリスタルを隠せるようにする。単にクリスタルを全キャラの後に一律で再描画して、前にいるキャラまで隠さない。既存の第１層クリスタルの深度処理も参照する。
- 橋は元背景のネイティブ **1638×960 px** で、赤線から生成した橋歩行マスク、左右の岸、石畳の見た目を重ねて確認する。表示の上下ずれを画像座標で測り、橋の石畳が足元の歩行帯を覆うようにする。晶石は橋の下・脇に見えてよいが、石畳の上を歩くキャラが水上に見えないこと。
- 発動前・片側起動・出現演出中・完成後の各状態で、橋の絵と通行可否の同期を保つ。描画位置の修正が赤線外や湖への通行を増やしていないことをテストする。
- ブラウザで（a）左上・左下の解除クリスタルの背後／前面、（b）橋の左端・中央・右端をキャラで実際に歩いて確認する。可能なら同じカメラ位置の修正前後スクリーンショットを残す。型検査・テスト・ビルドも実行する。
- 検証用サーバーとブラウザは終了し、ユーザーが起動したサーバーや音楽再生タブには触れない。

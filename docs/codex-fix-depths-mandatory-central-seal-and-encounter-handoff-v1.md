# Codex向け修正指示：第3層中央封印の必須化と遭遇グループ引継ぎ修正 v1

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- 理由：第3層のマップ導線、門衝突、遭遇状態機械、敵AI、戦闘BGMを連動して修正するため。
- `Sol` / `Ultra`は不要。

## 1. 添付画像から確認した問題

### 1.1 中央封印が進行を妨げていない

- 閉鎖状態の中央封印が広場下側へ置かれているだけ
- ボス前室へ向かう必須通路を横断していない
- 解除しなくても封印を避けて先へ進める
- 解除すると装飾物が消えるだけで、通路が開いた感覚がない
- 門へ直接`中央封印 0 / 2`と表示され、デバッグ表示のように見える

### 1.2 同じ画面に停止した敵がいる

- 1つの遭遇グループだけが戦闘対象になり、近くの別グループは停止している
- 停止中の敵も画面には表示されるため、不自然に見える
- 戦闘中の敵を倒すと、戦闘終了扱いとなって探索BGMへ戻る
- 直後に停止していた別グループが動き始める
- その際、戦闘BGMへ切り替わらないまま攻撃される
- `stageEncounter`、active group、enemy awareness、party formation、BGMの状態が一致していない

## 2. 修正目標

1. 中央封印を、ボス前室へ進む唯一の通路を完全に塞ぐ門にする
2. 霊灯と石楔を解除しなければ絶対にボス前室へ入れないようにする
3. 門に直接表示される`中央封印 0 / 2`等の常時文字を削除する
4. 近接する遭遇グループの停止・再開を自然に管理する
5. 敵が動いて攻撃する時は、必ず戦闘状態・3人陣形・戦闘BGMに同期する
6. 戦闘継続対象が近くにいる間は、探索BGMへ戻さない

## 3. 中央封印の位置とマップ構造を修正

### 3.1 必須チョークポイントへ移動

- 中央封印を、左右ルートが合流した後、守護者の前室へ入る直前の細い通路へ配置する
- 門の左右を連続したwallまたはvoidで閉じる
- 閉鎖中に横・上・下から回り込める床を残さない
- ボス前室へ入る経路は中央封印を通る1本だけにする
- 入口側、霊灯側、石楔側は門の手前で合流する
- 門を開くまで、守護者の前室とボス扉へ物理的に到達不能にする

### 3.2 門の向き

- 通路が南から北へ進むなら、門は東西方向へ壁から壁まで横断させる
- 縦長の飾りを床の中央へ置くだけにしない
- 見た目の門幅とcollision幅を一致させる
- 最低でもキャラクター半径を含めて両端へ隙間を残さない

### 3.3 閉鎖状態の見た目

- 石板、石の爪、霊布、石鱗を組み合わせた封印門とする
- 左半分に青紫の霊灯紋様
- 右半分に琥珀色の石楔紋様
- 未解除側は暗い
- 片方解除時は対応する紋様だけ点灯する
- 門が床の装飾ではなく、立ちはだかる障害物だと分かる高さを持たせる

### 3.4 開放演出

- 2つの装置が作動したら門を開く
- 石板が床へ沈む、または石の爪が上下へ退く
- 左右へ観音開きする必要はない
- 1.2～2.0秒程度の重い作動音を使う
- 開放完了後にcollisionを解除する
- 見えない壁を残さない
- 門が開いた床は周囲と同じwalkable corridorへ変わる

## 4. 中央封印の文字表示

- 門の上へ常時描画している`中央封印 0 / 2`を削除する
- `中央封印 1 / 2`、`2 / 2`も門の上へ常時表示しない
- デバッグ用の数値表示に見えるUIを通常画面へ残さない

進捗は装置作動時の会話だけで伝える。

- 1つ目：`封印の片側が解けた。もう一つの装置が残っている。`
- 2つ目：`二つの封印が共鳴し、中央門が開いた。`

作動済み装置を再調査した時は、残る装置の色と方向を文章で示してよい。常時HUDは不要。

## 5. 門の進行テスト

- 0装置：門を通れない
- 霊灯だけ：門を通れない
- 石楔だけ：門を通れない
- 2装置：開放演出後に通れる
- 門の左右端、壁際、斜め移動でも抜けられない
- ノックバック、キャラ交代、フォロワー追従で閉鎖門を越えない
- 敵も閉鎖門を越えない
- ボス前室へ別ルートから侵入できない

## 6. 遭遇グループの状態原則

敵の状態を次の原則へ統一する。

### dormant

- 待機アニメーションのみ
- その場で小さく向きを変える程度は可
- プレイヤーへ接近しない
- 攻撃しない
- 接触ダメージを出さない
- 戦闘AI tokenを取得しない

### noticed

- 対象グループをactive encounterとして登録済み
- 戦闘開始予兆中
- 3人陣形への安全配置を開始
- 戦闘BGMへの切替を開始

### active

- 接近、位置取り、攻撃、ダメージが可能
- `stageEncounter === active`
- active group IDが一致
- partyは戦闘陣形
- 戦闘BGMが再生中

### cleared / disengaged

- 対象グループの敵が全滅または逃走処理済み
- 次の近接グループがない場合だけ探索状態へ戻す

## 7. 非active敵を絶対に動かさない

現在、個別AI更新の前に共有directorが全敵へ作用している可能性を確認する。

- `enemyDirector.update()`へ層内の全敵を無条件で渡さない
- 現在のactive encounterに属する生存敵だけを戦闘AI更新対象にする
- dormant/cleared/別groupの敵は予約位置、attack token、aware状態を持たない
- 非active敵のknockback、approach、reposition、attack stateを進めない
- 非active敵はプレイヤーへダメージを与えない
- 描画だけしてよいが、動く瞬間には必ずencounter stateを先に切り替える

## 8. 近接グループの重なりを整理

### 8.1 配置

- 別遭遇グループ同士のdetection radiusが大きく重ならないよう座標と半径を調整する
- 同じ画面に複数グループが見えても、停止敵が戦闘広場の中央に立ち尽くさないよう距離を取る
- 1つの広場に一緒に戦わせたい敵は、別groupへ分けず同じgroupに含める
- 霊灯前のウツロボウ2体＋イワウロコ1体は1グループとして同時管理する
- 石楔前のイワウロコ1体＋ウツロボウ1体も1グループとして管理する

### 8.2 画面内の待機敵

- 別groupの敵が近すぎて不自然に停止して見える場合、次の広場または曲がり角の奥へ移動する
- 入口から1画面内へ複数groupを詰め込まない
- 敵の総数9体と種類は維持する

## 9. 戦闘終了前の引継ぎ判定

active groupの最後の敵を倒した瞬間、すぐ探索状態へ戻さない。

次の順で判定する。

1. 現active groupの撃破・報酬処理を完了
2. 周囲に生存中の別dormant groupがいるか確認
3. そのgroupの敵がプレイヤーの連結床上か確認
4. プレイヤーがそのgroupの検知範囲内、または直ちに攻撃可能な近距離なら次groupへ引き継ぐ
5. 引継ぐ場合は戦闘BGMと3人陣形を維持
6. active group IDを新groupへ安全に切り替える
7. 短いnotice演出後に新groupをactive化
8. 引継ぎ対象がない場合だけ探索BGM・1人表示へ戻す

## 10. 戦闘BGMの同期

- BGMをenemy.aiStateだけでなく、正式なencounter stateと同期させる
- 敵がapproach/reposition/attackへ入る前に`beginStageCombat()`を完了する
- active groupの生存敵がいる間は探索BGMへ戻さない
- group引継ぎ中は戦闘BGMを止めない
- 探索BGMへ戻った状態で敵が動き始めた場合はバグとして扱う
- 逃走成立時だけ、既存ルールに従って探索BGMへ戻す

## 11. 敵ダメージの安全条件

敵がダメージを与えられる条件を明示する。

- 現在のroom/layerに属する
- alive
- 現active encounter groupに属する
- `stageEncounter === active`
- 戦闘開始猶予終了後

一つでも満たさない敵は、接触・投射物・特殊攻撃のダメージを発生させない。

## 12. 遭遇グループ完了条件

- HUDの`ENEMY x / y`は現active groupだけを数える
- group内の全敵が倒れた時だけgroup cleared
- 別groupの敵を誤って現在groupの残数へ含めない
- 逆に、現在groupの生存敵を残したまま戦闘終了しない
- 画面外へ一時的に出ただけで撃破扱いにしない

## 13. 自動テスト

### 中央封印

- 0/2、1/2でボス前通路を通過不能
- 両装置作動後だけ通過可能
- 迂回路が存在しない
- 門上の`中央封印 0 / 2`文字が描画されない
- 門開放後にcollisionが残らない

### encounter state

- dormant groupの敵は一定時間更新しても待機位置から接近しない
- dormant敵は攻撃・接触ダメージを出さない
- active groupだけがAI tokenを取得する
- active group撃破時、近接groupが検知範囲なら戦闘状態を引き継ぐ
- 引継ぎ中に探索BGMへ戻らない
- 引継ぎ対象がなければ探索BGMとsolo表示へ戻る
- 敵が動いている時は必ず戦闘BGMとformation状態
- 第2層、第3層の双方で同じ原則が成立する

### group count

- 霊灯前は3体すべて倒すまで戦闘終了しない
- 石楔前は2体すべて倒すまで戦闘終了しない
- HUD残数が実際のactive groupと一致する

## 14. 手動QA

1. DEV層選択から第3層へ入る
2. 装置を一つも作動せず中央門へ行く
3. 門がボス前通路を壁から壁まで完全に塞ぐことを確認
4. 門の左右から回り込めないことを確認
5. 門上に`中央封印 0 / 2`が出ないことを確認
6. 霊灯だけ作動しても通れない
7. 石楔も作動すると門が開き、初めて通れる
8. 霊灯前の3体戦で、停止した別groupが広場中央にいない
9. active group内の全敵が自然に動く
10. 最後の敵を倒した時、近くに次groupがいなければ探索BGMへ戻る
11. 次groupが近い場合は、戦闘BGMを維持したまま引き継ぐ
12. 探索BGM中に攻撃してくる敵がいない
13. 逃走時は全敵が安全位置へ戻り、探索BGMへ復帰する
14. 第2層でも同じBGM・encounter同期を確認する

- `npm run typecheck`
- `npm test`
- `npm run build`

自動テストだけで完了扱いにせず、第3層の中央門、霊灯前3体戦、石楔前2体戦、連続遭遇、探索BGM復帰をブラウザ上で実操作する。

## 17. 完了条件

- 中央封印がボス前通路を本当に塞いでいる
- 2装置を解除しなければボス前室へ進めない
- 門上の数値テキストが消えている
- dormant敵が不自然に接近・攻撃しない
- active groupの敵は全員が正常に戦う
- 次groupへの引継ぎ時に戦闘BGMが途切れない
- 探索BGM中に敵から攻撃されない
- 戦闘状態、敵AI、陣形、HUD、BGMが常に一致する

今回は見た目だけでなく、中央封印を進行上の必須ゲートへ直し、遭遇グループとBGMの状態不整合を根本から修正する。

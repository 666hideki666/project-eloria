# Codex向け追加指示：Mac用ワンクリック起動

Project Eloriaを、ターミナルへコマンドを手入力しなくても起動できるようにしてください。

ユーザーはエンジニアではありません。macOSのFinder上でファイルをダブルクリックすると、開発サーバーが起動し、準備完了後にゲームがブラウザで自動的に開くことを目標にします。

既存のゲームコード、ゲーム仕様、画像、package.jsonの通常の開発コマンドは壊さないでください。

## 作成するもの

プロジェクト直下へ、分かりやすい日本語名で次の2ファイルを作成してください。

- `Project Eloriaを起動.command`
- `Project Eloriaを停止.command`

必要であれば、実処理を行う補助スクリプトを `scripts/` 以下へ置き、`.command` ファイルはその呼び出しだけにして構いません。

両方の`.command`ファイルへ実行権限を付け、Finderからダブルクリックで動作することを確認してください。

## 起動ファイルの動作

1. 起動ファイル自身が置かれているディレクトリを基準に、必ずProject Eloriaのプロジェクトルートへ移動する。
2. パスに日本語や空白が含まれていても動作するよう、すべて適切にクォートする。
3. `node`と`npm`が利用可能か確認する。
4. 利用できない場合は、短い日本語メッセージで「Node.jsが必要」であることを表示し、勝手にインストールしない。
5. `node_modules`が存在しない場合のみ`npm install`を実行する。
6. すでにProject Eloriaの開発サーバーが動作している場合は、新しいサーバーを重複起動せず、既存のゲームURLをブラウザで開く。
7. サーバーが動作していない場合は、既存の`npm run dev`を使って起動する。
8. 起動したプロセスIDを、プロジェクト内の専用PIDファイルへ保存する。
9. ログをプロジェクト内の専用ログファイルへ保存する。
10. サーバーへ短い間隔で接続確認を行い、応答可能になるまで待つ。
11. 応答可能になったらmacOSの`open`コマンドでゲームURLを既定ブラウザへ開く。
12. 接続待ちは無限にせず、30秒程度でタイムアウトする。
13. タイムアウトまたは起動失敗時は、日本語で原因の概要とログファイルの場所を表示する。

現在のスクリーンショットではゲームURLが`http://127.0.0.1:4173`になっていますが、実装前に既存のpackage.jsonと開発サーバー設定を確認してください。

- 可能なら開発ポートを4173へ固定する。
- 4173を別アプリが使用している場合、別ポートでProject Eloriaを重複起動するのではなく、分かりやすいエラーを出す。
- Project Eloria自身がすでに4173で動いている場合は、そのままブラウザで開く。
- 別アプリが4173を使用している場合、そのプロセスを勝手に終了しない。

## 停止ファイルの動作

1. 起動時に保存したPIDファイルを確認する。
2. Project Eloriaの開発サーバーとして起動したプロセスだけを終了する。
3. PIDファイルが古い、または対象プロセスが存在しない場合は、安全にPIDファイルを整理する。
4. ポートを使用しているという理由だけで、無関係なプロセスを終了しない。
5. 停止完了または「すでに停止中」を日本語で表示する。

## 安全性

- `killall node`、`pkill node`など、他のNode.jsプロセスまで終了する広いコマンドは禁止する。
- ホームディレクトリやプロジェクト全体を対象にした削除コマンドを使わない。
- PID、ログ、起動状態の管理ファイルだけを対象にする。
- 二重起動、古いPID、異常終了後の再起動を安全に処理する。
- ブラウザを開く前に、実際にHTTP応答が返ることを確認する。

## 開発時の使いやすさ

- 起動中のターミナル画面には、次を日本語で簡潔に表示する。
  - 準備中
  - サーバー起動中
  - ブラウザを開いた
  - 終了方法
- エラーが発生した場合に確認できるよう、ターミナルを即座に閉じない。
- 起動成功後も、ゲームを終了するには`Project Eloriaを停止.command`をダブルクリックすればよいことを表示する。
- 通常の開発者向け`npm install`と`npm run dev`も引き続き利用できるようにする。

## Git管理

- PIDファイルと実行ログはGitへ含めないよう`.gitignore`へ追加する。
- `.command`ファイルと必要な補助スクリプトはGit管理対象にする。

## 確認項目

- Finderから`Project Eloriaを起動.command`をダブルクリックして起動できる。
- サーバーの準備完了後にブラウザが1回だけ開く。
- 起動ファイルをもう一度ダブルクリックしてもサーバーが増えず、ブラウザだけが開く。
- `Project Eloriaを停止.command`で、このプロジェクトのサーバーだけが停止する。
- 停止後に再度起動できる。
- プロジェクトパスに日本語や空白が含まれていても動作する。
- `node_modules`がある通常起動時に、毎回`npm install`を行わない。
- 通常の`npm run dev`も従来どおり動作する。

実装後は、ユーザーが実際にダブルクリックするファイル名と、初回にmacOSの警告が出た場合の開き方を日本語で簡潔に説明してください。

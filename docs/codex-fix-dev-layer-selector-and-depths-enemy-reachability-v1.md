# Codex向け修正指示：開発用層選択と第3層敵配置の到達性修正 v1

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- 理由：開始フロー、DEV専用UI、層状態初期化、第3層マップ、敵配置、到達可能性検証を横断するため。
- `Sol` / `Ultra`は不要。

## 1. ユーザー確認事項

現状の第3層には、コード上は次の9体が定義されている。

- ウツロボウ ×5
- イワウロコ ×4

しかし、実プレイでは次の問題がある。

- 動けない床、壁向こう、孤立した床などに敵が多数見える
- プレイヤーが近づけないため遭遇判定が発生しない
- 結果として、ウツロボウとイワウロコへ正常に遭遇できない
- 第3層の確認に第1層・第2層を毎回通る必要があり、修正確認へ時間がかかる

## 2. 今回の目的

1. 開発ビルド起動時に、第1層・第2層・第3層を直接選択できる画面を追加する
2. 第3層の敵9体を、プレイヤーが実際に歩いて到達できる戦闘場所へ再配置する
3. 初回生成、逃走後、撃破後再出現、層移動後の全経路で不正出現を防ぐ
4. ウツロボウとイワウロコへ確実に遭遇できることをQAとテストで保証する

## 3. 開発用の開始時層選択画面

### 3.1 表示条件

- `import.meta.env.DEV`のときだけ表示する
- アプリ起動後、通常探索を始める前に表示する
- production buildではDOM、描画、入力判定、当たり判定を一切残さない
- 完成版では削除できるよう、一つのDEV専用コンポーネントまたは処理へ分離する

### 3.2 画面内容

見出し：

`開発用｜開始する層を選択`

選択肢：

- `第1層　苔根の遺構`
- `第2層　光羽の晶洞`
- `第3層　霊布と石鱗の深層`

補足：

`この選択画面は開発版でのみ表示されます。`

### 3.3 操作

- マウス・トラックパッドで各ボタンをクリックできる
- キーボードの`1`、`2`、`3`でも選択できる
- 上下キー＋Enterでも選択可能にできれば既存UIへ合わせる
- 選択後は画面を閉じ、選んだ層の安全な入口から開始する
- モバイル対応を想定し、ボタン全体を大きなクリック領域にする

### 3.4 各選択時の状態

#### 第1層

- 通常のゲーム開始状態
- 第1層入口から開始
- 第1層の仕掛け・敵を初期状態へ戻す

#### 第2層

- 第2層入口から開始
- 第2層の仕掛け・敵を初期状態へ戻す
- 第1層を通過済みとして扱うために必要な最小状態だけ設定する
- HP、MPはテスト開始用の初期値にする

#### 第3層

- 第3層入口テラスから開始
- 霊灯、石楔、中央門、近道、敵9体、ヒント表示を初期状態へ戻す
- 第2層の出口条件は通過済みとして扱う
- 第3層から第2層へ戻れる
- 第2層へ戻った場合も進行不能にならないよう、必要な主晶石・副晶石・湖上石段の状態を整合させる

### 3.5 既存DEVワープ

- スタート地点にある既存の第2層DEVワープは、開始時層選択が安定した後は重複する
- 今回は安全のため削除せず維持してよい
- ただしDEV専用のままとし、productionへ出さない
- 将来、開始時層選択だけで十分と確認後にまとめて削除可能な構造にする

## 4. 第3層の敵定義を維持

敵の合計と種類は変更しない。

- `depthsSpiritEntry`：ウツロボウ ×2
- `depthsSpiritLamp`：ウツロボウ ×2、イワウロコ ×1
- `depthsStonePassage`：イワウロコ ×2
- `depthsStoneWedge`：イワウロコ ×1、ウツロボウ ×1

合計：ウツロボウ5体、イワウロコ4体。

モスプルンやルミバネ等へ置換しない。画像ロード失敗時のフォールバックも敵種別を維持する。

## 5. 不正出現の根本原因を確認

次を確認してから座標を直す。

- `DEPTHS_ENCOUNTERS`の全authored position
- `DEPTHS_SAFE_GROUP_ANCHORS`
- `findNearestSafeDepthsEnemySpawn()`の探索範囲
- safe判定が単に`floor`だけを見ていないか
- 中央門開放前の入口側から到達可能な連結成分か
- 壁で隔てられた床の小島へ補正されていないか
- 敵半径を含めて通路幅が十分か
- encounter detection radius内へプレイヤーが入れるか
- 敵を描画しているが、対応する遭遇グループを開始できない状態になっていないか

## 6. 「安全な床」の定義を強化

敵の出現地点は、次のすべてを満たす必要がある。

1. 敵の中心と半径全体がwalkable tile内
2. 壁、void、門、装置、段差、前景オブジェクトと重ならない
3. 他の敵と重ならない
4. プレイヤーがその時点の進行状態で歩いて到達できる
5. その遭遇グループ用の戦闘広場と同じ連結床に属する
6. detection radius内へプレイヤーが歩いて入れる
7. 戦闘開始後、敵が最低80～120px程度動ける空間がある
8. イワウロコの突進方向に最低限の有効距離がある

## 7. 到達可能性判定

### 7.1 Flood fill / BFS

第3層入口の安全地点を起点に、現在通行可能なタイルをBFSまたはflood fillして、到達可能タイル集合を作る。

- 中央門閉鎖前の通常状態を基準にする
- shortcutは閉鎖状態を基準にする
- 左右の装置へ向かう全ルートは初期状態で到達可能でなければならない
- ボス前室は中央門開放後の別到達集合で検証する

敵の初期配置と再出現候補は、対象グループが属する到達可能集合に含まれる場合のみ採用する。

### 7.2 候補地点方式を推奨

ランダムな近傍補正だけへ依存せず、各遭遇グループに3～6個の明示的な安全候補地点を用意する。

例：

- `DEPTHS_SAFE_SPAWN_CANDIDATES[groupId]`
- 各候補はマップ作成時にwalkable、solid prop、到達可能性を検証する
- 初回出現も再出現も同じ検証済み候補を使用する

候補が見つからない場合、元の不正座標へ無条件フォールバックしない。

- DEVでは明確なwarningを出す
- 対象の敵は生成を保留する
- テストを失敗させ、問題を見逃さない

## 8. 敵の再配置方針

### グループA：霊布の入口

- 西側ルートへ入ると画面内または次の画面でウツロボウ2体が見える
- 壁向こうではなく、プレイヤーと同じ広間へ置く
- 1体目のdetection radiusへ必ずルートが交差する

### グループB：霊灯の広間

- ウツロボウ2体、イワウロコ1体を広間内部へ置く
- 霊灯の真上や背後へ置かない
- 装置へ到達する前に自然に遭遇する
- 3体を同じ一点へ密集させない

### グループC：石鱗の通路

- イワウロコ2体を別々の曲がり角または広がりへ置く
- 狭すぎて突進不能な通路へ置かない
- 2体が同時に反応しない距離を確保する

### グループD：石楔前

- イワウロコ1体、ウツロボウ1体を石楔手前の戦闘空間へ置く
- 石楔の操作範囲と敵の待機範囲を重ねない
- 装置へ向かう通常ルート上で必ず遭遇できる

## 9. 敵の表示と遭遇

- dormant状態の敵を表示する現行仕様は維持してよい
- ただし見えている敵へプレイヤーが到達できなければならない
- プレイヤーがdetection radiusへ入ったら`noticed`へ遷移する
- 初遭遇時にウツロボウ／イワウロコの既存ヒントを表示する
- ヒント表示後に遭遇状態が壊れず、そのまま戦闘へ移行する
- ウツロボウとイワウロコの専用攻撃、画像、影、接地設定を変更しない

## 10. 再出現

初期生成だけでなく、次のすべてで同じ安全候補と到達可能性判定を使う。

- 逃走してグループがリセットされた時
- 撃破後、距離と時間条件を満たして再出現する時
- 第2層へ戻って第3層へ再入場した時
- DEV層選択で第3層を選び直した時

層遷移開始フレームで退出元の敵を復活させない既存仕様も維持する。

## 11. 開始時層選択の視覚仕様

- 現在のゲームUIと同じ暗い青緑、シアン枠、金色の選択色を使う
- 各層を横並び、または縦3段のカードとして表示する
- 小さい画面では縦3段へ切り替える
- 選択中の層を明るい枠で示す
- ボタン文言は日本語で省略しない
- `DEV`または`開発用`を明確に表示し、完成版UIに見せない

### 第3層の敵

- 再出現地点も同じ安全・到達可能性判定を通る

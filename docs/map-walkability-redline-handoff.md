# 画像＋ユーザー赤線による歩行範囲：成功手順と引き継ぎ

## 結論

第1層「晶界・苔根の遺構」では、背景画像を先に確定し、ユーザーがその上に赤線で歩行可能範囲を囲み、その内側を歩行マスクにした。移動の可否はキャラクター全身や大きな当たり円ではなく、**足元の接地点 `pos` の一点**で判定する。ユーザーは2026-09-24に「これで歩ける通路はうまくいった」と確認した。第2層以降の画像ベースのマップでも、この方法を基本にする。

## 成功までに分かったこと

- 石畳の色や形から歩行範囲を自動推測すると、苔・階段・影・装飾を誤認しやすい。背景だけから通路を決めない。
- 赤線の内側は石畳だけでなく、階段・苔を含めて歩行可能。赤線外は、床に見える部分があっても歩行不可。未指定の近道や広場を追加しない。
- 赤線から生成したマスクは正しくても、足元の周囲を半径約5.5画像pxの円で調べる旧判定では、狭い通路が途切れた。第1層では `src/stage/tileCollision.ts` の円周16点判定が原因だった。
- 足元一点の終点判定だけでは薄い赤線・非歩行帯を高速移動で飛び越える。第1層の解決策は、x/y別の移動線分が横切る背景ネイティブ画像のセルを検査する方式。足元の歩行判定と、攻撃・被弾など戦闘用の物理半径は分離した。
- マスク上でスタートから目的地へ経路があるだけでは不十分。実際の移動関数で経路を再生し、狭い箇所を通過し、崖・赤線外に出ないことを確認する。

## 次の階層での標準手順

1. 背景マップ画像を作り、ユーザーと見た目・ランドマーク配置を確認する。
2. **背景だけの画像**を渡し、ユーザーに歩かせたい範囲の外周を赤線で囲んでもらう。どこが入口、クリスタル・仕掛け・出口かも確認する。
3. 赤線付き画像と元背景を同じネイティブ座標で重ね、線の閉じ忘れ、交差、極端なくびれ、ランドマークが外にある箇所を目視する。不明点はユーザーへ確認し、勝手に補完しない。
4. 赤線内をマスク化し、重ね図をユーザーに提示する。赤線上や外側を歩行可能に広げる変更は、見た目と一致するか確認するまで行わない。
5. 足元接地点で歩行可否を判定する。移動中に通過するマスクセルも検査し、赤線を跨ぐ抜け道を防ぐ。戦闘の当たり判定半径とは別に扱う。
6. スタートから各広場・重要アイテム・仕掛け・出口まで、マスク上の連結性だけでなく**ゲーム内の移動処理**で到達性をテストする。赤線外、画面外、細い遮断帯、斜め移動、高速移動も否定テストに入れる。
7. ブラウザで通常操作し、通路の通過と目的物のインタラクションを確認する。問題箇所は画像座標付きでユーザーへ返し、局所的な赤線修正を相談する。

### 第1層の仕掛けに関する追記（2026-09-24）

第1層の仕掛けは**右広場のクリスタルで、北側の大きな根を解除する1個だけ**。左広場の追加石碑と「隠し部屋用の根」は不要として撤去した。赤線マスクはそのまま床の範囲を示し、唯一の根が閉じている間だけ動的な障害領域を重ねる。解除アニメーションが終わってから通行可能にする。実装指示の詳細は `docs/codex-fix-layer1-single-root-puzzle-v1.md`。

### クリスタルへの橋の局所修正（2026-09-24）

ユーザーが右広場の橋の下側に青線を追記したため、旧赤線の対応区間だけ境界を移した。元画像座標 x=994〜1041、y=541〜557 の**306画素のみ追加**し、ほかの歩行範囲の削除は0画素。新しい参照図は `docs/references/moss-root-walk-boundary-red-v2.png`、拡大確認図は `docs/screenshots/layer1-blue-bridge-walkability-zoom.png`。小さな違和感にはマスク全体の膨張ではなく、ユーザー指定に沿う局所差分と差分検査で対応する。

### クリスタルの物体判定と DEV WARP（2026-09-25）

赤線内の床でも、石台のような立体物は別レイヤーの常設コライダーで塞ぐ。第1層ではクリスタル石台だけに足元一点の楕円判定を加え、広場や細い通路の床マスクは変えなかった。開発用 DEV WARP は赤線外の旧座標から、スタート北側の通路内（背景座標 `(648, 1120)`）へ移した。指示書と確認結果は `docs/codex-layer1-crystal-solid-and-dev-warp-v1.md`。

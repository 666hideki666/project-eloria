## 意図

前回の「２文をいきなり出す」は、**２文を出す間にクリックを挟まない**という意味。２文の全文を一瞬で表示する意味ではなかった。１枚の絵で１文目から２文目まで文字がタイプライター風に続けて現れ、２文とも出終わったところで静止する。現行の６画像・各２文の採用原稿は `docs/storyboard-eloria-prologue-narration-v3.md` を維持する。人物台詞と話者ラベルに戻さない。

## 期待する進行

1. 画像が表示されたら、１文目が左から順に現れる。文末後、同じ字幕枠の次の行で２文目が**追加操作なしで**続けて現れる。句読点に短い自然な間を入れるのは可。ただし２文目の開始にクリックは要求しない。字幕枠の高さは途中で大きく跳ねないよう、完成形を収める領域を確保する。
2. タイプ表示が終わっても自動で次の画像へは進まない。プレイヤーが内容を読み、クリック／タップ／既存の決定キー１回で次の画像へ進む。
3. タイプ表示の途中で操作した場合は、**その絵の２文を一度に最後まで表示する**。その同じ操作で次の絵には進まない。全文表示後の次の操作で次の絵へ進む。長押し・ダブルクリック・キーリピートで２段階が一気に消費されないようにする。
4. ６枚目も同じ動作とし、２文を読み終えて次へ進むと、既存どおり古の森へ一度だけ着地する。途中スキップ／タイトルへ戻る／再STARTは維持する。
5. 動き軽減設定では文字演出を省き、２文を最初から全文表示する。画面読み上げ向けの `aria-live` はタイプ途中の１字ごとに更新せず、場面ごとの完成した２文を一度だけ伝える。序章は引き続き無音で、タイプ音は加えない。

## 実装範囲と検証

- `src/ui/openingSequence.ts` に**場面単位の文字進行**を持たせ、改行を含む２文を一つの連続した本文として進める。Unicode文字を途中で壊さず、経過時間で一定のテンポにする。非表示タブ／ポーズ時は勝手に文字が進まない。前の台詞版の行単位進行には戻さない。
- `src/ui/OpeningController.ts` で進行中は「全文を表示」、完成後は「次へ」を明示。字幕の可視文字と読み上げ用全文を分けて更新する。`src/ui/opening.css` ではPC・横スマホ・iPad相当で２文表示とボタンの非重複、絵の要点の視認性を保つ。現在の６画像、画角、スキップ、フェード、無音→森BGM、開発用導線は維持する。
- 自動文字進行、１文目から２文目への**操作なし**の移行、途中操作で２文全文表示、次の操作で１画像だけ進むことをテストする。長押し・連打、６枚目の一度だけの森着地、途中スキップ、戻って再開始、動き軽減、画像失敗時、非表示タブからの復帰、読み上げ全文を確認する。
- `npm run typecheck`、`npm test`、`npm run build`、PC16:9・横スマホ・iPad相当・製品版の実画面確認を行う。検証で開いた隠しブラウザ／サーバー／音は作業後に閉じ、ユーザー起動中のサーバー等は止めない。実機・Safari/WebKit・VoiceOver・聴感が未確認なら、そのまま記録する。

# ゲーム中に読む文字の画質統一：実装指示書案 v1

状態：**2026-10-22、ユーザーが「実装に移って」と明示承認。同日に実装・技術検証済み。** 推奨モデル：Sol High。実機・Safari/WebKit・VoiceOver・聴感は未確認。

## 問題と原因

第１層のクリスタル横で出る「E　クリスタルに触れる」は `GameWorld.snapshot.interactionPrompt` を `src/render/HudRenderer.ts` の `fillText` で640×360の `#game` canvas下部へ10pxで描いている。`src/style.css` の `#game { image-rendering: pixelated; }` で画面いっぱいに拡大されるため、添付スクリーンショットのように文字が荒い。前回の改善は `src/ui/FieldMessages.ts` による**上部通知のみ**で、下部ヒントや仕掛けの会話は対象外だった。

承認時点の `src/render` 全体の `fillText` / `strokeText` 調査と移行方針：

| 表示 | 移行前の描画元 | 対応方針 |
| --- | --- | --- |
| 下部の操作ヒント（クリスタル、主・副結晶、晶泉、霊灯、石楔、再生晶石、封印門、封印石など） | `HudRenderer` の `interactionPrompt`、10px canvas | 全ステージ共通の高解像度DOMへ移す |
| 仕掛け・出口・DEV確認などの会話、送り表示 | `HudRenderer.drawDialogue`、8–10px canvas | 高解像度DOMへ移す。既存の文章・ページ進行・タイプ表示・入力仕様は保持 |
| ボスゲージの名称「森晶獣ヴェルグラン」と「晶核露出」 | `HudRenderer.drawBossGauge`、9px canvas | ゲージ全体をDOM表示へ移し、HP/装甲の値・表示条件を保持 |
| arenaモードの上部短文 | `HudRenderer` のarena専用banner、10px canvas | 既存の鮮明な上部通知へ統合。stage/arenaの優先順位を維持 |
| HP/MP/EXP取得時の浮く文字 | `Renderer.drawEffect` の `kind: "text"`、8–9px canvas | ワールド座標を既存カメラで画面へ投影するDOM効果へ移す。移動・寿命・色・発生位置を保ち、文字を鮮明にする |
| 敵の気づき「!」とdebug AI文字 | `Renderer` の記号／debug専用表示 | 「!」は絵の一部としてcanvasに残す。debug表示は製品版の読ませるUIではないため今回は対象外 |

タイトル・プロローグ・中央の層タイトル・パーティHUD・前回移行した上部通知は既にDOMであり、今回の描き直し対象ではない。マップ・キャラクターのピクセル表現と `#game` の `image-rendering: pixelated` は維持する。画像内に描き込まれた文字は今回のコード描画調査の対象外。

## 変更仕様

1. `.field-shell` に高解像度の下部操作ヒント、会話、ボスゲージ、浮き文字のレイヤーを追加し、canvas側の該当文字と背景箱を撤去する。既存の `WorldSnapshot` / `EffectPool` を表示データとして使い、同じ文字をcanvasとDOMに二重表示しない。１フレームごとにDOMノードを作り直さず、内容・表示状態が変わる時だけ更新する。
2. 操作ヒントは画面下部中央に16px以上の日本語システムフォントで表示。現行の文言と、敵遭遇・会話・上部通知中に出ない条件を維持する。初回異変演出、中央入場タイトル、ポーズ、ステータス画面、暗転中には表示しない。横スマホ・iPad・全画面・ブラウザ拡大で画面外へ出ず、下部の戦闘操作ガイドとも重ならない。
3. 仕掛け会話は下部の読みやすいDOMパネルにする。本文18px以上、長文は自然に折り返し、狭い画面ではスクロール可能。ページ見出し・「E / クリック ▼」は視認できる大きさへ。`snapshot.dialogue.text` の逐次表示をそのまま用い、完了・送り・連打防止・音・戦闘停止などのゲームロジックは変更しない。タップ領域は現行と同じくcanvas全面を使える状態を保ち、パネルが操作を邪魔しないようにする。重要会話は上部通知・下部ヒントより優先。
4. 守護者戦のゲージとラベルをDOMの同一コンポーネントにまとめる。既存のゲージ位置・HP／装甲／晶核露出の意味とタイミングを保つ。上部通知はゲージ下に配置し、左上パーティHUDと右上ポーズを避ける。arena上部通知もstageと同じ鮮明さにする。
5. 浮き文字はワールド効果の位置とカメラから画面上の位置を求め、既存の移動・フェード・寿命をDOMに反映する。複数同時発生、部屋遷移、画面端の切れ方、ポーズ時停止を確認。読み上げが頻繁に連発されないよう装飾効果として扱う。
6. DOM文字に背景との十分なコントラストを与えるが、古いPCゲーム風の大きな枠にはしない。中央入場タイトルとプロローグの既存デザインは変えない。

## 実装結果（2026-10-22）

- `FieldMessages` に下部操作ヒント、仕掛け／出口／DEV会話、ボスゲージ、浮き文字を統合。`HudRenderer` のcanvas文字・背景箱を撤去し、未使用となった同クラスも削除。arena通知を既存のDOM上部通知へ統合した。`Renderer` のテキスト効果はcanvas描画から除外し、同じ文字の二重表示をなくした。
- ヒントは16px以上、会話本文は18px以上、見出し／送り表示／ボス名／晶核露出は16px。既存の `interactionPrompt` と `dialogue.text` を使い、距離・遭遇・会話進行・タイプ速度・効果音・ページの入力ロックを保持する。会話パネルのクリック／タップはcanvasと同じ入力バッファへ渡す。初回のタッチではクリック処理後にタッチUIへ切り替え、操作中のレイアウト移動による入力取りこぼしを避ける。
- 会話は上部通知・下部ヒントより優先。中央タイトル・異変演出・ポーズ・ステータス・暗転中の表示を抑制する。下部戦闘ガイドの上にヒントを置き、会話中はガイドを隠す。長文会話の最大高をHUD／ボスゲージの実位置から決め、狭い画面でもHUDを覆わず、パネル内をスクロールできる。
- ボス名・HP・装甲・晶核露出を同じDOMコンポーネントへ移し、従来の表示フェーズと比率を保持。上部通知はDOMゲージの実際の下端より下へ配置する。狭い画面で左右の空きが足りない時は、HUDの下へ回して表示する。
- HP／MP／EXP文字は既存 `EffectPool` のオブジェクトにDOMノードを対応させ、ワールド座標からカメラを差し引いて画面へ投影する。色・回転・速度・寿命・フェードを同じデータから読み、ノードを毎フレーム作り直さない。画面外は効果レイヤーでクリップし、効果の終了や部屋遷移でノードを取り除く。読み上げ対象外の装飾として扱う。
- **ポーズ対応の限定変更**：従来は非プレイ時にも全効果を0.35倍速で進めていたため、`EffectPool.update` にテキストだけを停止するオプションを追加し、`GameWorld` のpaused時に指定する。ポーズ中の浮き文字の位置・寿命を固定し、他の環境粒子は従来どおり。ゲーム進行側の変更はこの指定だけで、元に戻した内容のハッシュが開始時と一致することを確認した。
- 640×360 canvasと `image-rendering: pixelated`、背景・歩行マスク・敵・仕掛け・BGMを保持。前回の異変演出と上部通知も維持した。

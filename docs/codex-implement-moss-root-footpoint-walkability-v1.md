## 目的

第1層「晶界・苔根の遺構」で、キャラクターの**足元の接地点（ゲーム座標 `pos`）**が既存の赤線由来の歩行マスク内にある限り歩けるようにする。斜め上から見る構図なので、胴体・頭・影・靴の描画が赤枠や床の輪郭から多少はみ出しても、そのことだけでは移動を止めない。

赤枠外へ接地点を出してはいけない。赤線・マスクの形、背景、クリスタル、根の仕掛け、戦闘や攻撃の当たり判定はこの作業で変更しない。

## 現状と原因

- `src/stage/tileCollision.ts` の `isMossRootPositionWalkable()` は中心点に加え、`radius - 0.35` の円周を16点サンプリングしている。カイル・ナディの移動半径9 world pxは背景画像上で約5.5pxの余白要求になり、赤枠内の狭い通路を塞ぐ。
- `tests/stage.test.ts` に現在の「足元円全体が入る」「赤線のくびれは通れない」を期待するテストがある。新仕様に合わせて書き換える。
- `scripts/generate-moss-root-walkability-data.mjs` の必須経路はすでに `routeFootRadius = 0`。経路が存在することと、実際の移動処理で通れることの両方を検証する必要がある。
- `resolveMossRootMovement()` は移動先を段階的に判定するが、現状の刻みは最小4 world px。足元一点判定へ変える際は、薄い赤枠・外側の非歩行域を一歩で跨がないよう、**移動線分が通る画像の全ピクセル**を検査する。

## 実装方針

1. 第1層の `isMossRootPositionWalkable(point, radius, options)` は、`point` がワールド内であり `isMossRootNavigationPoint(point)` が真なら歩行可とする。第1層の歩行可能性に `radius` の円周16点を使わない。既存の呼び出しAPIは必要なら互換性のため維持してよいが、`radius` は他ステージや戦闘用の物理サイズとして残す。コメントも「全身／足元円」から「接地点」に修正する。
2. `resolveMossRootMovement()` は横・縦のスライド挙動を維持しつつ、それぞれの移動線分が横切る背景ネイティブ画像のマスクセルをすべて確認する。推奨は source 座標に変換した線分の supercover/DDA 検査。終了点だけの判定や4 world px刻みのままでは、細い非歩行帯を飛び越えるおそれがある。赤枠外のセルを横切る移動はその手前で止める。斜め移動、ノックバック、高速移動でも同じ。
3. `findNearestMossRootWalkablePosition()` も接地点基準で投影する。スポーン、交代、ワープ、敵、追従キャラなど、第1層でこの関数・歩行判定を使う経路を確認する。赤枠外を許す例外を作らない。
4. 既存の赤線画像 `docs/references/moss-root-walk-boundary-red-v1.png`、生成済みマスク、背景画像は変更しない。赤線自体や赤枠外を新たに歩ける領域へ拡張しない。装飾・苔・階段は赤枠内なら引き続き歩行可能。
5. 戦闘の接触・攻撃・被弾半径を足元一点へ変更しない。歩行用のマスク判定と戦闘用の物理半径を混同しない。

## 必須テスト

- `tests/stage.test.ts` の「足元円全体が必要」「くびれは通れない」という旧仕様テストを新仕様へ置換する。既存マスク内の `{x:313,y:539}` と `{x:1015,y:540}`（背景画像座標）はカイル半径9でも足元一点として歩行可能になること。
- マスク内の境界ぎりぎりの点は歩行可能、隣接する赤線／赤枠外の点は不可。画面外も不可。
- 開始地点からクリスタル、根の手前・向こう、最終広場まで、`mossRootRequiredRoute.points` を実際の `resolveMossRootMovement()` へ順に通し、全点に到達できること。既存の経路JSONを再生成する必要がなければ保持する。
- 明確な赤枠外へ向かう移動が境界で停止すること。単発の長い移動、斜め移動、1〜数px幅の非歩行帯を跨ぐ移動も検証する。最終位置だけでなく途中の接地点もマスク外へ出ないこと。
- キャラクター、追従キャラ、敵の通常移動／ノックバック／ワープ先がマスク内に留まること。既存の他ステージと戦闘テストに回帰がないこと。

## 完了条件

1. ユーザーの赤枠内の狭い通路を、足元を床に置いたまま通れる。特に右側通路からクリスタル広場まで実機操作で到達し、クリスタルを調べられる。
2. 赤枠外へ足元の接地点は出ない。円周判定をなくした結果、赤線を飛び越える問題もない。
3. `npm run typecheck`、`npm test`、`npm run build` が通る。
4. 変更ファイル、テスト結果、ブラウザで確認した区間と未確認事項を実装タスクで報告する。見た目の違和感が残る場所があれば、マスクを勝手に広げず位置を示してユーザーへ相談する。

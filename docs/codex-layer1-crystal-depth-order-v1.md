## 実装方針

1. `drawTransferCrystal` を第1層の背景描画から外し、**一度だけ**キャラ・敵と同じ奥行き順で描く。既存の `Renderer.drawActors` には奥行き順の描画コールバック (`depthOverlayY` / `depthOverlay`) があるので、それを第1層のクリスタルにも利用するのが最小変更。第2層の既存オーバーレイを壊さない。
2. 奥行き基準は結晶の先端ではなく**地面に接する石台の位置**。現行の石台コライダー中心、背景座標 `(1160, 535)`（ワールド変換後の y）を候補とする。足元 `pos.y` がそれより小さいキャラ・敵はクリスタルの先に描き、足元が大きいキャラ・敵はクリスタルの後に描く。同じ y の境界は違和感のない順で統一する。
3. クリスタルの発光・解除アニメーションは現状の引数と状態を維持する。背景画像に焼き込まれた丸い石台を新規素材で描き直すことは今回の範囲外。まず描画された結晶と上面の重なりを直す。
4. カメラのスクロールや画面揺れに合わせ、他のキャラと同じワールド座標変換の内側で描く。別レイヤーで二重描画しない。DEV WARP と北の根の描画順には触れない。

## 検証

- ユーザー画像と同じクリスタル奥側に立つと、結晶がキャラの下半身／足元の手前に重なる。
- クリスタル手前側に立つと、キャラが結晶の手前に出る。左右を歩いても突然不自然に前後が切り替わらない。
- キャラ交代・仲間・敵が同じ位置に来ても、接地点 y による一貫した順序。クリスタルのアニメーションと E 操作・根解除は維持。
- 描画順を記録する自動テストを可能な範囲で追加し、`npm run typecheck`、`npm test`、`npm run build` を通す。可能ならブラウザで奥側／手前側の2画面を目視確認する。

# Codex向け追加指示：HUDによる戦闘画面の遮蔽を修正

現在のProject Eloria試作版では、キャラクターと敵が画面左上のパーティーHUDおよび右下の技ボタンの裏へ移動でき、戦闘中に完全に隠れてしまいます。

確認された問題：

- 左上へ移動すると、操作キャラクターと後方メンバーがHPパネルの裏に隠れる。
- 右下へ移動すると、キャラクター、敵、攻撃エフェクト、敵HPが技ボタンの裏に隠れる。
- HUDの裏で攻撃を受けたり敵が行動したりするため、状況を判断できない。
- 現在は簡易ドット絵だが、正式スプライトへ差し替えると遮蔽がさらに目立つ可能性がある。

既存の戦闘、操作、敵AI、陣形、BGM、効果音を維持したまま、デスクトップ版のHUDレイアウトを修正してください。

## 1. 基本方針

デスクトップ版では、常時表示する重要HUDを戦闘フィールドへ重ねないでください。

推奨レイアウト：

```text
┌─────────────────────────────────────┐
│ タイトル / エリア名 / 音声 / ポーズ │
├──────────┬──────────────────────────┤
│ 3人の状態 │                          │
│ HP / MP   │      戦闘フィールド      │
│ 操作状態  │                          │
├──────────┴──────────────────────────┤
│ 操作説明          技ボタン4個         │
└─────────────────────────────────────┘
```

- 左側へパーティー状態専用のサイドパネルを設ける。
- 中央から右側を、遮蔽物のない戦闘フィールドとして扱う。
- 通常攻撃、特殊技、大技、交代の4ボタンは戦闘フィールド下の専用フッターへ移動する。
- エリア名、残り敵数、BGM、ポーズは上部の細い情報バーへまとめる。
- 戦闘フィールド内に常時表示する大きな固定HUDを残さない。
- 現在ページ周囲にある余白を有効利用し、必要以上に戦闘フィールドを小さくしない。

既存構造の都合で完全な外部配置が難しい場合も、左上と右下の固定HUDがプレイ領域を覆う現状のままにはしないでください。

## 2. 戦闘フィールドとUIの座標分離

- ゲーム世界の座標とHUDの座標を明確に分離する。
- 戦闘フィールドの表示領域を、HUDを除いた実際の矩形として定義する。
- キャラクター、敵、ドロップ、攻撃判定、敵予兆は戦闘フィールド座標だけで動かす。
- CSS上のHUD位置をゲームの当たり判定座標へ混在させない。
- Canvas内にHUDを描いている場合は、戦闘描画用CanvasとDOM HUD、または戦闘CanvasとHUD Canvasを分離することを検討する。
- HUDを外へ移した結果、ゲーム世界の座標、衝突判定、敵AIの距離計算が変わらないようにする。

## 3. デスクトップHUD

### 左サイドパネル

- カイル、ナディ、メルの3行を縦に表示する。
- 操作中キャラクターを明るい枠で強調する。
- HP、メルのMP、自動回復待機状態を維持する。
- 現在より横幅を少し抑えてよいが、数値とゲージを読み取れる大きさを保つ。
- キャラクターがサイドパネルの裏へ入る構造にはしない。

### 下部アクションバー

- 通常攻撃、特殊技、大技、交代の4ボタンを横一列にする。
- J、K、L、Spaceのキー表示を維持する。
- 大技の使用可能状態とクールダウンを読み取れるようにする。
- アクションバーの高さを必要最小限にする。
- 戦闘フィールドの下へ配置し、ゲーム内オブジェクトを覆わない。

### 上部情報バー

- エリア名
- Trialまたはウェーブ情報
- 残り敵数
- BGMミュート
- ポーズ

これらを細いバーへ整理する。重複表示や大きな空白を作らない。

## 4. 戦闘フィールドの大きさ

- HUDを外へ出した結果、戦闘フィールドが極端に狭くならないようにする。
- 可能なら現在の戦闘フィールドと同程度の表示面積を維持するため、ゲーム全体の外枠を少し広げる。
- ブラウザの表示領域に合わせて、ゲームUI全体を均等に縮小する。
- 縦横比を崩してCanvasだけ引き伸ばさない。
- ピクセルアートの輪郭がぼやけないよう`image-rendering: pixelated`など既存の設定を維持する。
- 1280×720、1440×900、1920×1080相当で確認する。
- ブラウザのツールバーを除いた表示領域へ収まり、不必要な横スクロールを発生させない。

## 5. 小さい画面

ウィンドウ幅が不足する場合は、次の順で対応してください。

1. 余白を縮める。
2. HUD内の間隔を縮める。
3. ゲームUI全体を比率を維持して縮小する。
4. それでも不足する場合のみ、コンパクトHUDへ切り替える。

小さい画面でも、常時表示HUDがキャラクターを完全に隠さないことを優先してください。

## 6. 将来のモバイル版

モバイルでは技ボタンとスティックを戦闘フィールドへ重ねる必要があるため、デスクトップと別レイアウトにしてください。

- マウス／キーボード入力時はデスクトップ外部HUDを使用する。
- タッチ入力時はモバイル用オーバーレイHUDへ切り替える。
- モバイルHUDは半透明にする。
- キャラクターや敵がボタンの近くへ来た場合、ボタンの不透明度をさらに下げる方式を検討する。
- `env(safe-area-inset-*)`を考慮する。
- 今回の必須対象はデスクトップ版。モバイル版は既存機能を壊さない範囲で準備する。

## 7. 避ける修正

- HUDの下へ入れないよう、見えない壁を追加するだけの修正。
- プレイヤーだけを中央へ強制移動し、敵はHUDの裏へ入れる修正。
- HUDを小さくするだけで、依然として戦闘フィールドへ重ねる修正。
- HUDを極端に透明にし、HPや技の状態が読めなくなる修正。
- 戦闘フィールドを縦横別々に引き伸ばす修正。
- ウィンドウサイズごとにゲーム世界の速度や当たり判定が変わる修正。
- デスクトップとモバイルで同じHUD配置を無理に共有する修正。

## 8. 完了条件

- プレイヤーが戦闘フィールドの左上へ移動しても、パーティーHUDに隠れない。
- プレイヤーが戦闘フィールドの右下へ移動しても、技ボタンに隠れない。
- 敵、敵HP、攻撃予兆、ドロップ、エフェクトも固定HUDに隠れない。
- パーティーHP、メルのMP、操作中キャラクターを常に確認できる。
- 通常攻撃、特殊技、大技、交代の状態を常に確認できる。
- 現在のキーボード操作が変わっていない。
- BGM、効果音、ポーズ、ミュートが正常に動く。
- 戦闘フィールドの当たり判定と表示位置が一致する。
- 主要なデスクトップ画面サイズでレイアウトが収まる。
- 正式スプライトへ差し替えても使える余裕がある。

実装後は、修正前後のスクリーンショットを撮り、左上・右下へ実際に移動して遮蔽がなくなったことを確認してください。採用したレイアウト、戦闘フィールドの表示サイズ、確認した画面サイズを日本語で報告してください。

# Codex向け修正指示：第2層晶泉の湖統合・第1層泉撤去・石碑ゲート転用 v1

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- `Sol` / `Ultra`：不要
- 理由：2層分のマップ、描画、衝突、操作、進行フラグ、QAを連動して修正するため。

## 1. 目的

次の3点を修正する。

1. 第2層の大型晶泉を独立した床上施設として置かず、上側の大きな地下湖と一体化する
2. 第1層「苔根の遺構」の回復の泉を完全撤去する
3. 第1層石碑のゲートを「泉へ戻る近道」から、将来の宝箱区画を開く仕掛けへ転用する

回復地点を毎層へ置く規則にはしない。現段階では、第1ダンジョン内の主要回復地点を第2層の晶泉とする。

## 3. 第2層晶泉を大きな地下湖へ統合

現在の晶泉は直径約180pxの施設として狭い床広場へ置かれているため、周囲との比率が不自然に大きい。

小さく縮小するのではなく、上側または中央上側にある既存の大きな地下湖の一部を「回復の聖域」にする。

### 配置方針

- 既存大湖の岸辺または湖内の円形小島へ晶泉を移動
- 湖面そのものを回復水面として利用
- 大型円形石リングは湖へ半分沈んだ構造
- 中央の浮遊晶石は湖上に浮かぶ
- 天井光が湖面へ降りる
- 左右の小晶石は岸または小島端へ配置
- 手前から短い石橋または幅96〜128pxの参道で接続
- 大きさは現在のままでも、広い湖に包まれることで自然に見える構図
- 晶泉の周囲に狭い四角い床枠を作らない

### 湖との一体感

- 円形泉の外側の水と地下湖を連続させる
- 泉だけ別の青い円盤に見せない
- 内周だけ明るい水色、外側へ既存湖色へなじませる
- 石リングの一部を欠けさせ、水没させる
- 波紋が地下湖へ広がる
- 作動時には湖面の反射も少し明るくなる

## 4. マップ配置と進行

- 晶泉は主晶石→副晶石へ向かう必須ルートから発見できる
- ただし通路中央を完全に塞がない
- 混成戦後または湖上石段前に立ち寄れる位置を維持
- 回復後に最終戦へ向かえる流れを保つ
- 晶泉へ行くために未解放の湖上石段を要求しない
- 晶泉の参道は通常床またはbridgeとして常時歩行可能
- 参道を敵homeや逃走経路にしない
- 晶泉周辺は非戦闘区域

座標は既存湖と全経路を確認して決める。既存`spring`座標へ描画だけを残さない。

## 5. 第2層晶泉の衝突と操作

- 中央晶石と内側の明るい水面は歩行不可
- 湖面全体も歩行不可
- 石リング外周または岸辺から操作
- 参道は歩行可能
- 新座標を`LIGHTWING_CRYSTAL_CAVERN.spring`の単一基準にする
- 描画、solid prop、interaction、SFX、演出、QAへ同じ座標を使用
- 操作距離は外周から届く
- 3人回復演出の立ち位置は参道または岸辺に整列
- キャラクターを湖面へ配置しない

## 6. 第2層晶泉の既存機能を維持

- idle→charging→healing→afterglow
- HP・MP全回復
- 戦闘不能解除
- 初回固定会話
- 晶泉専用SFX
- 中央浮遊晶石
- 天井光
- 三人へ伸びる回復光
- 再利用可能

移設に伴い、三人へ伸びる光の終点を新しい安全な整列位置へ変更する。

## 7. 第1層の回復の泉を完全撤去

第1層の泉は不要。見た目だけ消して操作や衝突を残さない。

撤去対象：

- `MOSS_ROOT_LANDMARKS.spring`
- `MOSS_ROOT_RUINS.spring`
- 泉用solid propが存在する場合
- `MossRootRuinsRenderer`の`drawHealingSpring()`呼び出し
- 第1層の泉interaction
- `E　泉を調べる`
- 戦闘中の`戦闘中は泉を利用できない`
- 第1層泉用QA位置／状態
- 第1層泉を前提にしたテスト
- 泉へ戻るための文章

`restorePartyAtSpring()`は第2層晶泉と混同しないよう整理する。第1層用の古い即時回復経路を削除し、第2層専用phase回復だけを維持する。

## 8. 第1層泉跡地

泉撤去後の場所を空白や不自然な台座跡にしない。

- 通常の苔むした遺跡床へ戻す
- 壊れた柱、低い根、石片など控えめな景観
- 回復地点と誤認する発光水面を残さない
- 主ルートや敵配置を大きく変えない
- 必要なら小さな休憩広場として残すが、機能は持たせない

## 9. 石碑ゲートの役割変更

現在の石碑は「根が退き、泉へ戻るための近道が開いた」と説明している。この役割を廃止する。

新しい役割：

- 石碑左側または北西側にある余白へ、将来の宝箱用の隠し小部屋を作る
- 石碑作動で、その小部屋を塞ぐ根のゲートが開く
- 現時点では宝箱取得機能を実装しない
- 小部屋内に空の石台座だけを置く
- 将来、宝箱・装備・アイテムを追加できる構成

## 10. 隠し小部屋

### 配置

- 石碑の左側を第一候補
- マップ外周、既存通路、敵広場との干渉を確認
- 幅160〜256px程度の小部屋
- 入口は根のゲートで閉鎖
- 石碑からゲートの一部または光が見える
- 小部屋奥に宝箱用台座

### 見た目

- 第1層の苔根遺跡に合う石室
- 通常通路より少し暗い
- 奥の台座へ弱いシアン光
- 宝箱そのものはまだ置かない
- `ここに何か置かれそうだ`と分かる程度
- DEV、COMING SOON等の文字を世界内に表示しない

### 衝突

- ゲート閉鎖中は通行不可
- 開放後は完全に通れる
- 台座は歩行不可
- 小部屋床は歩行可能
- 壁・void・根の見た目と衝突を一致

## 11. 石碑の会話変更

未作動時：

```text
石碑には、根に閉ざされた小部屋の紋様が刻まれている。
```

作動時：

```text
石碑の光が、左奥へ伸びる根へ流れ込んだ。
```

ゲート開放後：

```text
絡みついていた根が退き、隠された小部屋への道が開いた。
```

再度調べた時：

```text
石碑は、開かれた小部屋を静かに照らしている。
```

「泉」「近道」「戻る」という文言を使わない。

## 12. フラグの整理

既存`shortcutUnlocked`を内部的にそのまま利用してもよいが、意味が変わるため名称変更を推奨する。

例：

```ts
hiddenRoomUnlocked: boolean
```

ただし大規模なセーブ互換性は現時点で不要。次を一致させる。

- snapshot
- map collision
- renderer
- interaction dialogue
- QA dataset
- tests

古い`shortcutSpring`、`shortcutUpper`等が新しい役割で不要なら削除する。死んだ座標定義を残さない。

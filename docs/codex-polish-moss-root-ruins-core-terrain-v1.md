# Codex向け実装指示：苔根の遺構・基本地形ビジュアル改善 v1

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- `Sol` / `Ultra`：今回は不要
- 理由：マップ、衝突、進行機能は完成しており、主対象はCanvas地形Rendererの整理、隣接タイル描画、視覚QA、回帰防止であるため。

## 最初に読む資料

1. `assets/concepts/environments/moss-root-ruins/tiles/moss-root-ruins-core-terrain-design-board-v1.png`
2. `assets/concepts/environments/moss-root-ruins/moss-root-ruins-production-map-concept-v2.png`
3. `docs/design-moss-root-ruins-production-layout-v2.md`
4. 現在の`src/stage/maps/mossRootRuinsMap.ts`
5. 現在の`src/render/stages/MossRootRuinsRenderer.ts`

デザインボードは色、質感、視点、素材の基準であり、完成した32pxスプライトシートではない。画像をランタイムへ貼り付けたり、セルをそのまま切り出して使用したりしない。Canvas上の決定的なピクセル描画へ翻訳する。

## 1. 目的

現在の地形は機能的には完成しているが、32pxの大きな四角形、単純な横線、均一な壁面が目立ち、開発用表示に見える。

今回の目的：

- 苔むした石床、遺跡壁、根、水路、橋、穴を16-bit風のピクセルアートへ改善
- 歩行可能領域と障害物の境界を明確に保つ
- マップ構造、座標、敵、衝突、泉、石碑、ショートカットを変更しない
- 既存キャラクターとモンスターより背景だけが細かすぎない密度へ調整
- 全域を1枚画像で置換せず、今後の別ステージでも応用できる描画単位へ整理

## 2. 今回変更しないもの

- ワールド2048×1920
- 64×60、32pxタイル
- 全タイル配置と歩行可能性
- 必須ルートとショートカット
- カメラとデッドゾーン
- モスプルン10体と4エンカウント
- 戦闘、逃走、陣形、BGM
- 回復の泉の効果
- 石碑と進行フラグ
- 第2層への門の条件
- HUDと操作方法
- アリーナモード

描画改善のために`MossRootTile`や衝突グリッドを書き換えない。

## 3. ピクセル描画ルール

- Canvasの`imageSmoothingEnabled`を無効のまま維持
- 1pxまたは2px単位を基本とし、滑らかなベクター風グラデーションを避ける
- 色数を絞り、明暗は段階色で表現
- 半透明は水面、発光、前景霧など必要な箇所だけ
- 線を毎フレームランダム生成せず、`hash2d(column, row, variant)`相当の固定値を使用
- タイルの継ぎ目が格子状に見えないよう、模様を隣接タイル境界へまたがらせる
- ただし衝突境界は輪郭で明確にする
- 時間アニメーションと静的模様を分離する

## 5. Rendererの構成

`MossRootRuinsRenderer.ts`が肥大化しすぎる場合は、同じ`src/render/stages/`配下に描画補助を分割する。

推奨関数：

```ts
drawFloorTile(context, column, row, neighbors)
drawWallTile(context, column, row, neighbors)
drawRootTile(context, column, row, neighbors)
drawWaterTile(context, column, row, neighbors, time)
drawBridgeTile(context, column, row, neighbors)
drawVoidTile(context, column, row, neighbors)
drawGateTile(context, column, row, state)
drawFloorDetails(context, column, row, variant)
```

隣接情報は上下左右と必要なら斜め4方向。毎タイルごとに不要な配列生成を行わない。

## 6. 石床

デザインボード左上を基準にする。

- 単色32px四角形を廃止
- 1タイル内に2〜5枚程度の不規則な石板
- 石板は全タイルで同じ形にしない
- 目地は暗緑、石の上面は灰緑〜オリーブ
- ひび割れは一部だけ
- 苔の割合を3〜4段階の固定バリエーションにする
- 戦闘広場は中央ほど苔を減らし、円形の石組みを読みやすくする
- 通路端は苔を増やし、中央の進行方向を自然に示す

現在の`drawPlazaRing()`による点線の円はデバッグ表示に見えるため、本番描画では廃止する。代わりに短い石の弧、同心円状の目地、欠けた環状石板で広場を表現する。

## 7. 遺跡壁と崖

デザインボード上中央を基準にする。

歩行床に隣接する壁だけを、隣接方向に応じて描き分ける。

- 床側に明るい上面の縁石
- その外側に8〜14px程度の暗い垂直面
- 垂直面へ2〜3段の石積み
- 柱頭または崩れ石を一定間隔で配置
- 壁の外側は深い暗闇へ落とす
- 全タイルへ同じ横線を引かない
- 内角、外角、直線、孤立壁を隣接マスクで区別
- 壁上の苔と小さな晶石は低頻度

壁の輪郭は歩行可能境界と一致させ、見た目上歩けそうなのに衝突する場所を作らない。

## 8. 巨大な根

デザインボード右上を基準にする。

- 茶色の太い主根と、細い枝根を2〜4本組み合わせる
- 根は直線ではなく、段階的な折れと幅変化で有機的にする
- 根元に暗い接地影
- 上面へ1〜2pxの明色
- 苔は根の上部または隙間へ限定
- 隣接する根タイル同士をつなぎ、タイルごとに途切れない
- ショートカット閉鎖中は複数の根が絡み合った明確な障害物
- 開放後は根が左右へ退き、通路中央が見える

Canvasの滑らかな太いBezier線だけで済ませず、ピクセル段差と複数色で立体感を出す。

## 9. 水路

デザインボード中段左を基準にする。

- 深部は暗い青緑
- 岸に近い部分だけ少し明るくする
- 1〜2pxの短い水平ハイライトを固定配置
- 水面アニメーションは2〜4パターン程度を時間で切り替える
- 毎フレーム連続的に線が滑らない、レトロゲームらしい段階アニメーション
- 波線の密度を抑え、床より暗くする
- 床との境界に石の岸、影、少量の苔を描く

水タイルの中央だけを塗るのではなく、床・壁との隣接関係で岸辺を描く。

## 10. 石橋

デザインボード中央を基準にする。

- 3タイル以上の幅が視覚的にも伝わる
- 橋面は長方形の石板を互い違いに配置
- 外周に低い縁石
- 橋の下へ暗い水と接地影
- 入口が床へ自然につながる
- 橋の模様と移動方向を一致させる
- 橋上へ大きな柱や瓦礫を置かない

`bridge`は従来どおり歩行可能。見た目変更で衝突を狭めない。

## 11. 深い穴とvoid

デザインボード中段右を基準にする。

- 画面外の完全な黒と、地形内部の穴を区別
- 穴の中央は`voidDeep`
- 縁に崩れた石、垂直面、垂れる根
- 穴へ近づくほど床が暗くなる1段階の影
- 穴の中へ低頻度で青緑の点光または遠い晶石影を置いてよい
- 地形内部の穴が単なる黒い四角に見えない

画面外の大部分は暗く保ち、装飾を敷き詰めない。

## 12. 柱、瓦礫、苔、床装飾

デザインボード下段左・右を基準にする。

- 柱は通路端または壁上へ配置
- 高い柱は前景レイヤーも使い、キャラクターが裏へ入る感覚を作る
- 瓦礫は歩行可能な中央を塞がない
- 苔、草、小石、ひび、青い胞子を固定バリエーションで配置
- 1画面に同じ装飾を繰り返しすぎない
- 戦闘広場中央は攻撃エフェクトを見やすくするため装飾密度を下げる
- 通路端、行き止まり、壁際は密度を上げる

## 13. 晶石

デザインボード下段中央を基準にする。

- 現在の単純な菱形を、主結晶1本＋小結晶2〜4本のクラスターへ改善
- 暗い青緑、明るいシアン、白に近いハイライトの3段階
- 根元に小さな接地影
- 発光は狭い範囲へ限定
- 転送晶石は他より大きく、床の環状紋様と組み合わせる
- 小晶石は壁際や水辺へ配置
- すべて同じ大きさ、同じ向きにしない

回復の泉、石碑、第2層門などのランドマーク描画は今回は大きく作り直さず、基本地形との色とピクセル密度だけ整合させる。個別の本番デザインは次段階で扱う。

## 14. 前景

現在の均一な小さな十字形植物だけではなく、次を低頻度で追加する。

- 壁上から垂れる根
- 柱上部
- 大きめの葉
- 画面端の暗い前景シルエット
- ごく少量の光る胞子

キャラクターの顔、HP表示、敵HP、攻撃予告を覆いすぎない。前景の不透明度は控えめにし、戦闘広場中央ではほぼ表示しない。

## 15. 描画優先順位

```text
暗いvoid背景
→ 水・穴の深部
→ 床と橋
→ 壁上面・岸・根の接地部
→ 静的装飾とランドマーク下部
→ キャラクター・敵・攻撃エフェクト
→ 柱上部・垂れ根・胞子などの前景
```

現在のRenderer全体のレイヤー順を確認し、キャラクターが壁の下へ消えたり、晶石の後ろへ不自然に隠れたりしないこと。

## 16. パフォーマンス

- 現在のカメラ内タイルだけを描くカリングを維持
- 1フレームあたりの可視タイル範囲で処理を完結
- 静的な複雑形状は必要なら`Path2D`、小規模キャッシュ、または事前計算したバリエーションを使用
- 2048×1920全体を毎フレーム描き直す巨大オフスクリーン処理を追加しない
- DOM要素を地形タイルごとに作成しない
- ゲームループ内で画像生成、文字列解析、大量配列生成を行わない

水面と発光以外の静的模様は時刻に依存させない。

## 17. 自動テスト

描画変更でゲームロジックを変えないことを重視する。

- 既存stageテストをすべて維持
- タイル種別と歩行可能性が変更されていない
- 敵10体の位置が変更されていない
- 泉、石碑、ショートカット、門が動作する
- 逃走と再戦が動作する
- アリーナモードが動作する
- Rendererが全タイル種別で例外を出さない
- カメラ端で範囲外アクセスしない
- 決定的描画用のvariant関数が同じ座標で同じ結果を返す

可能であれば、各タイル種別を含むQA位置で1フレーム描画するスモークテストを追加する。

## 18. 視覚QA

最低限、次の地点を820×600程度で撮影し、デザインボードと比較する。

1. 転送広場：石床、環状模様、転送晶石
2. 左下初戦広場：戦闘中でも床と敵が判別できる
3. 水路遺構：水、岸、橋の違いが明確
4. 中央巨大根：直進不能が見た目でも分かる
5. 右側戦闘広場：柱・瓦礫が戦闘を邪魔しない
6. 回復の泉周辺：水と通常水路を区別できる
7. 根迷路：通路と根の境界が明確
8. ショートカット：閉鎖中と開放後
9. 最終広場：床紋様、壁、門がまとまって見える

特に確認する問題：

- 32pxの四角いタイル境界が全面に見える
- 壁が同じ横線のコピーに見える
- 地形がキャラクターより明るい
- 苔や瓦礫で移動可能範囲が分からない
- 水と穴が同じ黒に見える
- 点線の広場リングが残っている
- 前景が戦闘を隠す

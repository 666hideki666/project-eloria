# Codex向け修正指示：戦闘封鎖の撤廃と逃走・戦闘離脱

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- `Sol` / `Ultra`：今回は不要
- 理由：既存のエンカウント状態遷移、敵AI、陣形、BGMを連動させる中規模修正だが、マップ全体の再設計ではないため。

## 背景

第1層「苔根の遺構」では、戦闘開始時に各戦闘広場の入口へ封鎖バリアを出している。

現在の問題：

- 通路上で戦闘が始まると、3人陣形への展開位置と封鎖が重なる
- 仲間が封鎖の反対側へ押し出される、または封鎖に挟まれる
- プレイヤー自身が動けなくなる場合がある
- 広い探索ステージなのに、戦闘ごとに強制的に閉じ込められる

ユーザーの希望は、封鎖を完全に廃止し、元の道へ戻って敵から十分な距離を取れば戦闘から逃走できる形式である。

## 1. 戦闘用封鎖を完全撤廃

`MOSS_ROOT_ENCOUNTERS`の戦闘用`barriers`を削除する。少なくともゲームプレイ、衝突、描画、QAから一切使用しない。

- 戦闘開始時に通路を閉じない
- 戦闘中もすべての接続通路を自由に通れる
- 封鎖の矩形を衝突判定へ渡さない
- `MossRootRuinsRenderer`で封鎖を描画しない
- 旧封鎖を前提にしたテストを削除または新仕様へ置換する

注意：メルの防御魔法など、キャラクター能力としての`barrier`状態・エフェクトは別機能である。こちらは削除しない。削除対象はステージの入口封鎖だけ。

## 2. 戦闘離脱の基本仕様

戦闘中、操作キャラクターが現在の戦闘グループに属する生存敵すべてから十分離れた状態を一定時間維持したら逃走成功とする。

初期推奨値：

```ts
const ENCOUNTER_DISENGAGE_DISTANCE = 300;
const ENCOUNTER_DISENGAGE_HOLD = 0.7;
const ENCOUNTER_REENGAGE_COOLDOWN = 1.5;
```

判定条件：

- `stageEncounter === "active"`
- 現在の`activeEncounterGroupId`が存在する
- 操作キャラクターと、そのグループの生存敵それぞれの距離がすべて300px以上
- 上記状態が連続0.7秒続く

1体でも300px未満へ戻ったら離脱タイマーを0へ戻す。1フレームだけ境界を越えて戦闘と探索が切り替わらないようにする。

距離はまず300pxで実装し、実プレイで逃げにくい場合のみ260〜280pxへ調整してよい。敵が操作キャラクターと同速以上で永遠に追いつく場合は、逃走開始後の追跡速度または敵のホーム位置からの追跡上限も調整し、実際に逃走可能にする。

## 3. 逃走成功時の状態遷移

逃走が成立したら、1回の処理で次を行う。

1. `stageEncounter`を`dormant`へ戻す
2. 対象グループの`encounterStates[groupId]`を`dormant`へ戻す
3. `activeEncounterGroupId`を`null`へ戻す
4. 3人陣形を解除して、操作キャラクター1人だけの探索表示へ戻す
5. 仲間2人は画面上から安全に収納し、衝突判定へ残さない
6. 敵の攻撃トークン、攻撃予告、攻撃状態、注目状態を解除する
7. 敵AIをホーム位置へ戻し、初期の待機状態へ戻す
8. バトルBGMから探索BGMへ自然に切り替える
9. HUDの戦闘中表示を探索表示へ戻す
10. 「戦闘から離脱した」程度の短いバナーを表示する

`endStageCombat()`で既に共通処理できる項目は再利用する。ただし「敵全滅による勝利」と「逃走」を同じクリア処理にはしない。

## 4. 逃走後の敵グループ

逃走した戦闘は未攻略扱いにする。

- グループを`cleared`にしない
- 経験値や撃破報酬を追加で与えない
- 敵は定義済みの初期配置へ戻す
- グループ全員を生存状態・初期HPへ戻す
- 攻撃途中のタイマー、ノックバック、状態異常、攻撃権を初期化する

途中まで敵を倒してから逃げる行為で攻略を分割できないよう、グループ単位で初期状態へ戻す。すでに倒した際に付与済みの経験値を二重取得できる構造がある場合は、逃走時復活した敵から経験値を再取得できない対策を入れるか、グループクリア時にまとめて経験値を付与する。既存の経験値仕様を調査し、重複稼ぎを発生させない。

## 5. 即再戦とBGMの往復を防ぐ

逃走直後、敵が初期位置へ戻った瞬間に同じグループを再発見しないようにする。

- 逃走後1.5秒はそのグループの発見判定を無効化
- 可能なら時間だけでなく、一度発見範囲の外へ出たことを再戦条件にする
- 再び敵へ近づいた時は通常どおり戦闘開始できる
- クールダウン中は敵を待機または帰還状態にし、遠距離攻撃を行わせない
- クールダウン中に別グループへ接近した場合の扱いは、現在の単一アクティブグループ仕様を維持しつつ破綻させない

探索BGMとバトルBGMが距離境界で細かく往復しないことを確認する。

## 6. 敵の帰還

敵ごとにエンカウント定義の初期座標をホーム位置として扱う。

- 逃走成立までは通常戦闘AIで追跡する
- 逃走成立後は攻撃せずホーム位置へ復帰、または即時復帰させる
- カメラ内で瞬間移動が目立つ場合は短い消失・再出現、または高速帰還を使う
- ただし帰還演出のために探索復帰を待たせない
- ホームへ戻る途中の敵がプレイヤーへ再攻撃しない

最初は安全性を優先し、カメラ外なら即時復帰、カメラ内なら短いフェードまたは帰還状態とする実装でよい。

## 7. 陣形展開の安全性

封鎖撤廃後も、戦闘開始時の3人展開位置は必ず歩行可能範囲へ補正する。

- 壁・穴・根・閉鎖中の常設ゲートへ仲間を置かない
- 細い通路で開始した場合、操作キャラクターの近くに置ける安全地点を探索する
- 安全地点が2つ見つからない場合は重ならない最小間隔で順次配置する
- 戦闘終了・逃走時に仲間が地形へ引っかかった状態を残さない

これは封鎖がなくても必要な回帰防止として維持する。

## 8. 維持する仕様

- 敵を全滅させた場合は従来どおり`cleared`
- 必須グループを全滅させる進行条件
- 任意戦を避けられるルート
- モスプルンのAI、攻撃モーション、効果音
- 戦闘中の3人陣形とキャラクター交代
- 探索中の1人表示
- 探索BGMと戦闘BGM
- カメラ、タイル衝突、ポーズ、HUD
- `?mode=arena`の既存挙動

アリーナモードは独立した戦闘確認用なので、今回の距離逃走を強制的に適用しない。

## 9. テスト

旧テスト：

```text
places every QA battle formation inside its arena while barriers close only entrances
```

は、封鎖を前提としない内容へ置換する。

最低限追加・更新するテスト：

1. 4グループすべてに戦闘用封鎖が存在しない
2. 戦闘中でも各広場の入口座標を通過できる
3. 戦闘開始時の3人全員が歩行可能位置にいる
4. 敵との距離が300px未満なら離脱しない
5. 300px以上でも0.7秒未満なら離脱しない
6. 300px以上を0.7秒維持すると探索状態へ戻る
7. 逃走時にパーティーが1人表示へ戻る
8. 逃走時に対象敵が初期位置・初期HP・待機状態へ戻る
9. 逃走したグループは`cleared`にならない
10. 逃走直後1.5秒以内に同じ戦闘が再発しない
11. 再接近すれば再戦できる
12. 敵全滅時の通常クリアは従来どおり動く
13. 他のエンカウント状態を壊さない
14. アリーナモードへ距離逃走が適用されない
15. 探索BGM・戦闘BGMの状態判定が逃走時に正しく戻る

## 10. 視覚QA

- 初戦広場の南通路付近で戦闘を開始し、封鎖が出ない
- 細い通路付近で3人展開しても誰も壁や旧封鎖へ挟まれない
- 元の道を戻って敵から離れる
- 離脱後、操作キャラクター1人表示になる
- 探索BGMへ戻る
- 敵へ再接近すると再び3人展開し、戦闘BGMへ切り替わる
- 左行き止まり、右ループ、最終広場でも同じ挙動を確認する

QA用のクエリまたはデバッグ表示で離脱距離を再現できるようにし、少なくとも開始直後・逃走成立後・再戦後のスクリーンショットを保存する。

## 11. 完了条件

- ステージ戦闘用の通路封鎖が完全に消えている
- 戦闘開始時に封鎖へ挟まれて動けなくなるバグがない
- プレイヤーが元の道へ戻って敵から離れれば実際に逃走できる
- 逃走時に3人陣形から探索1人表示へ戻る
- 逃走時に探索BGMへ戻る
- 敵へ再接近すれば正常に再戦できる
- 逃走と再戦で経験値の重複取得が発生しない
- 既存の全滅クリア、進行条件、アリーナモードを壊さない
- `npm test`と`npm run build`が成功する

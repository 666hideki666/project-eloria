## タイトル画面

採用済み見本に沿って、全画面背景、別レイヤーのロゴ、START、全画面ボタン、開発時のみ右下の小さな DEV WARP を実装する。ロゴと３人が横スマホ・iPadで隠れないよう安全領域と画面比率に対応し、全画面化は必ずユーザー操作から行う。通常開始前はゲーム操作・HUD・旧 INTRO 説明カードを見せない。キーボード、タップ、マウスと明瞭なフォーカス表示に対応する。`mode=arena`、QA直行URL、自動開始QA、開発層選択の既存導線は維持し、製品ビルドに DEV WARP を出さない。

## 序章の画面・操作

1. START は１回だけ受け付け、タイトルUIを閉じて序章演出に移る。３枚を16:9の原画として使用し、横スマホとiPadでは重要な人物・井戸を切らない `cover`／配置の調整を行う。画像ロード中の黒い点滅を避け、ロード失敗時でも古の森へ進める。
2. 静止画への緩やかなパン／ズーム、晶光の淡い脈動、葉・霧のごく控えめな動き、クロスフェードで動画らしい質感を作る。人物を無理に変形・口パクさせない。カットの切り替わりと話者が分かることを優先する。動き軽減設定では移動アニメーションを省く。
3. 各場面の仮台詞は絵コンテ記載の候補を基に、名前付き会話と地の文をタイプライター風に表示する。画像自体に文字を焼き込まない。小さい画面でも読みやすく、字幕帯は重要な顔・地図・晶石を隠さない。読み上げ補助では文字が１字ごとに再通知されないようにする。
4. タップ／クリック／決定キーは、表示途中ならその行を即座に全文表示、全文表示後なら次の行または次場面へ進む。二重入力による複数場面飛びを防ぐ。常設のスキップ操作では序章を丸ごと飛ばし、古の森へ１回だけ着地する。序章中は移動・攻撃・交代入力をゲームへ通さない。
5. 最終場面から短く暗転し、既存の古の森スポーン・入場タイトル・BGMへ移る。古の森の村道制限、洞窟接続、全層の進行状態・当たり判定は変更しない。タイトルに戻る／再開始時は序章状態を初期化する。

## 音声

START前にブラウザの音声制約を回避する自動再生を行わない。追加の新曲は今回作らず、導入は控えめな既存の古の森BGMまたは無音＋環境演出で成立するようにする。序章の終了・スキップ・タブ非表示・破棄で音源が残らず、古の森に入る時に二重再生しない。最終的な音量・切り替えの聴感は実機で確認する。

## 実装・検証結果（2026-10-18）

- `src/ui/OpeningController.ts`、`openingSequence.ts`、`opening.css` を追加。採用背景・透過v4ロゴを別レイヤーで使用し、通常起動にタイトル→START→３場面７行→暗転→古の森の既存スポーンと入場タイトルを接続。ブラウザタブ名も `ELORIA` に統一した。採用画像は加工・差し替えしていない。
- 字幕は１回の入力で全文表示、次の入力で次の行へ進む。クリック・タップ・Enter/E/Space、連打抑制、押しっぱなしのゲーム入力遮断、序章全体のスキップ、タイトルへの戻りと再開始を実装。場面ごとの読み上げ用全文を別要素へ置き、１文字ずつ読み上げ通知しない構成にした。
- ゆっくりしたパン・ズーム、クロスフェード、淡い光・霧、森への短い暗転と解除を実装。動き軽減時はパン・ズームとタイプ表示を省く。画像は先読みし、次の画像が読み込まれるまでは既存画像を保つ。３枚がすべて読み込み失敗しても字幕とスキップで進める。
- タイトル・序章は無音。ワールドを `intro` のまま停止し、HUDと旧説明カードを隠し、完了時のみ既存の `confirm()` で開始する。古の森に着地してから既存の単一BGMプレーヤーで「星巡る古の森」を再生する。新しい音源・プレーヤー・プレイ可能な村マップは追加していない。
- DEV WARPは開発時だけ生成し、既存の層選択をボタンから開く形へ変更。全５エリアの選択とキャンセル、QA直行URL、自動開始QA、arenaの旧導線を確認。製品版ではDEVボタン・選択パネルが存在しない。
- `npm run typecheck`、`npm test -- --reporter=dot`（17ファイル・350件）、`npm run build` が通過。新規５テストで場面・台詞順、全文表示、連続入力、スキップの一度だけの完了、再開始、動き軽減、起動経路の分岐を確認。
- ミュートした検証用Chromeで、通常の全台詞進行とスキップ、タイトル前と序章中のワールド時間・位置・技ゲージ停止、森到着とBGM、歩行・交代入力の遮断、Key Mのミュート、タイトルへ戻ってのリセットを確認。非表示は `document.hidden` / `visibilityState` と `visibilitychange` を模擬し、文字とCSSアニメーションが停止して復帰することを確認した。
- PC 1600×900、横スマホ844×390、iPad相当1024×768で画像と字幕を目視確認。横スマホのタップ開始、キー操作とフォーカス、実Fullscreen APIでの入・退出、API拒否・非対応を模擬した際の通常表示継続、動き軽減時の即時全文表示と短いフェードを確認。
- 製品ビルドをクエリーなしで開始し、タイトル→３場面→古の森を実操作で確認。製品版スキップと二重スキップ、森へのフェード解除も通常・動き軽減の両方で通過。開始後も村道制限、森→第１層→森の実移動、既存BGM切替を確認した。記録は `docs/screenshots/eloria-opening-*-v1.png`。

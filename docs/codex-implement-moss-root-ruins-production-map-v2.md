# Codex向け実装指示：第1層「苔根の遺構」本番マップ v2

## 実行設定

- 推奨モデル：`GPT-5.6 Sol`
- 推論レベル：`High`
- `Ultra`：不要
- 理由：マップ全体の再構成に加え、カメラ、衝突、敵グループ、逃走、進行フラグ、回復の泉、ショートカット、描画、QAを同時に整合させる必要があるため。

1. `docs/design-moss-root-ruins-production-layout-v2.md`
2. `docs/codex-revise-layer1-scale-to-reference.md`

v2画像は世界観、地形密度、左右へ広がる構造の基準である。画像を背景1枚として貼らず、既存のタイル、ランドマーク描画、衝突、エンカウントへ再構成する。

## 1. 目的

現在の1536×1504の縦長マップを、左右へ大きく広がる本番用第1層へ置き換える。

必須条件：

- 開始地点からゴールまで直線または中央の一本道で到達できない
- 左右を複数回横断する
- ゴールまでの必須歩行距離を現在実装のおよそ2倍にする
- 1画面に見える主要広場は原則1つ
- 初戦、任意戦、必須戦、回復、根迷路、最終戦の緩急を作る
- 戦闘封鎖を復活させない
- 敵から離れて逃走できる現仕様を維持する

## 2. ワールド定義

- ビューポート：640×360を維持
- タイル：32pxを維持
- ワールド：2048×1920
- グリッド：64列×60行
- カメラ範囲：`x=0..1408`、`y=0..1560`
- カメラ範囲はワールド定数から算出し、数値を重複ハードコードしない

`ScrollingStageDefinition`がステージごとに幅、高さ、開始地点、ゴール、カメラ範囲を持つ現在の構造を維持する。今回の寸法や進行方向を共通カメラコードへ固定しない。

## 4. 必須ルート

次の順序を地形と常設障害で保証する。

```text
A 転送広場
→ 西へ迂回
→ B 左下初戦
→ C 左側水路遺構
→ D 中央左晶石分岐
→ F 中央横断路
→ G 右側必須戦
→ H 回復の泉
→ I 右上石碑区画
→ 上部を西へ横断
→ J 左上根迷路
→ 東へ折り返す
→ L 最終戦
→ M 第2層への門
```

禁止事項：

- AからL/Mへ向かう中央縦通路
- DからLへ直接北上できる通路
- GからLへ短い直線で到達する通路
- 開始画面から中央分岐や最終門が見える構図
- 広い長方形床を複数つなげただけの地形

中央は巨大な根、水路、穴、崩落壁で分断する。初回は外周に近い蛇行ルートを進ませる。

## 5. タイル生成

既存の`carveEllipse()`と`carvePath()`を再利用・拡張する。

推奨：

```ts
carveEllipse(centerColumn, centerRow, radiusColumns, radiusRows)
carvePath(points, widthInTiles)
carveWater(...)
carveBridge(...)
placeRootMass(...)
```

必要ならタイル種別を追加する。

```ts
type MossRootTile =
  | "floor"
  | "wall"
  | "root"
  | "water"
  | "bridge"
  | "void"
  | "gate"
  | "shortcutGate";
```

- `floor`と`bridge`は歩行可能
- `water`、`wall`、`root`、`void`は歩行不可
- `gate`は開始晶石の進行フラグで開く
- `shortcutGate`は石碑または反対側操作で開く
- 戦闘中だけ現れるタイル・封鎖は作らない

通路幅：

- 通常通路：96〜128px
- 戦闘広場の入口：128px以上
- 橋：96px以上。ただし橋上に敵発見範囲を置かない
- 根迷路の最小幅：96px

## 6. 開始晶石と最初の根の門

既存の`northGateUnlocked`相当の開始進行を維持するが、今回は「北の門」ではなく転送広場の西寄り出口を開く。

- E/Enterで転送晶石を調べる
- 根がほどけて西側通路が開く
- ゲート開放演出、効果音、短いバナーを維持
- 位置依存の`isNearTransferNorthGate()`等は名称または実装を一般化する
- 古い座標を残して判定が誤作動しないようにする

## 8. 回復の泉

H `(1840, 1180)`へ実装する。

### 利用条件

- ステージ探索中
- `stageEncounter !== "active"`かつ`noticed`でもない
- 操作キャラクターが泉中心から48px以内
- EまたはEnterで使用

### 効果

- カイル、ナディ、メル全員のHPを最大まで回復
- メルのMPを最大まで回復
- 戦闘不能メンバーを復帰させ、HPを最大まで回復
- 一時状態、被弾無敵、攻撃状態を安全に解除
- 経験値や進行状態には影響しない

### 演出

- 青緑の水面を2〜3層の楕円と波紋で描画
- 晶石の光を弱く明滅
- 既存素材を利用できる場合は回復系SFXを再利用
- パーティー周囲に短い回復粒子
- バナー：「泉の力で体力が回復した」
- 探索BGMは継続

初期版は無制限に再利用可能でよい。連打してもSFXとバナーが重なり続けないよう0.8〜1.0秒の操作クールダウンを設ける。

HUDまたは近接プロンプトで`E 調べる`を表示できる場合は表示する。新しい大規模UIは作らない。

## 9. 石碑とショートカット

I `(1710, 420)`の石碑をE/Enterで調べると、K-K2間の根が開く。

状態：

```ts
shortcutUnlocked: boolean
```

- 初期値`false`
- 一度開いたら、そのプレイ中は開いたまま
- 開放前は`shortcutGate`が衝突する
- 開放後は通行可能
- 根が左右へほどける短い演出と効果音
- バナー：「遠くで根がほどける音がした」
- 戦闘中は石碑を操作できない

ショートカットは初回必須ルートを省略させない位置へ置く。Iへ到達して操作した後、回復の泉と最終広場周辺の往復を短縮する。

`WorldSnapshot`へ描画に必要な状態だけ公開し、UIやRendererから`GameWorld`内部状態へ直接依存させない。

## 10. 将来の宝箱台座

宝箱システムは今回実装しない。

- Eの奥に空の石台座を描画
- Jの短い行き止まりにも小さな設置余地を残す
- 衝突は石台座の見た目と一致させる
- 調べる処理を入れる場合は「古い台座だ。」程度に留める
- アイテム、所持品、保存機能を追加しない

## 11. 描画

コンセプト画像の情報量を一度に完全再現する必要はないが、現行の単純な床矩形から明確に改善する。

### 地域ごとの見分け

- A：大きな転送晶石、放射状床
- B：低い根と苔、広い戦闘床
- C：水路、石橋、崩れた柱
- D：小型晶石、三方向の床紋様
- E：暗い小部屋、石台座
- F：巨大な根塊と滝
- G：崩れた列柱、広い円形床
- H：明るい回復水面
- I：古代石碑と高い柱
- J：密集した太い根、暗い緑
- L：門へ続く古代紋様、背の高い柱

### 実装方法

- カメラ内だけ描画する現在のカリングを維持
- `hash2d()`による固定装飾を維持
- 同一フレームでランダムにちらつく装飾を作らない
- タイル境界を苔、ひび、根、縁石で弱める
- 歩行床と非歩行領域は輪郭でも判別できる
- 背景と前景を分け、キャラクターが高い根や柱の手前・奥を通る感覚を作る

コンセプト画像そのものをランタイムへ読み込む実装は禁止する。

## 14. 自動テスト

最低限確認する。

1. ワールドが2048×1920、64×60タイル
2. 全ランドマークが歩行可能位置または意図した操作物位置にある
3. AからMまで必須ルートが到達可能
4. AからL/Mへの中央直通ルートが存在しない
5. Eの任意行き止まりを通らずクリア可能
6. Iへ到達前はショートカットを通れない
7. 開放後はK-K2を通行できる
8. 回復の泉で全員のHP、MP、戦闘不能が回復
9. 戦闘中は泉と石碑を使用できない
10. モスプルン10体がすべて歩行可能位置にいる
11. 3・2・2・3のグループ構成を維持
12. 戦闘封鎖が存在しない
13. 逃走、再戦、経験値重複防止が維持される
14. 最終3体撃破で第2層の門が開く
15. カメラが全四辺で範囲外へ出ない
16. アリーナモードの回帰がない

必須歩行距離はタイル経路探索で測定できる場合、A付近からL入口までの最短経路が現行1536×1504版のおよそ1.7〜2.2倍になることを確認する。単なるワールド直線距離ではなく歩行可能タイル上の経路長で評価する。

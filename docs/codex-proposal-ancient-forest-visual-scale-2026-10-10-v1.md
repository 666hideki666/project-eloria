# 古の森：背景とキャラクターの縮尺合わせ（実装指示案 v1）

状態：**ユーザー承認済み・実装と技術検証済み**（2026-10-10「実装に移って！」）。2026-10-10の実画面スクリーンショットでは、カイルと比べて花・草・石畳・遺構の模様が大きすぎた。前回承認済みの森歩行・第１層接続実装を保持し、この縮尺変更を `コード実装 | エロリア2` で行った。型検査・全342テスト・ビルドとブラウザ経路確認は通過。旧縮尺と新縮尺の比較画像は `docs/screenshots/ancient-forest-browser-*-v1.png` と `docs/screenshots/ancient-forest-browser-*-scale-v2.png`。新縮尺についてユーザーの実画面での最終評価は未確認。推奨モデルは **Sol High**。

## 原因と提案する大きさ

- 元の森背景とユーザー赤線はどちらも **1536×1024 px**。現在の `src/stage/maps/ancientForestMap.ts` は背景を **2304×1536 ワールド単位（原画の1.5倍）** に表示している。キャラクターの描画サイズはこの背景拡大に追随しないため、花や敷石が相対的に巨大に見える。
- **提案：背景だけを現表示の50%に縮める。** ワールド寸法を **1152×768**（原画の0.75倍）にし、カイル・ナディ・メルの描画サイズは維持する。花・敷石は画面上で現在の半分程度の大きさになる。古の森は短い導入マップなので、全体の移動距離も短くなる。
- この50%は最初の調整値。実画面でキャラクターと草花・道幅を比較し、なお不自然ならユーザー確認のうえ再調整する。赤線や背景絵を描き直す提案ではない。

## 実装対象（承認後）

1. `ANCIENT_FOREST_BACKDROP_TRANSFORM`、マップの `width` / `height`、`columns` / `rows`、カメラ範囲を同じ **1152×768** の座標系に揃える。`tileSize` を32のまま使うなら36列×24行。背景の縦横比と位置は変えない。画面全体のCSSズームやキャラクターの拡大では代用しない。
2. 背景・マスクの**原画像座標1536×1024は変更しない**。元のユーザー赤線 `docs/references/star-circling-forest-intro-walk-boundary-red-v1.png` と歩行マスクを再解釈・膨張させない。`ancientForestSourceToWorld` / `ancientForestWorldToSource` を新しいワールド寸法と対で更新し、背景上の足元位置と判定画素を一致させる。
3. スポーン、洞窟入口、村出口制御線、カメラ、復帰・QA初期位置、洞窟の横幅など、森のワールド座標に依存する値を点検する。原画像基準の入口の実寸を維持するなら、現在の `caveEntryHalfWidth: 42` ワールド単位は **21** ワールド単位に相当する。他に座標依存の固定距離があれば同じ原則で見直す。既存の第１層以降の座標や描画倍率は変えない。
4. 衝突は従来どおり足元一点と移動線分全体を原画像マスク上で検査する。背景が小さくなり道が相対的に細く見えるので、見た目だけを理由に歩行境界を広げない。現在のキャラクター移動速度はまず維持し、速すぎると実画面で分かった場合のみ別途相談する。
5. 原寸背景ファイルを差し替えたり、低解像度の画像に書き出したりしない。縮小描画で草花や石畳がぼやける・ちらつく場合は描画方式を比較し、元のピクセルアートの印象を損なわない設定を選ぶ。

## 合格条件

- 森の実画面で、カイルと花・石・石畳の大きさが自然で、背景だけが現状の約半分になっている。３人のスプライトや第１層以降の見た目は変わらない。
- 背景と赤線マスクにズレがなく、下側スポーン→中央→左右の枝道→洞窟を実際に移動できる。洞窟から第１層へ遷移でき、村道は物語の案内で止まり、赤線外・森外・中央の物体島へ抜けない。狭い道、斜め移動、追従・ワープも確認する。
- 画質が悪化していないことを実画面の比較画像で確認する。型検査・テスト・ビルドを通し、テスト用ブラウザ・サーバー・BGMを作業後に止める。

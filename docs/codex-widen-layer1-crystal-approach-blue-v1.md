ユーザーの意図は、この箇所の旧赤線の下側境界を青線側へ移し、赤線と青線の間の橋面を歩けるようにすること。橋の上側や他の通路・広場・崖には手を入れない。

## 実装要件

1. 青線の位置を画像上で再確認し、対応する旧赤線の**下側境界の短い区間のみ**青線へ移す。両端は元の境界へ自然につなぐ。青を追加の独立した柵として抽出するだけでは目的を満たさない。既存マスクの一律膨張、通路全体の拡幅、背景画像の変更はしない。
2. 元の赤線と、青線に基づく局所修正版の参照画像を区別して保存する。生成スクリプトとバイナリ歩行マスク、RLEデータ、必要経路などに整合を持たせる。新旧マスクの差分がこの短い橋の周辺に限定されることを機械的に確認する。
3. 変更後の歩行可能領域を背景へ重ねた画像と、該当橋の拡大図を残す。青線そのものと、そのすぐ外側の崖・滝側は歩行不可のままにする。クリスタル側の広場まで途切れずつながること。
4. `src/stage/tileCollision.ts` の足元接地点一点判定と移動線分の検査は維持する。今回直したいのは**静的マスクの形だけ**であり、キャラクターの当たり半径を広げたり、赤枠外へ通す例外を作ったりしない。
5. 右広場クリスタルによる北側の根の解除は別の動的仕掛けとして維持し、この橋の修正で開閉判定を壊さない。

## 確認項目

- 修正前に歩けなかった橋の下寄りを、足元の接地点で自然に歩ける。橋の左端からクリスタル広場まで実際の移動処理で到達し、クリスタルに触れられる。
- 青線の外側へ足元を出そうとすると止まり、細い遮断帯を高速移動・斜め移動で飛び越えられない。
- 新旧マスク差分は指定箇所周辺に限定され、他の通路・広場・根の障害領域・北側出口の動作に回帰がない。
- `npm run typecheck`、`npm test`、`npm run build` が通る。ブラウザで通常歩行を確認し、実際に通れた範囲と未確認箇所を報告する。

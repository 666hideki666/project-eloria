# Codex向け追加指示：モスプルンの待機・ホップ移動スプライトを導入

Project Eloriaの現在の簡易図形で描画されているモスプルンを、正式な4方向ピクセルアートへ置き換えてください。

今回は待機と移動だけを正式スプライト化します。攻撃・被弾・撃破の専用シートは次の作業で追加するため、現在の攻撃予兆、攻撃判定、被弾発光、ノックバック、撃破エフェクトは維持してください。

モスプルン以外の敵、敵AI、戦闘数値、出現数、パーティー側の機能は変更しないでください。

## 使用素材

- 画像：`assets/sprites/enemies/moss-plun/moss-plun-idle-hop-48px-v1.png`
- 設定：`assets/sprites/enemies/moss-plun/moss-plun-idle-hop-48px-v1.json`

画像仕様：

- 全体：288×192px
- 1コマ：48×48px
- 6列×4行
- 透過PNG
- 推奨描画倍率：0.8
- 足元アンカー：`x: 0.5`, `y: 0.92`

方向行：

- 0行目：下向き・正面
- 1行目：上向き・背面
- 2行目：左向き
- 3行目：右向き

各行の6コマ：

1. 静かな待機
2. 小さくぷるんと揺れる
3. 地面へ低く潰れてホップを溜める
4. 縦に伸びて小さく跳ねる
5. 横へ広く潰れて着地する
6. 通常の形へ戻る

4番目の空中コマには、セル内ですでに約4px分の浮き上がりが含まれています。ゲーム側で同じ上下移動を追加しないでください。

## 1. 敵用スプライト設定

将来ルミバネ、ガラクロウ、ウツロボウ、イワウロコ、守護者にも展開できるよう、敵種別ごとのスプライト設定を追加してください。

構造は既存のキャラクタースプライト設定を参考にして構いませんが、プレイヤー専用の`CharacterId`や行動種別へモスプルンを混ぜないでください。

たとえば次を管理できる小さな敵用設定を用意します。

- `enemyKind`
- 画像URL
- シートサイズ
- フレームサイズ
- 方向別行
- 待機・移動クリップ
- クリップごとのコマ時間
- 描画倍率
- 足元アンカー
- 方向別の描画微調整

今回は`mossPlun`だけを登録し、イワウロコの現在の描画は変更しないでください。

## 2. 方向の決定

モスプルンの既存`enemy.facing`から、プレイヤーキャラクターと同じ基準で4方向を選んでください。

- `abs(x) > abs(y)`の場合：xが負ならleft、正ならright
- それ以外：yが負ならup、正ならdown
- ベクトルがほぼ0の場合：直前の表示方向を維持

向きが斜め付近で毎フレーム細かく切り替わらないよう、各モスプルンIDごとに直前方向を保持してください。可能ならプレイヤー側の方向解決関数を、型を壊さない範囲で共通化してください。

画像をコードで左右反転して4方向を作らないでください。左右で花・根・身体の描き分けが含まれるため、指定された行をそのまま使います。

## 3. 待機と移動クリップ

待機：

- 使用コマ：方向行内の0、1
- コマ時間：`[0.42, 0.42]`
- ループ

移動：

- 使用コマ：方向行内の2、3、4、5
- コマ時間：`[0.08, 0.18, 0.12, 0.16]`
- ループ

現在の敵状態と実際の移動処理に合わせてクリップを選んでください。

- `notice`、`windup`など、その場で止まっている状態：待機
- `approach`、`reposition`、後退中の`recover`：移動
- `idle`中の巡回：現在位置と移動目標の差が小さくなければ移動
- ノックバック中：専用被弾シート追加までは待機を基本にし、移動ホップを高速再生しない

`EnemyState.velocity`は現在の通常移動量を表していないため、単純にその長さだけでクリップを決めないでください。既存AI状態と、必要なら描画側で保持する直前位置との差を使用してください。

複数のモスプルンが完全に同時に跳ねて機械的に見えないよう、アニメーション開始位相へ`enemy.id`由来の小さなずれを加えてください。ただし移動速度やAIの行動時刻は変更せず、表示だけをずらします。

## 4. 現在の描画を置き換える

`Renderer.drawMossPlun()`にある緑色の`fillRect`中心の仮描画を、読み込み済みの正式スプライト描画へ置き換えてください。

- 48×48pxの該当コマを切り出す。
- 推奨描画倍率0.8から開始する。
- nearest-neighborで描画する。
- `enemy.pos`を足元基準として配置する。
- アンカー`x: 0.5`, `y: 0.92`を使用する。
- ワールド座標は整数へ丸め、ピクセルの滲みを防ぐ。
- Canvasの`imageSmoothingEnabled`を無効にする。

現在のモスプルン本体幅は約24px、当たり判定半径は12です。正式スプライトが極端に大きくならないよう、最初は0.8倍で確認してください。実機表示で必要な場合は0.75〜0.85の範囲だけで描画倍率を微調整して構いません。当たり判定半径は変更しないでください。

## 5. 影と接地

スプライトには影が含まれていません。現在のモスプルン用接地影をゲーム側で維持してください。

- 影の中心：現在と同じ足元付近
- 楕円半径：現在の13×4を基準
- 色と透明度：現在の`rgba(0,5,3,0.48)`を基準
- 影は本体より先に描画

ホップの空中コマでも影のワールド位置は固定してください。本体は画像内で少し浮きますが、影まで上下させないでください。

影が強すぎて浮いて見える場合は、位置をずらすより透明度を少し下げてください。影を水色の選択リングへ変更しないでください。

## 6. 攻撃予兆と被弾表示を維持

専用アクションシートを追加するまで、現在の表現を正式スプライトへ適用してください。

攻撃予兆：

- `enemy.telegraph > 0`の既存状態を維持する。
- 現在の予兆進行に合わせた軽い潰れ・膨らみを、スプライト全体の描画倍率へ適用してよい。
- 足元アンカーを固定し、上方向へ浮いて見えないようにする。
- 攻撃判定と予兆時間を変更しない。

被弾：

- `enemy.hurtFlash > 0`の間、短い明度上昇または白寄りの合成で被弾を表示する。
- PNGそのものを加工した別画像へ置き換えない。
- 被弾中も苔、花、顔が読める強さにする。
- `hurtFlash`の継続時間を変更しない。

攻撃状態では、専用攻撃シートがまだないため待機または移動シートを一時的に使用して構いません。ただし現在の攻撃エフェクト、判定、ノックバックを削除しないでください。

## 7. HPバーと描画順

現在の`drawEnemyBars(enemy)`を維持してください。

描画順：

1. 接地影
2. モスプルン本体
3. 被弾や予兆の表示
4. HPバー

HPバーがスプラウトや花へ重なる場合は、HPバーのY位置だけを見た目に合わせて数px上へ調整して構いません。HP値、最大HP、バー幅のルールは変更しないでください。

- 当たり判定半径12
- 攻撃クールダウン1.8秒
- `basicMelee`のAIと攻撃権制御
- 敵の接近速度、待機距離、予兆、攻撃、後退
- イワウロコの描画と全数値
- プレイヤー3人のスプライトと戦闘機能
- パーティー陣形、交代、回復
- BGM、効果音、HUD

## 9. テスト

既存テストを維持し、可能なら次を追加してください。

- モスプルン画像とJSONが正常に読み込まれる。
- 4方向で正しい行が選ばれる。
- 待機は0、1コマをループする。
- 移動は2、3、4、5コマを順番にループする。
- 複数個体の開始位相が少しずれる。
- 画像読み込み失敗時は、ゲームが停止せず現在の簡易描画へフォールバックする。
- 攻撃予兆、攻撃判定、被弾、ノックバック、撃破が従来どおり動く。
- HP58、ダメージ18、経験値12、半径12、クールダウン1.8秒が変わっていない。
- イワウロコの表示へ影響がない。

最後に`npm test`と`npm run build`を実行してください。

## 完了条件

- モスプルンが正式な苔スライムのピクセルアートで表示される。
- 正面・背面・左右が移動方向に応じて切り替わる。
- 待機中は静かにぷるんと揺れ、移動中は潰れて小さく跳ねる。
- ホップ中も足元と影が安定し、宙へ浮き続けて見えない。
- 花、芽、苔、半透明の身体がゲーム内サイズでも読める。
- 攻撃予兆、被弾、HPバー、AI、戦闘数値が壊れていない。
- イワウロコとプレイヤー側へ意図しない変更がない。

# 序章を６枚・各２文の一括表示ナレーションにする実装指示案

状態：**2026-10-20、文案・表示方向を採用し「実装に移って」と明示承認。同日、実装・技術検証済み。** 実機・Safari/WebKit・VoiceOver・聴感等の未確認事項は末尾に記載。実装先は `コード実装 | エロリア2`。推奨モデル：**Sol High**。

## 目的・一次資料

現行の「１枚の絵に１行ずつ、クリックで２行目」から、**各絵が出た瞬間にナレーション２文の全文を同時に表示し、１回の操作で次の絵へ進む**形に変える。現行の６画像を維持し、文面・順序は `docs/storyboard-eloria-prologue-narration-v3.md` を一次資料とする。人物の台詞・話者ラベルは外す。６場面・計１２文で、序章の開始／終了位置、物語の核、アートワーク、森のプレイマップは変更しない。

## 実装範囲

- `src/ui/openingSequence.ts`：各場面のナレーション２文を一単位として管理する。場面表示時点で２文とも全文可視とし、タイプライター進行・行単位のクリック消費をなくす。次へ操作は１場面だけ進める。６枚目からは既存どおり森へ一度だけ移る。スキップ、戻ってからの再開始、連打・押しっぱなしによる飛ばし防止を維持する。既存の他画面の文字演出には影響させない。
- `src/ui/OpeningController.ts`：話者名領域を表示しない。ナレーション２文を読みやすい一組として初回描画から全文表示し、ボタンを一貫して「次へ」にする。クリック／タップ、Enter・Space・E等の既存操作とスキップ／戻るを維持。`aria-live` では各絵への切り替え時に２文を自然な順で一度だけ伝え、細かな再描画で読み上げを重複させない。
- `src/ui/opening.css`：PC、横スマホ、iPad相当で２文が同時に読め、送りボタンと重ならず、人物・重要な手がかりを必要以上に隠さないよう字幕エリアを調整する。狭い画面では折り返しを許し、文字を過度に小さくしない。画像６枚の切替、パン／ズーム、クロスフェードの画角は保つ。
- タイトル・序章は無音。森への着地後に既存の森BGMを開始する。新しい音楽・効果音、自動送り、村のプレイマップ、開発ワープの仕様変更は対象外。

## 検証条件

1. 通常STARTから６画像が所定の順番で表示され、**各画像の初回描画時にその２文がともに全文表示**される。全１２文が絵コンテ v3 と一致し、旧１３行の台詞や話者ラベルが残らない。
2. １クリック／タップ／決定キーで１画像だけ進み、２文目表示のための余分な操作がない。連打や押しっぱなしで意図せず複数画像を飛ばさない。６枚目の次に森へ一度だけ着地する。
3. 途中スキップ、タイトルへ戻って再START、動き軽減、画像読み込み失敗時のナレーションとスキップ、字幕のアクセシビリティを確認する。

5. `npm run typecheck`、`npm test`、`npm run build` を通す。検証用に開いたブラウザ／隠しタブ／サーバー・音は作業後に閉じ、ユーザーが起動中のものは勝手に停止しない。

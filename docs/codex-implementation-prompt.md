# Codex向け実装指示文

以下の文章を、Project Eloriaをコード実装するCodexタスクへそのまま渡してください。

---

`project_eloria` に、ブラウザで遊べる見下ろし型アクションRPGの試作版を実装してください。

最初に次の仕様書を全文確認してください。

- `docs/game-design-first-stage.md`

既存の正式コンセプト画像は `assets/concepts/` 以下にあります。これらは世界観とデザインの参照資料です。元画像を上書き、切り抜き、削除しないでください。実装用に作る素材は別フォルダへ非破壊で保存してください。

## 今回の目的

ダンジョン全体を作る前に、1つの戦闘アリーナで3人パーティーの操作感と攻撃エフェクトを試せる、プレイ可能な縦切り試作版を完成させてください。

## 技術方針

- PCブラウザを最優先にする。
- TypeScriptを使用する。
- 軽量なCanvasベースの構成を優先する。既存のプロジェクト構成がある場合はそれを尊重する。
- 新規構成の場合は、保守しやすい最小限のVite構成を選んでよい。
- 外部ゲームエンジンや大規模ライブラリは、明確な利点がなければ追加しない。
- ゲームループ、入力、描画、衝突、キャラクター、敵、エフェクト、HUDの責務を分離する。
- デスクトップとモバイルで同じゲームロジックを共有できる入力抽象化を用意する。
- 既存コンセプト画像は背景資料として扱い、試作版では独自に描いた単純なピクセル風プレースホルダーを使用してよい。

## 必須のプレイ内容

### 3人パーティー

- カイル、ナディ、メルの3人を同時に表示する。
- 1人を操作し、残り2人は後方で陣形を取りながら追従する。
- Spaceで操作キャラクターを順番に交代する。
- 交代時は各キャラクター固有の交代攻撃を出す。
- 後方メンバーは近い敵へ通常攻撃だけを自動使用する。
- 後方メンバーの攻撃力は50%、受けるダメージも50%にする。
- メルが後方にいて、味方のHPが一定以下かつMPがある場合、回復魔法を自動使用する。回復量は半減しない。

### PC操作

- WASDまたは矢印キー：移動
- J：通常攻撃
- K：特殊技
- L：大技
- Space：キャラクター交代
- EまたはEnter：調べる・決定
- Esc：ポーズ
- ブラウザ標準動作と衝突するキー操作はゲーム中に適切に抑止する。
- キーを押し続けた際に大技や交代が不正に連続発動しないよう、押下エッジとクールダウンを管理する。

### 戦闘

- 1つのアリーナへ通常敵を2〜3体配置する。
- 最初はモスプルン系の近接敵と、イワウロコ系の装甲敵を簡略実装する。
- 敵の攻撃には床上の予兆を付ける。
- 攻撃を受けると軽くノックバックし、約1秒間無敵になる。
- キャラクターのHPが0になると、その場で片膝をつき、頭と武器を下げた戦闘不能状態になる。
- 戦闘不能中はターゲット、攻撃判定、衝突判定の対象外にする。
- 操作キャラクターが戦闘不能になった場合は、生存キャラクターへ自動交代する。
- 戦闘終了後、戦闘不能キャラクターはHP30%で復帰する。
- 3人全員が戦闘不能になるとゲームオーバー画面を表示し、現在のアリーナをHP・MP全回復で再挑戦できる。
- 再挑戦しても獲得経験値は失わない。

### 技

カイル：

- 通常攻撃「連刃剣」：短い近接斬撃。
- 特殊技「破陣突き」：前方突進と装甲破壊。
- 大技「裂空断」：前方へ大きな風の刃。
- 交代攻撃「先陣斬り」：交代地点へ高速で入り斬る。

ナディ：

- 通常攻撃「月輪投げ」：短距離を往復する月輪刃。
- 特殊技「円月旋」：自身を中心とした広範囲攻撃。
- 大技「月蝕乱舞」：複数の円環攻撃後、大きな円環を発生させる。
- 交代攻撃「輪光掃」：交代直後に前方を広く払う。

メル：

- 通常攻撃「燐光弾」：追尾しすぎない小型魔法弾。
- 特殊技「癒しの環」：味方を回復する範囲魔法。
- 大技「天晶崩落」：指定方向または近い敵の位置へ大きな晶石魔法を落とす。
- 交代攻撃「瞬光障壁」：交代時に短時間の防御障壁を展開する。

大技にはゲージまたはクールダウンを設け、通常攻撃の連打だけで即座に連発できないようにしてください。試作段階では調整値を定数ファイルへまとめてください。

## エフェクト

- 通常攻撃は短く読みやすい軌跡にする。
- 特殊技はキャラクター固有色を強くする。
- 大技は通常技より明確に派手にする。
- ヒット時に短いヒットストップ、軽い画面振動、火花または破片を入れる。
- カイルは白銀と青緑の斬撃・風。
- ナディは青白い円環と月輪軌跡。
- メルは淡い青緑の燐光・晶石・葉の回復光。
- 星形の意匠は多用しない。
- 大技エフェクトで敵、プレイヤー、敵攻撃予兆を完全に隠さない。
- 画面振動と強い点滅を無効化できる設定値をコード上に用意する。
- オブジェクトプールまたは再利用可能な軽量エフェクト管理を行い、長時間遊んでもDOMや描画オブジェクトが増え続けないようにする。

## HUD

- 左上へ3人分のHPを表示する。
- 操作中キャラクターを大きく明るい枠で表示する。
- メルのみMPバーを表示する。
- メルの自動回復が可能なときは、小さな回復待機アイコンを表示する。
- 右下へ通常攻撃、特殊技、大技、交代の4アイコンを表示する。
- PCでは各アイコンへJ、K、L、Spaceを小さく表示する。
- 経験値ゲージは常設しない。
- 敵撃破時、その位置へ小さく `EXP +数値` を表示し、上へ移動しながら約1秒で消す。
- タイム、スコア、コンボ、ランキングは表示しない。

## 回復ドロップ

- 敵撃破時に状況に応じて「若葉の雫」または「魔力の露」を落とす。
- 若葉の雫は最もHPが減っている味方を少量回復する。
- 魔力の露はメルのMPを少量回復する。
- 近づくと自動取得する。
- HP・MPが十分な場合は対応ドロップ率を下げる。

## モバイル準備

今回の完成条件はPC操作ですが、入力層は将来のタッチ操作を追加できる構造にしてください。

可能なら次も実装してください。

- 画面左側を触ると、その位置へフローティングスティックを表示する。
- 指を離すと約0.5秒で消える。
- 右側へ通常攻撃、特殊技、大技、交代のタッチボタンを表示する。
- 最後に使用した入力方式がPCならタッチUIを隠し、タッチなら表示する。

モバイル対応が試作完成を遅らせる場合は、入力インターフェースとTODOだけを用意し、PC版を優先してください。

## 品質条件

- 開発サーバーを起動し、実際に操作して主要フローを確認する。
- ビルド、型チェック、既存テストを実行する。
- 追加したロジックへ必要最小限の自動テストを用意する。
- キー入力、交代、戦闘不能からの自動交代、メルの自動回復、経験値加算、再挑戦で経験値を失わないことを確認する。
- 既存ファイルやコンセプト画像を削除しない。
- 作業完了時に、起動方法、操作方法、実装済み項目、未実装項目を日本語で報告する。

まず既存ファイルを確認し、短い実装計画を示してから作業を開始してください。質問がなくても合理的な仮定で進め、プレイ可能な状態まで完成させてください。

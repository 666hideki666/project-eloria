# Codex向け追加指示：メル特殊技「癒しの環」モーションを導入

Project Eloriaへ、メルの特殊技「癒しの環」の4方向詠唱アニメーションを導入してください。

カイル「破陣突き」とナディ「円月旋」で追加済みの共通アクションスプライト読み込み、方向固定、非ループ再生、終了後の待機・歩行復帰処理を再利用してください。メルだけ別方式のアニメーション管理にしないでください。

今回は表示モーションだけを追加します。回復量、MP消費、範囲、クールダウン、自動回復条件、効果音、既存の回復エフェクトなど、ゲームプレイの数値と判定は変更しないでください。

## 使用素材

- 画像：`assets/sprites/characters/mel/attacks/mel-special-healing-ring-48px-v1.png`
- 設定：`assets/sprites/characters/mel/attacks/mel-special-healing-ring-48px-v1.json`

画像仕様：

- 全体：288×192px
- 1コマ：48×48px
- 6列×4行
- 透過PNG
- ループなし
- 再生時間：0.38秒

方向行：

- 0行目：下向き
- 1行目：上向き
- 2行目：左向き
- 3行目：右向き

各行は左から次の6コマです。

1. 通常の杖構え
2. 杖を胸元へ寄せて祈る
3. 杖を上げながら空いた手を開く
4. 杖を高く掲げる詠唱の頂点
5. 杖を静かに下ろす
6. 通常の杖構えへ戻る

杖は画像へ含まれています。別描画の杖を重ねないでください。回復円、葉、晶石粒子、発光、回復数値などは画像へ含まれていないため、既存のゲーム側エフェクトを維持してください。

## 1. アクションスプライト登録

既存の`characterSpriteConfig.ts`へ、カイルとナディの`special`と同じ構造でメルの特殊技画像とJSONを読み込み、`MERU_SPRITE.actions.special`として登録してください。

実行時のキャラクターIDは既存どおり`meru`です。素材フォルダ名とJSON上の制作名は`mel`ですが、新しいキャラクターIDを追加しないでください。

設定値：

- フレームサイズ：48×48px
- 列数：6
- 方向別行：down 0 / up 1 / left 2 / right 3
- 足元アンカー：`x: 0.5`, `y: 0.92`
- ループ：なし
- 総再生時間：0.38秒
- コマ時間：`[0.05, 0.055, 0.07, 0.08, 0.065, 0.06]`
- 視覚的な詠唱頂点：3番コマ

画像補間は無効にし、既存キャラクターと同じnearest-neighbor描画を使用してください。

## 2. 手動発動へ接続

プレイヤー操作中のメルが特殊技を使い、現在の`performSpecial()`内で

```ts
this.beginCharacterAction(member, "special", 0.38);
```

が呼ばれた場合だけ、この「癒しの環」シートを再生してください。

- 発動開始時の`actionFacing`から方向行を一度選ぶ。
- 再生中は向きを固定する。
- キャラクター画像をコードで回転・左右反転しない。
- 6コマを1回再生し、終了後は現在の待機・歩行へ戻す。
- 詠唱中もメルのワールド座標は固定し、画像内の上半身と杖だけが動いて見えるようにする。
- 同じ技を再発動したときは0番コマから再スタートする。

現在の手動回復仕様をそのまま維持してください。

- MP消費：24
- 回復量：31
- 効果範囲：メル中心、半径82
- 特殊技クールダウン：4秒
- 範囲内にいる戦闘不能ではない味方全員が対象
- 回復は後方補正で半減しない
- バナー：`メル｜癒しの環`
- 既存の回復効果音を使用

回復処理を3番コマまで遅らせるなど、既存の発動タイミングは変更しないでください。3番コマは視覚上の頂点であり、ゲーム判定の新しいタイマーではありません。

## 3. 後方AIの自動回復へ接続

`updateAutoHeal()`から

```ts
this.beginCharacterAction(meru, "special", 0.38);
```

が呼ばれた場合にも、同じ「癒しの環」シートを再生してください。

現在の自動回復仕様を維持してください。

- メルが後方にいるときだけ使用
- 味方HPが既存の閾値を下回った場合に発動
- MP消費：18
- 回復量：27
- クールダウン：5.2秒
- 回復量は後方補正で半減しない
- バナー：`メル｜癒しの環 AUTO`
- 既存の回復効果音を使用

自動回復時の向きは、発動直前のメルの向きを使用して固定してください。回復対象の方向へ強制的に旋回させる必要はありません。

後方AIの移動によってモーションが即座に歩行へ上書きされないよう、既存の行動中スプライト優先順位を守ってください。ただし、メルの座標・追従AI・陣形ロジックそのものは変更しないでください。

## 4. エフェクトとの役割分担

スプライトはメル自身の詠唱動作だけを担当します。

現在の`spawnHealingEffects()`による次の表現を維持してください。

- 足元へ広がる柔らかな回復円
- 淡い青緑色の発光
- 葉や晶石を思わせる粒子
- 回復対象側の回復表現

モーション導入時に同じ回復円をスプライト側へ追加したり、既存エフェクトを二重に生成したりしないでください。杖頭の桃色の晶石はスプライトに含まれるため、別の杖や杖頭を重ねないでください。

## 5. 状態の優先順位

描画アクションの優先順位は、既存の共通ルールを使用してください。

1. 戦闘不能
2. 特殊技などの行動中
3. 通常攻撃
4. 移動
5. 待機

少なくとも次を保証してください。

- 癒しの環中に燐光弾シートを再生しない。
- 通常攻撃中に癒しの環シートを再生しない。
- 天晶崩落や瞬光障壁で癒しの環シートを誤再生しない。
- 戦闘不能時は詠唱より戦闘不能表示を優先する。
- キャラクター交代後も行動状態が不正に残らない。

## 6. 変更しないもの

- カイルとナディの全スプライト
- メルの待機・歩行スプライト
- メルの通常攻撃「燐光弾」スプライト
- 手動回復と自動回復の数値・対象判定
- メルのMPシステム
- 回復エフェクトと効果音
- 敵AI、当たり判定、ダメージ計算
- パーティー陣形、交代、後方補正
- HUD、ポーズ、BGM

## 7. テスト

既存テストを維持し、可能なら次の確認を追加してください。

- メルの`special`画像とJSONが正常に読み込まれる。
- 特殊技は方向別の正しい行を使用する。
- 0.38秒で6コマを1回だけ再生する。
- 手動の癒しの環で特殊技シートが再生される。
- 後方AIの自動回復でも同じ特殊技シートが再生される。
- 燐光弾、天晶崩落、瞬光障壁で特殊技シートが誤再生されない。
- 手動回復のMP消費24、回復量31、半径82、クールダウン4秒が変わっていない。
- 自動回復のMP消費18、回復量27、クールダウン5.2秒が変わっていない。
- 回復量に後方の0.5倍補正が適用されない。
- 行動終了後に待機・歩行へ正常に戻る。

最後に`npm test`と`npm run build`を実行し、既存機能に回帰がないことを確認してください。

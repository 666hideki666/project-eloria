# Codex向け追加指示：ルミバネの浮遊待機・飛行スプライトを導入

Project Eloriaへ、小型飛行昆虫「ルミバネ」を正式な敵種別として追加してください。

今回は待機・飛行移動の正式スプライト化までを対象にします。専用攻撃、被弾、撃破、羽の発光エフェクトは次の作業へ分離し、既存の敵AIや戦闘システムを大きく作り直さないでください。

## 使用素材

- 画像：`assets/sprites/enemies/lumibane/lumibane-idle-flight-48px-v2.png`
- 設定：`assets/sprites/enemies/lumibane/lumibane-idle-flight-48px-v2.json`
- 採用コンセプト：`assets/concepts/monsters/lumibane-pixel-concept-v1.png`

画像は横6列×縦4行、1コマ48×48px、全体288×192pxの透過PNGです。

行の向き：

1. `down`：正面
2. `up`：背面
3. `left`：左向き
4. `right`：右向き

各行は最後まで同じ方向です。左右を反転流用せず、JSONの行をそのまま使用してください。

## 1. 敵種別と暫定戦闘値

`EnemyKind`へ`"lumibane"`を追加してください。

待機・移動の確認段階では次の値を使用します。

```ts
lumibane: {
  name: "ルミバネ",
  hp: 42,
  armor: 0,
  archetype: "swarm",
  radius: 10,
  damage: 12,
  attackCooldown: 1.5,
  exp: 10,
}
```

ルミバネは小型で素早い飛行敵ですが、単体の火力と耐久はモスプルンより低くします。`swarm`は既存設定を使い、この作業で全敵のAI数値を変更しないでください。

## 2. 現在の3体構成

現在の敵数3体は維持し、2体目だけをルミバネへ変更してください。

```ts
createEnemy(1, "mossPlun", 425, 132, wave),
createEnemy(2, "lumibane", 485, 244, wave),
createEnemy(3, "utsurobou", 505, 178, wave),
```

これにより確認用アリーナは次の3種類になります。

- モスプルン
- ルミバネ
- ウツロボウ

敵IDと座標、合計数は変更しません。イワウロコの型、設定、簡易描画も後の正式実装に使うため残してください。

## 3. 既存の敵スプライト基盤を再利用

`src/render/enemySpriteConfig.ts`へ画像とJSONを読み込み、既存の`createEnemySpriteConfig()`で設定を作成してください。

```ts
export const LUMIBANE_SPRITE = createEnemySpriteConfig(
  lumibaneSpriteUrl,
  lumibaneFrameData,
);
```

`ENEMY_SPRITE_CONFIGS`へ追加します。

```ts
lumibane: LUMIBANE_SPRITE,
```

モスプルン、ウツロボウと同じ`EnemySpriteRenderer`、方向解決、フレーム選択、敵ID由来の位相ずらしを再利用してください。ルミバネ専用の画像ローダーや別アニメーションクラスは作らないでください。

## 4. アニメーション

JSONのクリップをそのまま読み込みます。

### `idle`

- コマ：`0 → 1 → 2 → 1`
- 時間：`0.15 → 0.12 → 0.15 → 0.12`秒
- ループ：あり

### `move`

- コマ：`2 → 3 → 4 → 5`
- 各0.08秒
- ループ：あり

高速な羽ばたきは表示だけです。アニメ速度を移動速度、攻撃間隔、当たり判定へ連動させないでください。

`resolveEnemySpriteClip()`は既存処理をそのまま使います。

- `approach`、`reposition`、`recover`、実際に巡回移動中：`move`
- 停止中、予兆中、攻撃中、ノックバック中：`idle`

## 5. 描画

`Renderer.drawEnemy()`へ`lumibane`分岐を追加し、次の順で描画してください。

1. 小さく薄い飛行影
2. ルミバネ本体
3. 既存のHPバー

影の初期値：

- 中心：敵座標の下約5px
- 横半径：8px
- 縦半径：2px
- 色：`rgba(0, 5, 8, 0.22)`

スプライトには影が含まれていません。羽ばたきに合わせて影を大きく伸縮させず、浮遊物だと分かる程度のごく小さな変化に留めてください。

JSONの初期値：

- `drawScale: 0.72`
- `anchor: { x: 0.5, y: 0.86 }`

実機で必要な場合、描画倍率だけ`0.68〜0.76`の範囲で微調整して構いません。半径10の当たり判定は見た目調整のために変更しないでください。

ロード失敗時には、ルミバネと判別できる簡易フォールバックを表示してください。既存のイワウロコへ落とす`else`にはせず、敵種別ごとに明示的に分岐させます。

簡易フォールバックは、茶色い小型胴体、左右の水色の羽、小さな影だけで十分です。

## 6. HPバー

ルミバネは小型かつ羽が上へ伸びるため、HPバーが羽に重ならない位置へ置いてください。

- 幅：24〜26px
- 基準：敵座標から上へ約38px

既存のモスプルン、ウツロボウ、イワウロコのHPバー位置は変更しないでください。

## 7. 開発用スプライト確認

現在の`enemySpriteQa`はウツロボウを直接探しているため、敵種別を選べる形へ小さく一般化してください。

例：

```text
?enemySpriteQa=down&enemySpriteQaClip=idle&enemySpriteQaKind=lumibane
?enemySpriteQa=left&enemySpriteQaClip=move&enemySpriteQaKind=lumibane
```

`enemySpriteQaKind`は登録済みの敵種別だけを受け付け、未指定時は現在どおり`utsurobou`を既定値にしてください。本番処理へQA専用分岐を混ぜず、`import.meta.env.DEV`内に限定します。

確認対象：

- 正面では両目が見える。
- 背面では目が見えない。
- 左右で頭の向きが正しい。
- 各行の途中で別方向へ回転しない。
- 羽が高速に動いても胴体の世界座標が跳ねない。
- 複数個体の羽ばたきが完全同期しない。

## 8. 今回は実装しないもの

- 専用の突進攻撃モーション
- 攻撃予兆エフェクト
- 被弾モーション
- 撃破・消滅モーション
- 羽の残光や光粒
- 飛行高度による近接攻撃無効
- 新しい遠距離攻撃

現在の通常攻撃、予兆、被弾フラッシュ、ノックバックを維持してください。専用アクション素材ができるまでは既存表示へ安全にフォールバックさせます。

## 9. テスト

最低限、次を追加または更新してください。

- `EnemyKind`と`ENEMY_TUNING`にルミバネが存在する。
- ルミバネの暫定HP42、ダメージ12、経験値10、半径10、クールダウン1.5秒が使われる。
- 現在の敵ID2が座標485・244のルミバネになる。
- 敵数は3体のまま。
- 画像寸法が288×192で、48×48の24コマとして読める。
- 4方向の行と`idle`・`move`クリップがJSONどおり解決される。
- ロード失敗時もゲームが停止せずフォールバック表示になる。
- モスプルン、ウツロボウ、イワウロコの既存設定が変わっていない。

最後に次を実行してください。

```bash
npm test
npm run build
```

既存スクリプトに個別テストコマンドがある場合は、それも実行してください。

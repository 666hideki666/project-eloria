## 再生と画面操作

1. 既存の `AudioManager` の**単一BGMプレーヤー**へタイトル用トラックを追加する。開発用の直接開始やQA/arena起動にはタイトル曲を流さない。既存の音量・ミュート・タブ非表示時停止、再表示時の扱いを共通の再生系で維持する。
2. タイトル画面表示中は、再生可能なら穏やかに曲を始めてループさせる。ブラウザ側で初回自動再生が許可されない場合、エラーを出して画面を止めず、タイトル内に邪魔にならない**「♪ 音楽を再生」ボタン**を示す。クリック／タップで再生を許可し、STARTせずにタイトル画面で曲を聴けるようにする。再生中は同じボタンを「♪ 音楽を止める」と表示し、タイトル曲の停止／再開を切り替えられるようにする。音声を聴かずにSTARTする操作も妨げない。
3. STARTを押したらタイトル曲を短くフェードアウトし、プロローグ中に鳴らさない。STARTのユーザー操作による再生許可処理と競合して、プロローグに入ってからタイトル曲が遅れて鳴り出すことも防ぐ。プロローグから「タイトルへ戻る」ときは、再生許可済みならタイトル曲へ戻す。再STARTで複数の音声要素や曲が重ならない。
4. プロローグ６枚の最後に古の森へ着地したときだけ、既存の森BGMを通常どおり開始。タイトル曲が同時に鳴らない。スキップ、DEV WARP、全画面、音量・ミュート、タブ切替、再生失敗からの回復も既存導線を壊さない。タイトルの絵、ロゴ、START配置とプロローグの文字演出は変更しない。

## 検証

- 通常起動のタイトルで、許可済み環境では曲が再生され、再生制限のある環境では「♪ 音楽を再生」操作後に聴ける。ループ、音量・ミュートを確認。START後はプロローグが無音で、タイトルへ戻れば再生可、最後に森曲へ移る。スキップとDEV直接開始でも余計な曲が残らない。再生の拒否や音源読込失敗でもゲーム進行可能。
- `npm run typecheck`、`npm test`、`npm run build`。PC、横スマホ、iPad相当、製品ビルドのタイトル操作・曲の選択／停止を確認。可能なら実耳で、ループの継ぎ目、既存曲との音量差、START時のフェードを試聴。実耳で未確認なら音量調整や自然なループを検証済みと記録しない。
- 作業時に開いたブラウザ・隠しタブ・検証サーバーや鳴っている音を終了する。ユーザーが起動中の既存サーバー／タブは無断で停止しない。実装・検証結果と未確認事項を `docs/project-handoff.md` に更新する。

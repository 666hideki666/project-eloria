# Codex向け追加指示：イワウロコの待機・重歩行スプライトを導入

Project Eloriaで既に戦闘データと簡易描画が存在する「イワウロコ」へ、正式な4方向ピクセルアートを導入してください。

今回は岩装甲が残っている状態の待機・移動までを対象にします。装甲破壊後の正式画像、専用突進、被弾、撃破エフェクトは次の作業へ分離してください。

また、ユーザーの希望により、確認用アリーナへモスプルンを必ず戻してください。

## 使用素材

- 画像：`assets/sprites/enemies/iwauroko/iwauroko-idle-crawl-48px-v1.png`
- 設定：`assets/sprites/enemies/iwauroko/iwauroko-idle-crawl-48px-v1.json`
- 採用コンセプト：`assets/concepts/monsters/iwauroko-pixel-concept-v1.png`

画像は横6列×縦4行、1コマ48×48px、全体288×192pxの透過PNGです。

行の向き：

1. `down`：正面
2. `up`：背面
3. `left`：左向き
4. `right`：右向き

各行は全コマ同じ方向です。左右反転で代用せず、JSONの行をそのまま使用してください。

## 1. 既存の敵種別と戦闘値を維持

`EnemyKind`には既に`"iwaUroko"`が存在します。新しい別名や重複する敵種別を追加しないでください。

現在の設定を維持します。

```ts
iwaUroko: {
  name: "イワウロコ",
  hp: 132,
  armor: 42,
  archetype: "heavyCharge",
  radius: 16,
  damage: 30,
  attackCooldown: 2.7,
  exp: 28,
}
```

この作業では戦闘数値と`heavyCharge`の挙動を変更しません。

## 2. 確認用アリーナへモスプルンを戻す

敵数3体を維持し、次の構成へ変更してください。

```ts
createEnemy(1, "mossPlun", 425, 132, wave),
createEnemy(2, "iwaUroko", 485, 244, wave),
createEnemy(3, "utsurobou", 505, 178, wave),
```

確認画面：

- モスプルン
- イワウロコ
- ウツロボウ

モスプルンは正式なホップアニメーションを従来どおり使用し、動きや数値を変更しないでください。

ガラクロウとルミバネは現在の確認画面から外れますが、型、戦闘設定、正式スプライト、描画処理、QA機能をすべて残してください。

## 3. 既存の敵スプライト基盤を再利用

`src/render/enemySpriteConfig.ts`へ画像とJSONを読み込み、既存の`createEnemySpriteConfig()`で設定を作成してください。

```ts
export const IWAUROKO_SPRITE = createEnemySpriteConfig(
  iwaurokoSpriteUrl,
  iwaurokoFrameData,
);
```

`ENEMY_SPRITE_CONFIGS`へ追加します。

```ts
iwaUroko: IWAUROKO_SPRITE,
```

既存の`EnemySpriteRenderer`、方向解決、フレーム選択、敵ID由来の位相ずらしを再利用してください。イワウロコ専用のローダーや別アニメーションクラスは作らないでください。

## 4. アニメーション

JSONのクリップをそのまま読み込みます。

### `idle`

- コマ：`0 → 1`
- 各0.48秒
- ループ：あり

### `move`

- コマ：`2 → 3 → 4 → 5`
- 各0.16秒
- ループ：あり

イワウロコは低い重心で、ゆっくり体重を移動させます。アニメ速度を移動速度、攻撃時間、当たり判定へ連動させないでください。

既存の`resolveEnemySpriteClip()`を基本的に使い、イワウロコの`heavyCharge`中だけ次を追加します。

- `windup`：`idle`
- `attack`：`move`
- `recover`：従来どおり`move`

これにより、突進中に静止した待機絵にならないようにします。AIの状態時間や突進速度そのものは変更しません。

## 5. 岩装甲状態と暫定フォールバック

今回の正式画像は、背中の岩装甲が残っている状態です。

- `enemy.armor > 0`：正式スプライトを表示
- `enemy.armor <= 0`：既存の簡易描画を、暫定的な装甲破壊後表示として使用

現在の簡易描画では装甲ゼロ時に背中の岩板が減り、青緑の亀裂が見えるため、正式な破壊後スプライトができるまで視認性を維持できます。

既存の簡易描画を`drawIwaUrokoFallback()`のような明確な名前へ整理して構いませんが、処理内容は失わないでください。正式スプライトのロード失敗時にも同じフォールバックを使用します。

装甲が壊れた瞬間に当たり判定、HP、位置、向き、AI状態をリセットしないでください。変わるのは表示だけです。

## 6. 描画

描画順：

1. 接地影
2. イワウロコ本体
3. 既存のHPバーと装甲バー

影の初期値：

- 中心：敵座標の下約3px
- 横半径：18〜19px
- 縦半径：4px
- 色：`rgba(0, 5, 4, 0.42)`

JSONの初期値：

- `drawScale: 0.94`
- `anchor: { x: 0.5, y: 0.82 }`

実機で必要な場合、描画倍率だけ`0.90〜1.00`の範囲で微調整して構いません。半径16の当たり判定は見た目調整のために変更しないでください。

イワウロコは接地型です。本体の脚・腹の下端と影の上半分を3〜4px程度重ね、影だけが離れて見えないようにしてください。

被弾中の白色フラッシュは既存の`EnemySpriteRenderer`を使います。画像内に追加の亀裂や石片を描き足さないでください。

## 7. HP・装甲バー

既存のイワウロコ用表示を維持します。

- HPバー幅：34px
- HPバーの下に装甲バー
- 装甲が0になったら装甲バーは空または非表示

岩板や額の青い亀裂と重ならないよう、基準位置は敵座標から上へ約34〜38pxの範囲で実機調整してください。他の敵のバー位置は変更しないでください。

## 8. 開発用スプライト確認

既存の`enemySpriteQaKind`を再利用します。

```text
?enemySpriteQa=down&enemySpriteQaClip=idle&enemySpriteQaKind=iwaUroko
?enemySpriteQa=up&enemySpriteQaClip=move&enemySpriteQaKind=iwaUroko
?enemySpriteQa=left&enemySpriteQaClip=move&enemySpriteQaKind=iwaUroko
?enemySpriteQa=right&enemySpriteQaClip=move&enemySpriteQaKind=iwaUroko
```

QAモードでは装甲値も確認できるようにしてください。

- 通常：装甲ありの正式スプライト
- `armor=0`相当の既存QA：暫定破壊後フォールバック

確認対象：

- 正面で両目、岩兜、青い亀裂が読める。
- 背面で背中の石列と尾が見える。
- 左右で頭と尾の向きが正しい。
- 歩行しても腹部の接地点が跳ねない。
- モスプルンのホップが従来どおり再生される。

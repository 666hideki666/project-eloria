# Codex向け実装指示：スクロールマップ基盤と第1層「苔根の遺構」

> **初回実装の記録**：この指示書の1280×1152マップは実装済み。プレイテストで、1画面に入るマップ構造が多く、参照画像の探索スケールより小さいことが判明した。今後の寸法・レイアウト修正は`docs/codex-revise-layer1-scale-to-reference.md`を正とする。カメラ、タイル衝突、4エンカウント、BGM切り替えはそのまま再利用する。

## 実行設定

- 推奨モデル：`GPT-5.6 Sol`
- 推論レベル：`High`
- `Ultra`：不要
- 理由：固定画面座標からワールド座標とカメラへ移行し、衝突、描画、敵エンカウント、エフェクト、QAをまとめて守る重要な基盤変更のため。

## 最重要の仕様変更

当初の「1部屋＝1画面」固定画面式は廃止する。

第1層全体を1つの大きな連続マップとし、操作キャラの移動に合わせてカメラが追従する。プレイヤーが進むと、画面外にあった通路、分岐、行き止まり、敵、晶石が見えてくる方式にする。

旧指示書`docs/codex-implement-moss-corridor-first-encounter.md`の固定画面・暗転部屋遷移は実装しない。すでに実装済みのモスプルン3体戦、探索・戦闘BGM切り替え、1人探索・3人陣形は新マップへ再利用する。

## 1. マップとビューポート

- Canvas内部解像度：640×360を維持
- 第1層ワールドサイズ：1280×1152
- タイル基準：32px
- グリッド：40列×36行
- プレイヤー、敵、攻撃、エフェクト、ドロップ、調査対象はワールド座標で保持
- HUDと画面オーバーレイはスクリーン座標で描画

このサイズは暫定とし、プレイテスト後に変更できるよう、定数を1か所に集約する。床の各マスをDOMで作らない。外部タイルマップライブラリは追加しない。

## 2. カメラ

新規の小さなカメラ定義を追加する。配置は既存構成に合わせてよいが、例：

```text
src/stage/StageCamera.ts
```

必要状態：

```ts
interface CameraSnapshot {
  x: number;
  y: number;
  viewportWidth: 640;
  viewportHeight: 360;
}
```

要件：

- 操作キャラを緩やかに追従
- 完全な画面中央固定で常に揺らさず、中央周辺に小さなデッドゾーンを設ける
- 推奨デッドゾーン：画面内`x=260..380`、`y=145..215`
- デッドゾーンを出た分だけ目標座標を動かす
- 目標へ急ワープせず、短い補間で追従
- ワールド端で停止：`x=0..640`、`y=0..792`
- ピクセルアートがぼやけないよう、実描画時のカメラ座標は整数丸め
- ヒット時の画面揺れはカメラオフセットへ加算し、ワールド座標を書き換えない
- アリーナモードは従来どおり固定描画で、カメラの影響を受けない

`WorldSnapshot`からカラメ座標を取得できるようにする。Rendererはステージのワールド描画時に`translate(-cameraX, -cameraY)`を1度だけ適用する。各アクターが個別にカメラを引かない。

## 3. タイルグリッドと衝突

大きな迷路マップで複数の長方形障害物を大量に置く方式は避け、32pxグリッドの通行可否データを導入する。

推奨ファイル：

```text
src/stage/maps/mossRootRuinsMap.ts
src/stage/tileCollision.ts
```

最低限のタイル分類：

- `floor`：通行可
- `wall`：通行不可
- `root`：通行不可、根として描画
- `void`：通行不可、遺跡の外側
- `gate`：フラグにより通行可否が変化

要件：

- キャラクターの円形半径を考慮
- X軸とY軸を分けて解決し、壁沿いに滑れる
- 斜め移動で角をすり抜けない
- ノックバックや低FPS時に壁を貫通しない
- 後方メンバー展開時の安全位置検索にも使う
- 敵も通行不可タイルの外へ出ない
- 現在の固定部屋衝突は、移行完了までテストを残してよい

タイルグリッドは36行すべて同じ長さであることをテストする。

## 4. 第1層全体構成

第1層名：

```text
晶界・苔根の遺構
```

スタートはマップ最下部、出口は最上部とする。一本道にせず、左右の行き止まり、ループ、中央広場、将来の宝箱候補を含める。

ワールド座標の基準点：

| 場所 | 中心座標の目安 | 用途 |
| --- | --- | --- |
| 転送広場 | `(640, 1050)` | 開始・中央クリスタル |
| 初戦広場 | `(640, 805)` | モスプルン3体の初戦 |
| 中央晶石広場 | `(630, 610)` | ルートの主要目印・分岐 |
| 左の行き止まり | `(225, 535)` | 任意戦・将来の宝箱 |
| 右の曲路 | `(990, 625)` | 必須戦・中央へ戻るループ |
| 右上の小部屋 | `(1040, 390)` | 将来の宝箱または石碑 |
| 最終戦広場 | `(640, 235)` | モスプルン3体・出口解放 |
| 第2層への門 | `(640, 70)` | 今回は予告のみ |

ルート要件：

- 転送広場→初戦は迷わない短い通路
- 初戦後から左右の分岐が始まる
- 左には明確な行き止まりと1つの任意戦
- 右には大きく回り込んで中央へ戻るループ
- メインルートは床の晶石線や苔の少なさで暗示
- 行き止まりは無意味にせず、光る晶石、石碑、将来の宝箱用台座を置く
- 戻り道が長すぎないよう、中央広場へ戻るループを1つ作る
- 通路の最小幅は原則96px、戦闘広場への入口は128px程度を確保
- 戦闘広場は3人＋3体で戦える直径280〜340px程度

参照画像の密度をそのままコピーせず、第1層として迷いすぎないよう8割程度に簡略化する。

## 5. 描画

新規または再構成するファイル例：

```text
src/render/stages/MossRootRuinsRenderer.ts
```

転送の間と苔の回廊の既存描画ロジックを再利用・分割してよい。世界座標内の異なるエリアとして描画し、上下の固定部屋を並べただけに見えないよう通路と分岐で連続させる。

描画順：

1. 画面外の暗い晶洞
2. 古い石床と円形広場
3. 崩れた石壁、段差の側面
4. 太い根、苔、草、落ち葉
5. 青緑の晶石、石柱、床の導線
6. 調査対象と門
7. エフェクト、アクター、前景の根・柱

タイル境界が目立たないよう、固定ハッシュで床石のジッター、苔、亀裂を追加する。毎フレームの乱数は使わない。

カメラ外まで全タイルの高コスト描画を行わず、ビューポート周辺のタイルだけ描画する。静的な背景レイヤーは必要ならオフスクリーンCanvasへキャッシュしてよいが、過剰な最適化は不要。

## 6. 転送広場と開始フロー

- 通常起動は第1層最下部の転送広場から
- 操作キラ1人表示と探索BGMを維持
- 現在の入口オーバーレイ文言を維持
- 中央クリスタルを調べると、北の根の門が開く
- 開門後は部屋暗転を挟まず、そのまま北へ歩いて進む
- 中央クリスタルと門の演出は既存成果を再利用

古い`transferChamber -> mossCorridor`の暗転遷移は無効化する。調査キーは開門にのみ使い、開いた門は歩いて通過できる。

## 7. モスプルン10体と4エンカウント

第1層全体にモスプルン10体を配置する。すべて同時に反応させず、4つの独立したエンカウントグループに分ける。

```ts
type EncounterGroupId = "mossIntro" | "mossFork" | "mossDeadEnd" | "mossGate";
type EncounterGroupState = "dormant" | "noticed" | "active" | "cleared";
```

| グループ | 数 | 性格 | 場所の目安 |
| --- | ---: | --- | --- |
| `mossIntro` | 3 | 初戦、必須 | 初戦広場 `(640, 805)` |
| `mossFork` | 2 | 分岐後の必須戦 | 右の曲路 `(930, 620)` |
| `mossDeadEnd` | 2 | 行き止まりの任意戦 | 左の脇道 `(245, 520)` |
| `mossGate` | 3 | 第1層のまとめ、必須 | 最終広場 `(640, 235)` |

要件：

- 各グループは個別の発見範囲とクリア状態を持つ
- 発見範囲外の敵は待機描画のみで、追跡・攻撃トークン取得をしない
- 画面外の別グループが同時に反応しない
- 戦闘開始で操作キラを動かさず、他の2人を安全な後方タイルへ展開
- そのグループの敵数だけ`ENEMY n/total`と表示
- 攻撃トークンを使い、同時に攻撃するのは原則1体
- 敵同士の分離を維持し、団子状態を防ぐ
- グループの全敵撃破後に1人探索と探索BGMへ戻す
- 撃破済みグループは階層内で復活しない
- ページ再読み込み後の復活は今回許容
- 任意の`mossDeadEnd`を倒さなくても最終広場へ到達できる

各戦闘広場は、戦闘中だけ出入口の小型晶石または根が活性化して閉じる。不可視壁だけで閉じ込めず、視覚的な理由を描画する。戦闘終了で通行可能に戻す。

## 8. 第1層の出口

- `mossGate`の3体を撃破すると最上部の根の門が開く
- 門へ近づくと`第2層・崩れた晶洞へ`と表示
- `E`で`門の先から、小さな羽音が響いている。`と表示
- 今回は第2層へ遷移しない

第1層到達済み表示や大きなクリアオーバーレイはまだ不要。門を開け、次の階層を予告するところまでとする。

## 9. 回復の泉と宝箱候補

将来の追加に備え、マップ上に置き場所だけを用意する。今回はアイテム機能や所持品UIを実装しない。

- 左の行き止まり：宝箱用の小さな石台
- 右上の小部屋：宝箱または石碑用の空間
- 中央晶石広場の脇：小さな水盆。今回は装飾のみ

宝箱の空スプライトや「未実装」メッセージを画面に出さない。自然な小部屋・台座として描画する。本格的な全回復の泉は第3層のボス前に実装予定。

## 10. スクロール中のオブジェクト描画とカリング

- ワールド座標から画面座標への変換はカメラの1か所で行う
- 後方メンバー、敵、ドロップ、攻撃範囲、飛び道具、エフェクトがすべて同じカメラ変換を受ける
- 影とテレグラフが本体からずれない
- カメラ外のスプライトは描画を省略してよい
- カメラ外の未発見敵はAIを高頻度更新しない
- ただし、カメラ外へ移動した攻撃判定や敵を即座に削除しない

## 11. HUDとBGM

探索中：

- AREA：`晶界・苔根の遺構`
- TRIAL・ENEMYは非表示
- 1人表示
- 探索BGM「森晶遺跡の静寂」

戦闘中：

- AREA名は同じ
- 現在のグループの`ENEMY`数だけ表示
- 3人陣形
- バトルBGM「晶界を駆ける」

グループ撃破後は探索表示と探索BGMへ戻す。マップ内の移動で探索BGMを再読み込まない。

## 13. テスト

最低限、次を追加・更新する。

### マップデータ

- 40列×36行で、全行の長さが同じ
- スポーン、10体の敵、4グループ、出口が通行可タイル上にある
- 必須ルートでスタートから出口手前まで到達できる
- 左行き止まりと右ループが存在
- 通路幅が操作キラと陣形展開に必要な最小幅を満たす

### カメラ

- デッドゾーン内の小さな移動でカメラが不必要に揺れない
- デッドゾーン外の移動を追従
- ワールドの4辺を越えない
- 操作キラ交代時にカメラが急ワープしない
- アリーナモードの描画位置が変わらない

### 衝突・描画

- プレイヤーと敵が壁、根、虚無タイルを越えない
- 壁沿いに滑れる
- アクター、影、テレグラフ、エフェクト、飛び道具が同じカメラオフセットで描画される
- HUDはカメラで動かない

### エンカウント

- 各グループの数が3・2・2・3、合計10体
- 一つのグループが発見しても他のグループは待機を維持
- 戦闘開始で3人展開とバトルBGM
- 現在のグループの敵だけがAI攻撃
- 撃破で1人探索と探索BGM
- 撃破済みグループは再発生しない
- 任意戦を無視しても第1層出口へ到達可能
- 最終グループ撃破で第2層予告の門が開く

最後に：

```bash
npm test
npm run build
```

## 14. 画面確認

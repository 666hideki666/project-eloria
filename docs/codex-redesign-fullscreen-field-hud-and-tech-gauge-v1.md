## 現状確認の要点

- `index.html` と `src/style.css` に、フィールド外のブランド帯、上情報帯、左の固定 `party-panel`、下の `action-bar`／4つの技カード、二重枠を持つ `game-shell` がある。これらがフィールドを小さくしている。
- `#game` の論理解像度は `640×360`。現在の CSS はフィールドを `16:9` に固定し、画面サイズで最大幅を抑えている。単に親要素を広げるだけでは、16:10や縦長で伸び・大きな余白・重要地点の切れが起こり得る。
- `DesktopHudController` は HP、メルのMP、各技クールダウンを表示する。`OverlayController` は第1層の開始時に、入力を止める大きな紹介カードを表示する。`src/main.ts` の Canvas `pointerdown` は現在、どこを押しても「調べる」に変換する。
- `GameWorld` は J/K/L を通常／特殊／大技として処理し、個別クールダウンを持つ。メルの手動回復・自動回復にはMP消費がある。タッチ時には仮想スティックとアクションボタンが必要。

## 目指す画面と状態別表示

1. `body`／`game-shell`／`field-shell` の外枠と常設サイドバー・フッターを取り除き、ブラウザのゲーム領域をフィールド主体にする。`PROJECT ELORIA` や試作版ラベルはプレイ中に常設しない。ゲームタイトルは開始画面やポーズ画面などへ移す。
2. フィールド上の左上に、小さく不透明度の高い操作キャラの顔・名前・HP・技ゲージを重ねる。その横に仲間2人の小顔と短いHP表示を置く。操作キャラの状態が主、仲間は補助。攻撃中も通路や敵予兆を覆わない位置・大きさにする。危険な低HP・戦闘不能は色だけでなく形やテキストでも区別する。
3. 右上は小さなポーズ入口。BGM/SFX調整はポーズ内へ集約する。常設の `AREA`・敵数・試練番号は撤去し、現在地は入場演出／ポーズで見られるようにする。敵数は戦闘中のみ控えめに表示する。
4. フィールド外の J/K/L/Space 技カードは撤去する。ただし操作方法を失わせない。戦闘開始直後や操作を覚えるまで、画面隅に短いキー案内を出す。いつでも状態画面／ポーズから技名・効果・キーを確認できる。戦闘中に大技可能になった時は、技ゲージと必要なら `L` の短いヒントで伝える。
5. 「E 調べる」などは対象の近くでだけ、対象または画面下中央に出す。元の常設「WASD移動」帯は置かず、初回チュートリアルとポーズ内の操作説明に移す。会話やポーズ、ゲームオーバーは読みやすさを優先して画面上に窓を出してよい。
6. タッチ端末では移動スティックと J/K/L/交代の操作を残す。従来の下部デスクトップ技カードを単に消すだけで、タッチ操作を不能にしない。アクションボタンは半透明で、押しやすさとHUDの重なりを確認する。

## 状態確認の操作

- 操作キャラの顔をクリック／タップすると、フィールドの一部だけを覆う状態パネルを開く。探索時にはフィールド上のキャラスプライトのタップでも開ける。仲間の顔ならその仲間の状態を見る。パネルには HP、技ゲージ、メルのMP、技名・効果・消費段数・操作キーを表示する。
- 戦闘中のスプライトタップは対象選択や攻撃と誤認されないよう慎重に扱う。確実な入口はHUDの顔。現在の Canvas 全面 `pointerdown -> interact` を見直し、状態パネルを開く操作が「調べる」や会話送りを発火させない。閉じる方法は同じ顔、閉じるボタン、Esc／戻るとする。
- キーボードだけでも状態パネルに到達できる操作を設け、フォーカスを失わず戻れるようにする。状態を見ている間に戦闘が進むか止まるかは、原則「一時停止」して誤操作を防ぐ。敵予兆中に開いても即被弾しないこと。

## 技ゲージ：UIだけでなくゲームルールまで

- **キャラごとに1本**の連続ゲージを HP の下に追加し、1/3・2/3位置に薄い縦目盛りを重ねる。操作キャラのゲージは常時表示し、仲間の詳細は状態画面で見る。キャラ交代しても個別の残量を保持する。
- 攻撃・敵の有無に関係なく、探索・戦闘中のゲーム時間で全員のゲージが連続的に増える。現在の調整は5秒で1段、0から満タンの3段まで15秒。上限3段。ポーズ・状態パネル・会話などゲーム時間が止まる間は蓄積しない。
- J はゲージ不要、K は1段消費、L は3段消費。端数を保持する（例：1.6段からKを使うと0.6段）。2段時はKを2回使うかLまで温存する選択肢。新しい技や操作キーを増やすことは今回の範囲外。必要段数がなければ技を出さず、短い音・HUD反応で不足を示す。消費は技が実際に発動した時だけ行う。
- 現在の長い特殊技／大技クールダウンをゲージ消費と二重の主制約にしない。アニメーションの連打防止やごく短い硬直は残してよい。既存の攻撃判定、演出、ヒットストップやキャラ交代の安全性は維持する。
- メルの**手動K回復**は「ゲージ1段」で発動し、既存MPコストを重ねない。メルの**自動回復**は現状どおりMPとクールダウンで制御し、技ゲージを勝手に消費しない。MP自体は残し、メル操作時に小さな数値・低MP警告を示し、状態画面には常時明示する。MPバーをもう1本常設して画面を膨らませない。HP・MPの回復アイテムやステージ移動の持ち越しは既存挙動を守る。
- 大技の「3段たまった」演出は節度ある1回の点灯・効果音。点滅し続けるHUDや画面全体のフラッシュを避け、`prefers-reduced-motion` では動きを抑える。

## 第1層の入場演出

- `苔根の遺構` は、既存の大きな説明カードを置いたまま表示するのではなく、フィールドを見せながら短い非モーダル演出で出す。例：背景をわずかに暗くする → 「第一層」 → 大きな「苔根の遺構」と細い光の横線 → 音に合わせて文字が落ち着く → フェードアウト。現在の調整はフェードイン約0.4秒、明瞭表示約4秒、フェードアウト約0.8秒の合計約5.2秒。
- 字体は日本語として読めるドット感のある太字を基調にする。Courier系の英語・機械風ラベルを画面一面に繰り返さない。極端なCRT線や激しいグリッチではなく、文字の出る間、控えめな光、短い効果音で格好よくする。
- 演出中は移動・戦闘開始を阻害しないか、阻害する場合は最小時間でスキップ可能にする。会話・初回ストーリー説明は別の適切な場面へ残し、重要な文脈を削除しない。再訪時の反復、ポーズ・リスタート・レイヤー遷移でも二重発火しない。`prefers-reduced-motion` では即時または短いフェードにする。

## 画面比率・描画・当たり判定

- 16:9だけでなく、ユーザーの16:10画面、狭いデスクトップ、タッチ端末でも確認する。背景・スプライトを非等方に伸ばさない。ブラウザ内ゲーム領域は極力全面フィールドにし、必要な端数は世界に馴染む余白処理を使う。単純な `object-fit: cover` で通路・敵・インタラクト対象を見切れさせない。
- カメラ可視範囲やCanvas倍率を変える場合も、ワールド座標の歩行マスク、足元一点判定、移動線分判定、敵の当たり判定を一切拡大・縮小しない。クリック／タッチ座標を正しくワールドに変換し直す。高DPIと縮小画面でドット絵を滲ませない。
- HUDはカメラ追従の世界オブジェクトではなくスクリーン固定。地形・敵予兆・クリスタル・根の門の必要な視認性、上下の深度描画を維持する。

## 実装順と合格条件

1. まず全画面フィールドのレイアウトと探索HUD。既存のポーズ・音量・会話・タッチ操作の入口を維持する。
2. 次に顔からの状態パネルと入力競合の整理。マウス、タッチ、キーボードで開閉し、会話送りやE操作を誤発火させない。
3. 技ゲージの時間蓄積・端数を残す消費・HUD同期を入れ、J/K/L、メル手動／自動回復、ポーズ・状態パネル、交代、再挑戦、ステージ移動の回帰テストを追加する。
4. 最後に入場演出、控えめな戦闘／インタラクト文脈HUD、レスポンシブ調整を加える。
5. `npm run typecheck`、`npm test`、`npm run build` を通す。実ブラウザで第1層の開始→戦闘→クリスタル→根解除→奥へ進む動線を確認し、16:9と16:10、可能ならタッチ幅でスクリーンショットを比較する。第1層の赤線通路内外の歩行、クリスタルの衝突と前後描画も回帰確認する。
6. 実画面QAで開いたゲームのブラウザタブは、**非表示タブも含めて実装・検証後に閉じる**。BGMが作業終了後も鳴り続けないことを確認する。QA用の開発サーバーも、作業用に起動したものだけ停止する。ユーザーが自分で閉じられない背景タブを残さない。

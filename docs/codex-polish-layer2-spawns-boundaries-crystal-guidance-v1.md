# Codex向け修正指示：第2層の敵配置・外周仕上げ・晶石誘導 v1

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- `Sol` / `Ultra`：不要
- 理由：敵配置データ、復活処理、タイル生成、地形描画、進行会話と演出をまとめて修正するため。

## 1. 目的

第2層「光羽の晶洞」の次の問題を修正する。

1. モンスターがステージ外、void、壁ブロック上へ出現して動けない
2. 歩行床の外周が途中で切れ、黒い空間へ直接つながって作りかけに見える
3. 主晶石を作動しても何が起きたか分からず、副晶石を探す順番が伝わらない

ルミバネとモスプルンの種類・総数・基本戦闘バランスは維持する。

## 2. 敵スポーンの問題

現在の`LIGHTWING_ENCOUNTERS`は手入力の座標を直接使い、生成時と再出現時に地形を検証していない。

そのため、次の状態が起きる。

- モスプルンがvoidや壁上へ生成
- 地上敵が歩行不能地点から出られない
- ルミバネも壁際で移動AIが衝突し続ける
- 再出現時に同じ不正座標へ戻る
- 敵HPバーだけがステージ外へ見える

## 3. 敵の初期座標を歩行領域内へ修正

`LIGHTWING_ENCOUNTERS`全14体の座標を、実際のタイルマップ上で再確認する。

要件：

- モスプルンは必ず`floor`または十分に広い`bridge`上
- ルミバネも初期ホームは`floor`上
- `wall`、`water`、`void`、未解放`platformLocked`、solid prop上は禁止
- 敵中心から地形境界まで、敵radius＋最低16pxの余白
- 大型ランドマークから最低48〜64px離す
- 3〜4体グループは各敵間を最低56〜80px空ける
- プレイヤー初期位置や層間入口の画面内に置かない
- グループ中心は戦闘可能な広場の中央寄り
- 逃走方向を塞がない

特にスクリーンショットで不正配置が見える`mixedChannel`と`lightwingNest`を重点確認する。

## 4. 安全スポーン補正

座標修正だけでなく、生成時・再出現時の安全確認を追加する。

推奨関数：

```ts
findNearestSafeEnemySpawn(
  desired: Vec2,
  enemyRadius: number,
  kind: EnemyKind,
  occupied: readonly Vec2[],
): Vec2
```

ルール：

- desired位置が安全ならそのまま使う
- 不正なら32pxグリッド単位または16px刻みで周囲をリング状に探索
- 最大探索距離96〜160px
- 歩行可能タイルで、円形当たり判定が非歩行領域へ重ならない地点を選ぶ
- solid prop、プレイヤー、他の敵ホーム位置から十分離す
- 地上敵は既存のプレイヤー歩行判定と同等以上に厳しくする
- 飛行敵も初期位置はステージ内とし、voidへ補正しない
- 安全地点が見つからない場合は黙って不正位置へ置かず、DEVで明確なwarningを出す
- productionではグループ中央の既知safe anchorへフォールバック

この補正を次の両方で使う。

1. 第2層room初期生成
2. 距離／層移動による敵再出現

可能なら第1層にも汎用化できるが、第1層の配置を変える回帰を避ける。まず第2層へ安全に適用する。

## 5. 敵ホームとAI復帰

- 補正後の位置を`idleAnchor`、`idleTarget`、`reservedPos`へ設定
- desiredの不正座標をhomeとして残さない
- 逃走後、補正済みの安全位置へ戻る
- 再出現のたびに異なる位置へランダム移動させない
- 同じマップ状態なら同じ安全位置になる決定的な探索順を使う
- 地上敵が壁の反対側へhome帰還しようとしない

## 6. 外周を連続した地形として仕上げる

現在は歩行可能タイルに隣接したvoidの一部だけを、不規則にwallへ変換している。そのため壁が欠け、床が黒いvoidへ直接切れて見える。

外周方針：

- 歩行床の縁は必ず`wall`または`water`に接する
- 床から直接`void`へ接しない
- 洞窟の外側は、濃い岩壁、地底湖、深い崖のいずれかで明確に閉じる
- 1タイルだけの壁抜けや孤立した壁ブロックを減らす
- 角を2〜3タイルの塊として描き、洞窟輪郭を連続させる

## 7. 外周タイル生成

タイル生成を次のように改善する。

1. `floor`、`bridge`、解放後platform、layerGateを歩行領域とする
2. 歩行領域の8近傍にあるvoidは原則wallへ変換
3. 湖・水路に面する縁はwaterのまま維持し、必要なら岩の縁取りを追加
4. wallのさらに外側だけvoidにする
5. 1タイル穴、孤立wall、ギザギザ過多を後処理で整理
6. 通路幅を削って96px未満にしない

乱数式で25%だけwallにする現在の方式は廃止または、wallの装飾variant選択だけに使う。壁の有無を見た目用hashへ委ねない。

## 8. 外周の見た目

コンセプト画像のように、洞窟全体が地下湖と濃い晶石壁に囲まれている印象へ近づける。

### 岩壁

- 床より明確に濃い青紫
- 2〜3段の岩の縁
- 床側に明るい上面、外側に暗い垂直面
- 高さを感じる接地影
- 孤立した四角ブロックに見せない

### 地底湖

- 床境界の一部を水辺として使う
- 暗い青、細い水面反射、岸の石
- 歩行不可だと分かる
- 全外周を水だけにせず、岩壁と組み合わせる

### void

- wallやwaterのさらに外側に限定
- 黒一色ではなく、ごく暗い青の洞窟深部
- 床のすぐ隣へ大面積の矩形voidを見せない
- タイル境界が縦横の四角い穴として目立たないよう輪郭を整える

## 9. 衝突と見た目の一致

- 濃い壁、地底湖、voidは進入不可
- 床に見える場所は歩行可
- 壁に見える場所へ敵や味方が乗らない
- ルミバネは水上を飛行できても、初期出現と待機homeは床上
- 外周を描画だけで足し、見えない床判定を残さない
- 外周追加で既存ルートを塞がない

## 10. 主晶石の目的を明確化

現在の主晶石作動後の説明だけでは、どこに何が起きたか分からない。

修正後の流れ：

1. 主晶石に触れる
2. 固定会話：`晶石の奥で、眠っていた光が目を覚ます。`
3. 決定入力で会話を閉じる
4. 主晶石が発光
5. 青白い光が床の導線または空中の粒子として副晶石方向へ走る
6. カメラを副晶石へ強制移動せず、画面端に目的方向を示す短い光の流れを出す
7. 遠くの副晶石が紫色に3回程度脈打つ
8. 固定会話で結果を説明

結果会話例：

```text
主晶石の光が、洞窟の奥にある別の晶石へ流れ込んだ。
二つの晶石を共鳴させれば、湖を渡る道が現れそうだ。
```

文章はクリック／Eまで消えない既存固定会話を使う。

## 11. 目的方向の補助

主晶石作動後から副晶石作動まで、迷いすぎない程度の環境誘導を追加する。

- 主ルート沿いの小晶石を順番に淡く点灯
- 副晶石へ近づくほど紫の光が強くなる
- 常時矢印や大きなUIマーカーは使わない
- ミニマップは今回追加しない
- 主晶石を再度調べた場合：`光は洞窟の奥にある副晶石へ続いている。`
- 副晶石を主晶石前に調べた場合：`この晶石だけでは眠ったままだ。遠くの強い晶力を求めている。`

## 12. 副晶石と湖上石段

- 副晶石作動時の固定会話で、湖の足場が出ることを明言
- 足場演出は既存の段階表示と長い効果音を維持
- 足場完成後：`湖上に晶石の石段が現れ、対岸へ渡れるようになった。`
- 可能なら演出中だけ短いカメラ注視を使ってよい。ただし操作不能時間を長くしすぎない
- カメラを動かす場合は、足場全体を2〜3秒見せてからプレイヤーへ滑らかに戻す
- 画面酔いする速いパンは禁止

5. 外周生成を連続wall/water方式へ変更
6. 外周Rendererを濃い岩壁・湖・深部へ描き分け
7. 衝突と経路を確認
8. 主晶石の固定会話と副晶石誘導演出を追加
9. 副晶石・石段結果会話を明確化
10. QAと自動テスト追加
11. `npm run typecheck`
12. `npm test`
13. `npm run build`

# Codex向け修正指示：第1層のスケールと迷路レイアウトの再設計

## 実行設定

- 推奨モデル：`GPT-5.6 Sol`
- 推論レベル：`High`
- `Ultra`：不要
- 理由：カメラ基盤は維持しつつ、タイルマップ、敵配置、エンカウント範囲、ゲート、描画ランドマーク、QAを新スケールに合わせて再配置する回帰リスクのある修正のため。

## 背景と問題

現在の第1層は次で実装されている。

- ワールド：1280×1152
- ビューポート：640×360
- グリッド：40列×36行、32pxタイル
- カメラ、タイル衝突、4エンカウント、モスプルン10体は実装済み

しかし、ユーザーの意図した見え方は、参照画像の赤枠程度だけが1画面に表示されるスケールである。

参照：

- `assets/concepts/environments/crystal-dungeon-01/forest-ruins-layer-scale-reference-v1.png`
- ユーザーが赤枠を追記した原本：`/Users/katouhideki/Desktop/あああ.png`

赤枠の中に見えるのは、おおむね次の範囲である。

- 円形広場1つ
- 隣接する曲がり道の一部
- 小部屋または水盆の一部
- マップ全体の位置関係は分からない

現在の実装は、これより多くの広場、分岐、長い通路が1画面に収まりやすい。単にCanvasを拡大表示するのではなく、ワールドのサイズと地形配置を修正する。

## 1. 修正後の基準サイズ

- Canvas内部解像度：640×360を維持
- カメラの表示倍率：1.0を維持
- ワールド：1536×1504
- タイル：32pxを維持
- グリッド：48列×47行
- 画面数の目安：横約2.4画面、縦約4.2画面
- 面積：現在の約1.57倍

世界座標のスケール変換は行わない。現在の全座標を1.2倍で掛けるような機械的拡大は禁止する。グリッド内の地形を新しく作り直す。

サイズは定数へ集約し、さらなるプレイテスト後に、例えば1472×1440や1600×1600へ調整できる構成を維持する。

### ステージごとに異なる形と進行方向を許容する

今回の`第1層：苔根の遺構`は、最下部から開始して最上部を目指す縦長ステージとして実装する。ただし、この縦長サイズや下から上への進行をゲーム全体の共通仕様にはしない。

- ワールドの幅・高さはステージ定義ごとに保持する
- 開始地点とゴール地点もステージ定義ごとに保持する
- カメラのclamp範囲は各ステージのワールド寸法から計算する
- 敵配置、エンカウント範囲、ゲート、ランドマークを特定の進行方向へ依存させない
- ステージ切り替え時に、前ステージの幅・高さ・カメラ位置を引き継がない

将来作成できる構成例：

- 下から上へ進む縦長ステージ（今回）
- 上から下へ進む縦長ステージ
- 左から右へ進む横長ステージ
- 右から左へ進む横長ステージ
- 中央から複数方向へ探索する正方形に近いステージ
- 複数の分岐と合流を持つ迷路型ステージ
- 通常層より小さいボス専用ステージ

今回は将来分のステージを作成しない。`MOSS_ROOT_RUINS`固有の値を共通カメラや共通戦闘コードへ直書きせず、次のステージを別サイズ・別方向で追加できる境界だけ維持する。

## 2. 表示スケールの必須条件

数値だけでなく、次の視覚条件を完了条件にする。

- 転送広場の中央に立った時、1画面の主役は転送広場1つになる
- 初戦広場全体は見えてもよいが、その先の中央晶石広場全体まで同時に見えない
- 中央晶石広場では、広場1つと左右の入口が見えるが、行き止まりの奥や右ループの全容は見えない
- 行き止まりへ入るまで、その奥にある台座や敵数を確認できない
- 最終広場は接続通路から入る時に少しずつ見えてくる
- マップの最下部から最上部まで1枚の画面に見える名付き大広場は原則1つまで
- 隣接広場は、通路の先に照明、晶石、壁の切れ目が少し見える程度に留める

カメラをズームしたり、キャラクターだけを大きくしたりして条件を満たさない。

## 3. マップ作成方法の修正

現在の`buildTiles()`は大きな`floorRect()`を複数組み合わせており、広場と通路が大きな長方形に見えやすい。円形広場と曲がる通路を作れる小さなビルダーに置き換える。

例：

```ts
carveEllipse(centerColumn, centerRow, radiusColumns, radiusRows)
carvePath(points, widthInTiles)
carveRoom(left, top, right, bottom) // 小部屋のみ
```

要件：

- 大広場は`carveEllipse()`で作る
- メイン通路は2〜4点の折れ線または曲線に近い折れ線でつなぐ
- タイル単位の直角をそのまま見せず、幅の変化とジッターで輪郭を崩す
- 長方形の巨大な床面を作らない
- 衝突グリッドは引き続き32pxでよい
- 描画側で床境界を根、崩れ石、陰影で隠し、四角いタイルマップ感を弱める

新しい外部マップライブラリは追加しない。

## 5. 地形構成

### 最下部

- 転送広場は横幅320〜380px、縦240〜300px程度
- マップ端のカメラ停止時に広場が主役になる
- 北の根の門とその先の通路は見える
- 初戦広場の敵全員が開始時から見えない

### 初戦から中央まで

- 門から曲がり道を経て初戦広場へ入る
- 初戦広場は直径300〜360px
- 初戦広場の出口から中央広場まで、少なくとも1回曲がる
- 初戦広場と中央広場の中心を同時に表示しない

### 中央分岐

- 中央晶石広場は直径320〜380px
- 北、左、右の3方向へ道が伸びる
- 左は明確な行き止まり
- 右は大きく回り込んで北のメインルートへ合流する
- 北は最終広場へ向かう最短ルートだが、直線ではなくS字状に曲げる

### 行き止まりとループ

- 左行き止まりは中央広場から往復で約2〜3画面分程度の寄り道
- 奥へ入るまでモスプルン2体と台座を見せない
- 右ループは必須戦広場と小部屋を通り、北ルートへ合流
- 合流地点を開くと、中央への戻り道が短縮されるように見える構造にする

### 最上部

- 最終広場は直径320〜380px
- 手前の通路を曲げ、広場の3体が一度に画面に現れないようにする
- 広場の奥に第2層への門を置く
- 最終グループ撃破で門を開く現在の進行条件を維持

## 6. 通路と戦闘空間

- 探索通路の標準幅：96〜128px
- 局所的な細道：80pxまで許容するが、戦闘を発生させない
- 戦闘広場の入口：128px以上
- 3人展開の安全候補が少なくとも3点見つかる広さを確保
- モスプルン3体戦で、敵同士が壁に押し付けられない
- 戦闘中のバリアは広場の出入口に合わせて再配置
- 旧座標のバリアをそのまま残さない

通路を長くするだけで水増ししない。通路の途中に晶石、根のアーチ、石柱、水滴、床の紋様などを置き、方向を判断できる視覚的目印を作る。

## 8. カメラ

現在の`StageCamera`のデッドゾーンと補間は基本的に維持する。修正必須なのはワールド端の新しいclamp範囲である。

- `x=0..896`（`1536 - 640`）
- `y=0..1144`（`1504 - 360`）

ワールド定数から自動計算し、数値を`StageCamera`内へ重複ハードコードしない。

確認点：

- 開始広場でカメラが最下端に正しく停止
- 最終広場で最上端に停止
- 左行き止まりと右小部屋で左右端を越えない
- 交代、戦闘展開、ノックバックでカメラが急ワープしない
- アリーナの固定カメラに影響しない

## 9. 描画と視覚密度

参照画像と完全に同じ描き込み量を一度に作る必要はないが、現在の大きな長方形床が連続する見た目は解消する。

- 円形広場は環状の石組みで視覚的に区別
- 曲がり道の外側に高い壁、内側に崩れ石や根
- 各ランドマークに晶石の数、色、根の形の違いを付ける
- 同じ床パターンの大面積繰り返しを避ける
- 通行可能な床と壁・穴が暗さだけでなく輪郭で判別できる
- カメラ外カリングと固定`hash2d()`を維持

開始広場、中央広場、最終広場を同じ装飾のコピーにせず、床紋様と周辺物で場所を覚えられるようにする。

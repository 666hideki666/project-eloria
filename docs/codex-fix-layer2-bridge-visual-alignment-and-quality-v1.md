# 第２層：橋の表示位置と石畳の画質修正（実装承認済み）

## ユーザーの確認結果

- 2026-09-28の実画面 `スクリーンショット 2026-09-28 13.13.34.png`：解除クリスタルの前後関係は **OK**。今回は変更しない。
- 湖上の橋はまだ石畳の絵が歩行位置とずれており、キャラの足元が橋の下端／晶石側に見える。歩行可能な位置そのものは問題なさそうなので、**赤線マスクと当たり判定を動かさない**。
- 石畳の画質が周囲の背景より著しく粗く見える。元背景・既存の広場の画質を下げず、橋だけを直す。

## 現行コードで確認した原因

`src/render/stages/LightwingCrystalCavernRenderer.ts` の `getAlignedBridgeArt()` は、承認済みの全体コンセプト画像から石畳を **幅１画像pxずつ**切り出す。そして各列について `bounds.top + 4` からの **21画像px** を、赤線由来の `bounds.top`〜`bounds.bottom` の高さへ `drawImage` で引き伸ばす。橋歩行帯の縦幅は中央のサンプル位置で約 **37〜45画像px** あるため、石の模様が列ごとに約２倍へ縦伸長され、拡大表示で粗さ・不自然な継ぎ目が強調される。これはスクリーンショットの画質低下と整合する。

この処理は歩行帯を石畳色で埋めるが、石畳の元の形・橋の端・晶石の支え・両岸とのつながりを正しく位置登録していない。橋の絵がずれる原因も、**衝突マスクではなく表示素材の変形と位置合わせ**にあると考えられる。

## 修正方針

1. **承認済みの青い晶石で支えられた石畳橋というデザインは維持する。** `lightwing-crystal-cavern-full-map-concept-v3.png` を発動前背景とし、橋だけを別の透明レイヤーとして重ねる。橋の透明レイヤーは背景と同じ **1638×960 px** のネイティブ座標で、実際の赤線橋帯と両岸の接続に位置合わせする。全体コンセプトを背景ごと差し替えない。
2. 現在の「１px列ごとに21pxの石畳を37〜45pxへ引き伸ばす」描画はやめる。石畳は自然な縦横比・画素密度を維持した一枚の橋面として作成／配置する。解像度の低い帯の単純拡大、ぼかし補間、同じ小片の不自然な反復は避ける。晶石の支えは橋面の下・脇へ置き、歩行面を塞がない。
3. 橋面の見た目は、赤線橋帯の**足元接地点**が石畳上にあると読める幅に合わせる。キャラの上半身や影は通路外に重なってよい。単純に橋全体を一定pxだけ下へ移すのではなく、左端・中央・右端で足元位置と両岸の接合を確認して調整する。赤線外の水面に新しい歩行域を作らない。
4. 起動前には橋を描かず、片側起動でも渡れず、２基起動後の出現演出完了時に表示と通行が一致する従来仕様を維持する。解除クリスタルの描画順、回復の泉、敵・戦闘、他階層は変更しない。

## レビュー・QA

- 実装前に、元背景＋新しい橋だけの重ね図を **1638×960** で作り、赤線由来の橋歩行帯を別色の確認用オーバーレイで重ねて、石畳の内側に足元が収まるか確認する。確認用の色線はゲーム本番の画像へ混入させない。
- 両岸への継ぎ目、橋中央の石畳模様、晶石の上下関係を原寸表示とゲーム内拡大表示の両方で確認する。周囲の既存広場と比較して橋だけが異常に粗くないこと。
- ゲーム内で橋の左端・中央・右端を通常移動して撮影し、キャラの接地点が石畳上に見えることを確認する。水面と赤線外へは歩けないことも再確認する。
- 型検査、テスト、ビルドを実行する。検証用ブラウザ・サーバーは終了し、ユーザー起動のサーバーには触れない。

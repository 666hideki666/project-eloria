# Codex向け統合修正指示：開発用層選択・安全陣形・両層敵配置・第3層仕掛け v2

## 0. この指示書の位置付け

この文書は、次の旧指示書を置き換える統合版である。

- `docs/codex-fix-dev-layer-selector-and-depths-enemy-reachability-v1.md`

旧指示書を個別に実装せず、本v2だけを基準に修正する。

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- 理由：開始フロー、層遷移、敵配列の所有権、2マップのspawn、戦闘陣形、仕掛け演出、テストを横断するため。
- `Luna`は今回は非推奨。
- `Sol` / `Ultra`は不要。

## 1. 添付画像で確認した問題

### 画像1：戦闘陣形が壁・voidへ展開される

- 戦闘開始直後、操作キャラの後方2人が歩けない壁上またはvoid側へ展開されている
- 狭い通路でも固定幅の陣形をそのまま適用している
- 戦闘陣形へ変わった瞬間に味方が移動不能となり、バトルが成立しない
- フォロワーの配置先について、現在の層のwalkable判定と連結性を確認していない

### 画像2〜4：第3層へ別階層の敵が混入している

- エリア名は第3層「霊布と石鱗の深層」
- しかし画面内にルミバネ、モスプルンが存在している
- 第3層の正式な敵はウツロボウとイワウロコだけ
- 第2層の敵配列または遭遇状態が、層遷移時に第3層へ残留・混入している可能性が高い
- 画面外のvoidや壁上にも敵が存在する

### 第2層にも不正spawnがある

- 第2層のモスプルンがプレイヤーの移動不能領域へ出現する
- 第3層だけを修正しても再発する
- 第2層・第3層へ共通するspawn安全性と到達可能性の仕組みが必要

### 第3層の仕掛けが伝わらない

- 石碑のような装置とクリスタルのような装置が何を意味するのか分かりづらい
- どちらを作動させたのか、次にどこへ行くのか、何が開いたのかが視覚的に伝わらない
- 中央門との関係が弱い

## 2. 今回の修正目標

1. DEV起動時に第1層・第2層・第3層を直接選択できる
2. 戦闘陣形へ切り替わっても、3人全員が必ず到達可能な床へ配置される
3. 第2層と第3層の敵配列を完全に分離し、別層の敵を混入させない
4. 第2層・第3層の全敵を、プレイヤーが歩いて到達できる戦闘場所だけへ配置する
5. 第3層にはウツロボウ5体、イワウロコ4体だけを出現させる
6. 第3層の2つの仕掛けと中央門の関係を、見た目・文章・音・進行表示で明確にする

## 3. 開発用の開始時層選択

### 3.1 表示

- `import.meta.env.DEV`の時だけ、ゲーム開始前に層選択画面を表示する
- 見出し：`開発用｜開始する層を選択`
- ボタン：
  - `第1層　苔根の遺構`
  - `第2層　光羽の晶洞`
  - `第3層　霊布と石鱗の深層`
- マウスクリック、数字キー1・2・3、上下＋Enterに対応する
- production buildでは表示・入力・DOM・当たり判定を残さない
- 後で一括削除できるDEV専用処理へ分離する

### 3.2 選択時の状態

#### 第1層

- 通常の初期状態から開始する

#### 第2層

- 第2層入口から開始する
- 第2層の敵、主晶石、副晶石、湖上石段、回復晶泉状態をテスト用初期状態へ戻す
- 第1層の通過に必要な最小フラグだけ整合させる

#### 第3層

- 第3層入口テラスから開始する
- 第3層の敵、霊灯、石楔、中央門、近道、ヒントを初期状態へ戻す
- 第2層へ戻って再び第3層へ来られるよう、第2層出口条件を整合させる
- 開始時の`enemies`参照を必ず第3層専用配列へ切り替える

## 4. 層ごとの敵配列を完全に分離

### 4.1 正式な敵種別

第2層：

- モスプルン
- ルミバネ
- 現在の第2層定義に含まれる敵だけ

第3層：

- ウツロボウ ×5
- イワウロコ ×4
- モスプルン、ルミバネ、ガラクロウ等を出さない

### 4.2 遷移時の必須処理

- room切替完了時、`this.enemies`を到着先の層専用配列へ明示的に再代入する
- 出発元の配列参照を持ち越さない
- `lightwingEnemies`と`depthsEnemies`を共有しない
- enemy IDとencounter group mapも層ごとに対応させる
- transition中にsnapshotへ出発元の敵を載せ続けない
- 到着後の最初の描画フレームから、到着先の敵だけを表示する
- DEV層選択でも通常遷移と同じ切替経路を使う

### 4.3 DEVの防御的検証

DEV時、roomへ入った直後に敵種別を検証する。

- 第2層で許可外kindがあればwarningまたはテスト失敗
- 第3層で`utsurobou`と`iwaUroko`以外がいればwarningまたはテスト失敗
- 不正な敵を黙って描画し続けない

## 5. 第2層・第3層共通の安全spawn

### 5.1 安全条件

初期配置、逃走リセット、撃破後再出現、層再入場、DEV開始のすべてで次を満たす。

1. 敵の中心と半径全体がwalkable tile内
2. wall、void、水、閉鎖門、装置、段差、solid propと重ならない
3. 他の敵と重ならない
4. プレイヤー入口から歩いて到達できる連結床に属する
5. 該当遭遇広場と同じ連結成分に属する
6. プレイヤーがdetection radius内へ歩いて入れる
7. 敵AIが動ける面積を持つ
8. イワウロコは突進できる距離、飛行敵は帰還できる床アンカーを持つ

### 5.2 BFS / flood fill

- 各層入口の安全地点からwalkable tileをBFSする
- 現在の門・橋・近道状態を反映する
- 単にtile種別がfloorでも、孤立床ならspawn候補へ使わない
- 敵の待機座標、group anchor、再出現候補を到達可能集合と照合する

### 5.3 検証済み候補地点

- 第2層と第3層の各遭遇グループに複数の安全候補地点を定義する
- 近傍を円形探索して偶然見つけたfloorへ置く方式だけに依存しない
- 初回と再出現で同じ検証関数を使う
- 候補が見つからない場合、元の不正座標へフォールバックしない
- DEVで明確なエラーを出し、テストを失敗させる

## 6. 第3層の敵配置

合計9体を維持する。

### A：霊布の入口

- ウツロボウ ×2
- 西ルート上の同じ広場へ置く
- 入口から歩くと確実にdetection radiusへ入る

### B：霊灯前

- ウツロボウ ×2
- イワウロコ ×1
- 霊灯を操作する前に遭遇する広場へ置く
- 装置の操作範囲と重ねない

### C：石鱗の通路

- イワウロコ ×2
- 狭い一本道ではなく、突進と回避ができる2つの広がりへ1体ずつ置く
- 同時反応させない

### D：石楔前

- イワウロコ ×1
- ウツロボウ ×1
- 石楔へ向かう通常ルート上で確実に遭遇する

## 7. 戦闘陣形の安全配置

### 7.1 問題

現在は戦闘開始時の後方2人のformation slotが固定オフセットで決まり、壁、void、水、装置上へ入る場合がある。

### 7.2 必須方針

- 操作キャラの現在位置は勝手に移動させない
- 後方2人の希望slotを計算後、現在の層のmovement/collision判定で安全性を確認する
- unsafeなら、操作キャラの周囲から安全候補を探索する
- 候補は操作キャラと同じ到達可能連結床に限定する
- 2人同士、操作キャラ、敵、solid propと重ならない
- 配置後に最低1方向以上へ移動可能であることを確認する

### 7.3 動的な陣形幅

広い場所：

- 現在の見やすい三角陣形を使用

狭い通路：

- 左右幅を段階的に縮める
- 斜め後方が無理なら縦列へ切り替える
- 縦列も無理なら操作キャラ近くの最寄り安全床へ配置する
- 壁上へ置くくらいなら、3人の間隔が少し近くなる方を優先する

### 7.4 安全候補の探索順

1. 通常の左右斜め後方
2. 縮小した左右斜め後方
3. 1人ずつ前後にずらした縦列
4. 操作キャラ周囲の螺旋／リング探索で最寄り安全地点

配置を瞬間移動で見せる場合も、壁を横切る長いスライドは行わない。戦闘開始演出中に短くフェードまたは素早く整列させる。

### 7.5 戦闘中の維持

- followerのformation slot更新時にも同じ安全判定を使う
- ノックバックや交代後にunsafe位置へ戻そうとしない
- 層ごとのcollision resolverを正しく選ぶ
- 第1層、第2層、第3層すべてで共通適用する

## 8. 第3層の仕掛けを明確化

現在の「石碑」と「クリスタルに見える装置」を、役割が分かる2つの封印装置として統一する。

### 8.1 西側：霊灯の石碑

名称：`霊灯の石碑`

外見：

- 石碑上部に青紫の消えた炎型くぼみ
- 未作動時は暗い灰色
- 近づくと炎型紋様だけがゆっくり明滅する
- 通常の背景石柱と明確に区別する

プロンプト：

`E　霊灯の石碑を調べる`

初回文章：

> 石碑には、青い霊火と中央門を結ぶ紋様が刻まれている。  
> 霊火を灯せば、中央の封印が一つ解けそうだ。

選択後：

- 青紫の霊火が灯る
- 光脈が中央門の左半分へ流れる短い演出
- 作動音を鳴らす
- 固定会話：`霊灯の封印が解けた。残る封印はあと一つ。`
- 画面上部へ短く `中央封印　1 / 2` を表示

### 8.2 東側：石楔の晶石

名称：`石楔の晶石`

「単独で置かれた用途不明のクリスタル」に見せず、岩盤へ打ち込まれた楔と晶石を一体化する。

外見：

- 琥珀色の短い晶石が石の台座へ深く刺さる
- 周囲に石鱗状の亀裂
- 未作動時は暗い琥珀
- 近づくと亀裂へ弱い光が走る

プロンプト：

`E　石楔の晶石を調べる`

初回文章：

> 晶石は、石の楔として岩盤へ打ち込まれている。  
> 引き抜けば、中央門を縛るもう一つの封印が解けそうだ。

選択後：

- 楔が少し持ち上がる、または石台へ沈み込む
- 琥珀色の光脈が中央門の右半分へ流れる
- 重い石の作動音
- 先に霊灯が作動済みなら `二つの封印が解けた。中央門が開く。`
- 未作動なら `石楔の封印が解けた。残る封印はあと一つ。`
- `中央封印　1 / 2`または`2 / 2`を表示

### 8.3 中央封印門

- 左半分に青紫の紋様、右半分に琥珀の紋様を置く
- 未解除側は暗い
- 片方解除時は対応する半分だけ点灯
- 両方解除時に`中央封印　2 / 2`を表示して門を開く
- 開放演出中、短いメッセージをクリックまで保持する
- 何が起こったか読める前に消さない
- 作動済み装置を再調査すると、中央門との関係と現在の進捗を説明する

### 8.4 道案内

- 中央環道の分岐付近に、左右へ伸びる色付き床紋様を追加する
- 青紫の線は霊灯側、琥珀の線は石楔側へ続く
- ミニマップは不要
- 目的地マーカーを常時画面へ出さず、環境内の色と紋様で誘導する

## 9. 戦闘と仕掛けの分離

- 装置の操作範囲内へ未撃破の敵を待機させない
- 戦闘中は装置を調べられない
- 該当グループから十分離脱した場合は既存の逃走処理を使う
- 装置会話中は敵AI、移動、攻撃を停止する
- 作動後の演出にカイルの大技、斬撃、戦闘リングを流用しない

## 10. テスト

### 開始時層選択

- DEV時に3層選択画面が表示される
- クリックと1・2・3キーで正しい層へ入る
- productionでは表示されない

### 敵配列の分離

- 第2層へ入ると第2層許可kindだけが存在する
- 第3層へ入ると`utsurobou`5体、`iwaUroko`4体だけが存在する
- 第2層→第3層、第3層→第2層を複数回往復しても混入しない
- DEV層選択を繰り返しても混入しない

### spawn

- 第2層と第3層の全初期spawnが安全判定とBFS到達判定を通る
- 全group anchorが到達可能
- 再出現候補も同じ判定を通る
- 不正候補しかない場合に元座標へ戻さない

### 陣形

- 広場で通常三角陣形になる
- 狭い通路で縮小陣形または縦列になる
- 壁際、void際、水際、装置際で3人全員がwalkable位置へ出る
- 交代後もunsafe位置へ移動しない
- 第1層、第2層、第3層で同じ安全性を確認する

### 仕掛け

- 霊灯だけで中央門左半分と1/2表示が有効
- 石楔だけで右半分と1/2表示が有効
- 逆順でも正常
- 両方で2/2となり中央門が開く
- 再調査で現在の進捗が分かる
- 門開放後に見えない衝突が残らない

## 11. 手動QA

1. 起動直後、第2層・第3層をクリック選択できる
2. 第2層の全敵が歩ける場所にいる
3. 第2層で戦闘開始し、3人が水・壁・voidへ展開されない
4. 第3層を直接開始し、モスプルンやルミバネが一切いない
5. ウツロボウ5体、イワウロコ4体を目視・遭遇確認する
6. 第3層の狭い通路で陣形が安全に縮む
7. 霊灯の石碑を見て、中央門の左封印だと理解できる
8. 石楔の晶石を見て、中央門の右封印だと理解できる
9. どちらを先に作動しても1/2、2/2が正しく表示される
10. 逃走、撃破、再出現、層往復後も敵が不正位置へ出ない
11. production buildに開発UIが出ない

## 12. 検証コマンド

- `npm run typecheck`
- `npm test`
- `npm run build`

ブラウザ上で第2層、第3層、全遭遇グループ、狭い通路の陣形を実操作QAする。自動テスト成功だけで完了扱いにしない。

## 13. 完了条件

- DEV開始時に3層から選べる
- 第2層と第3層の敵が混入しない
- 第2層・第3層の敵が全て到達可能な場所にいる
- 第3層でウツロボウ5体、イワウロコ4体へ確実に遭遇できる
- 戦闘開始時に3人全員が安全な床へ配置される
- 狭い場所では陣形が自動で縮小または縦列になる
- 霊灯、石楔、中央門の関係と進捗が理解できる
- 既存の戦闘、層遷移、回復晶泉を壊していない

今回は座標だけを直す応急処置ではなく、層別の敵所有権、到達可能spawn、安全陣形という3つの根本部分を修正する。

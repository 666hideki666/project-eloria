# Codex向け実装指示：第2層「回復の晶泉」本番化 v1

## 実行設定

- 推奨モデル：`GPT-5.6 Terra`
- 推論レベル：`High`
- `Sol` / `Ultra`：不要
- 理由：ランドマーク描画、前後レイヤー、衝突、回復ロジック、固定会話、専用SFX、QAを連動させる中規模実装だから。

## 2. 目的

現在の第2層晶泉は、細い水色の板状描画で回復地点に見えず、格好良さと特別感がない。

修正後は次を満たす。

- 遠くからでも回復・安全地点だと分かる
- 主晶石、副晶石とは異なる「聖域」に見える
- 大型の円形泉、浮遊晶石、天井光が主役
- 休眠時と回復作動時が明確に変化
- 3人全員が回復したことを視覚と音で理解できる
- 戦闘必殺技や攻撃エフェクトには見えない
- 中央構造物の上を歩けず、外周から自然に操作できる

## 3. 配置広場

現在の`LIGHTWING_CRYSTAL_CAVERN.spring`付近を晶泉専用の小広場として整える。

- 中心座標は既存値を基準に、必要なら周囲タイルとの整合で±32〜64px調整可
- 円形ランドマーク全体の直径：約150〜180px
- 手前に幅96〜128pxの短い参道
- 周囲は地下湖または濃い晶石壁で囲む
- 3人陣形が泉外周へ並べる床余白を確保
- 敵home、索敵範囲、復活位置を泉から十分離す
- 晶泉周辺は非戦闘区域にする
- 主ルートから見つけやすいが、通路そのものを塞がない

## 4. 本番描画

現在の次の簡易描画を置き換える。

```ts
fillRect(spring.x - 22, spring.y - 7, 44, 15)
fillRect(spring.x - 15, spring.y - 4, 30, 5)
```

推奨関数：

```ts
drawCrystalHealingSanctuaryBack(context, snapshot)
drawCrystalHealingSanctuaryFront(context, snapshot)
```

### 基礎

- 大きな円形の浅い泉
- 2〜3重の古代石リング
- 欠けた青灰色の石材
- 水面は暗い青からシアン
- 泉の内周へ古代文字風の幾何学模様
- 医療記号、十字、＋は使用しない
- 手前に2本の短い門柱または晶石灯
- 外周左右に2本の小晶石

### 中央晶石

- 水面上へ浮かぶ大型の多面体結晶
- キャラクター身長の1.5〜2倍
- シアン、青、白の3〜4段階
- 主晶石より細く神聖、副晶石より白く柔らかい
- 台座に固定された機械装置ではなく、泉の力で浮遊して見える
- 上下へ1〜2pxの遅い浮遊

### 天井光

- 晶石へ落ちる縦長の柔らかい光柱
- 通常時は非常に弱い
- 作動時だけ明るくなる
- 大きな半透明矩形1枚ではなく、複数の縦pixel streakと粒子で表現
- 画面全体を白くしない

## 5. 描画レイヤーと前後関係

背景側：

- 水面
- 円形石リング
- 古代紋様
- 小晶石の台座
- 接地影

entity層：

- キャラクター
- 中央晶石の下部または必要な部分

前景側：

- 中央晶石上部
- 手前の泉縁
- 手前門柱
- 光粒子

キャラクターが泉の後ろを歩く時は晶石が前へ被り、手前を歩く時は泉の手前縁が自然に被る。全体を常にキャラクターより前へ描いて隠さない。

## 6. 状態

推奨：

```ts
type HealingSpringPhase = "idle" | "charging" | "healing" | "afterglow";
```

または既存timerからsnapshotへphaseとprogressを算出する。

必要なsnapshot例：

```ts
healingSpringPhase: HealingSpringPhase;
healingSpringProgress: number; // 0..1
```

RendererがGameWorldのprivate timerへ直接触れない。

## 7. 休眠状態

- 水面は暗い青
- 中央晶石は弱く一定間隔で明滅
- 古代紋様は一部だけ淡く点灯
- 天井光は細く弱い
- 小さな水面波紋
- 粒子は低頻度
- 遠目でも重要地点だと分かるが、主晶石作動中ほど派手にしない
- 休眠といっても使用不能ではない。回復前の待機状態を意味する

## 8. 近接案内と固定会話

操作距離は、拡大したcollisionの外側から届くよう調整する。

近接案内：

```text
E　回復の晶泉に触れる
```

初回だけ、操作前または操作直後に固定会話：

```text
澄んだ晶光が、静かな水面へ降り注いでいる。
この泉なら、傷ついた仲間たちを癒せそうだ。
```

初回以降は説明会話を省略し、すぐ回復演出へ進んでよい。

戦闘中：

```text
戦闘中は晶泉に集中できない。
```

これは短い不透明バナーでよい。戦闘中に固定会話を開かない。

## 9. 回復演出

全体1.8〜2.6秒程度。

### 1. 充填（約0.5秒）

- 中央晶石が白シアンへ明るくなる
- 天井光が太くなる
- 泉の古代紋様が入口側から順に点灯
- 水面の中心へ光が集まる

### 2. 回復（約0.8〜1.1秒）

- 水面から3本の細い光が各パーティーメンバーへ伸びる
- 3人の足元に小さな円形回復紋様
- 上昇する小粒子
- HP、MPゲージを瞬時に飛ばさず、0.5〜0.8秒で滑らかに満たしてもよい
- 戦闘不能キャラは片膝状態から立ち上がる
- 画面全体の大きな白フラッシュは禁止
- メルの既存回復魔法をそのまま流用せず、泉専用の静かな演出にする

### 3. 余韻（約0.6秒）

- 円形波紋が2〜3回広がる
- 晶石の光が穏やかに戻る
- 粒子がゆっくり消える
- 結果固定会話または短い明瞭な通知：

```text
晶泉の力が満ち、仲間たちは完全に回復した。
```

結果文は初回のみ固定会話、2回目以降は短いバナーでもよい。

## 10. 回復処理

既存の次を維持する。

- 全員のHPを最大
- 全員のMPを最大
- 戦闘不能解除
- invulnerable、hurtFlash、不要なvelocityを整理

追加確認：

- 回復演出開始時点で回復を確定するか、中盤で確定するかを統一
- 演出中にダメージを受けないよう、晶泉周辺を非戦闘にする
- 連打で複数演出を起動しない
- `springInteractionCooldown`を演出全体より短くしない
- 全員満タンでも使用可能だが、再演出の連打は防ぐ
- 全員満タン時に調べた場合、短く`晶泉は穏やかな光をたたえている。`としてもよい
- 技クールダウンは回復しない。HP、MP、戦闘不能だけ
- 経験値や進行フラグへ影響しない

## 11. 衝突

現在の`radiusX: 18, radiusY: 11`は新デザインには小さすぎる。

推奨：

```ts
{ id: "spring", center, radiusX: 62, radiusY: 38 }
```

実際の描画接地面に合わせて調整する。

要件：

- 中央の泉、水面、晶石台座を歩けない
- 見た目の円形外周に合う楕円衝突
- 手前参道と泉の外周は歩ける
- 外側から操作距離が届く
- 角へ引っかからず滑らかに回り込める
- プレイヤー、仲間、地上敵に適用
- 飛行敵も晶泉の上を待機homeにしない
- collision拡大後も主ルートを塞がない

## 12. 晶泉専用SFX

現在のメル特殊技音の流用をやめ、晶泉専用cueを追加する。

推奨イベント：

```ts
kind: "healingSpringActivate"
kind: "healingSpringComplete"
```

### 起動音

- 全長1.2〜1.8秒
- 柔らかな水音
- 透明な晶石の上昇和音
- 低中域の穏やかな共鳴
- 充填→回復に合わせて明るくなる
- 短いピコン音にしない

### 完了音

- 0.6〜1.0秒
- 安心感のある下降または解決和音
- キラキラしすぎず、静かな余韻
- BGMありでも認識できる

必要なら演出中だけBGMを10〜15%程度duckする。根や足場より控えめ。

## 13. 回復後の状態

- 使用後も晶泉は消えない
- 色を枯らさない
- 10〜20秒程度、古代紋様の明るさを少し残してもよい
- 再利用可能
- 層移動後も使用可能
- セーブ機能は今回対象外

## 14. HUD

- 回復演出中、通常interaction promptを隠す
- 戦闘用のENEMY表示は晶泉で出さない
- HP、MPゲージが全員回復したことを確認できる
- 会話ウィンドウとアクションHUDが重ならない
- 小さい画面幅でも泉全体と会話が同時に見える必要はないが、操作キャラクターを隠しすぎない

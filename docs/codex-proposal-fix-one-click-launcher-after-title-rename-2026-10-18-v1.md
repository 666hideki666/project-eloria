# 実装指示案：タイトル変更後のワンクリック起動修正

状態：**2026-10-18に明示承認・修正・技術検証済み**。`コード実装 | エロリア2` で実装。実際の起動ファイルをシェルから実行し、既存サーバーの再利用と既定ブラウザへのURL表示を確認した。Finderのダブルクリック操作自体は未確認。推奨モデル：**Sol High**。

## 症状と確定した原因

Finder の `Project Eloriaを起動.command` からゲームが開かない。`scripts/project-eloria-start.sh` の `is_project_http_ready()` は、4173番の応答に `<title>Project Eloria` が含まれる場合だけ自分のゲームサーバーと判定する。一方、採用済みタイトル画面の実装で `index.html` は `<title>ELORIA</title>` に変更された。実際に `http://127.0.0.1:4173/` は新タイトルで応答し、4173番のリスナーは本プロジェクトの Vite プロセスだった。したがってランチャーは起動中のゲームを認識できず、ポート使用中として失敗する。

直近の回避策：サーバーが起動中ならブラウザで `http://127.0.0.1:4173/` を直接開く。これは恒久修正ではない。

## 最小修正

- `scripts/project-eloria-start.sh` の自プロジェクトHTTP判定を現行の `<title>ELORIA</title>` に追従させる。旧タイトルも移行期に受け入れるかは任意だが、少なくとも無関係な4173番サーバーを誤認しないこと。`index.html` の製品表示名は **ELORIA** のまま維持し、古い `Project Eloria` に戻さない。
- PID、ルートの確認、ポート競合時の安全な失敗、停止スクリプト、ゲームコードは変更しない。既存サーバーを勝手に停止・再起動しない。
- ランチャーの「準備完了→ブラウザを開く」は現在のタイトルで正常動作すること。エラー時はログと理由を利用者が読める形で表示する。

## 検証

1. 4173番に本ゲームがすでに動いている状態で起動ファイルを実行し、重複起動せずゲームURLを開く。
2. 本ゲームが停止した状態で起動ファイルを実行し、Vite起動後にゲームURLを開く。停止ファイルで管理対象だけを終了し、再起動できる。
3. 無関係なHTTPサーバーが4173番を占有する場合はブラウザを誤って開かず、無関係なプロセスを停止しない。
4. Finderからのダブルクリックを可能なら実機で確認。シェル検証しか行えなかった場合はその制限を明記。
5. テスト用ブラウザ、サーバー、BGMを残さず終了する。ただしユーザーがすでに起動していた本ゲームサーバーは勝手に停止しない。
